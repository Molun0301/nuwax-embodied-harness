# 升级与恢复

Nuwax Embodied Harness（NEH，具身运行框架）使用一套模块安装器和更新事务。机器人型号通过注册表中的适配器接入，网页、命令行与兼容入口都更新同一个受管安装，不按机器人型号选择另一条部署链。

## 安装描述与运行模式

安装器在当前代际的 `manifest.json` 中保存 `deployment` 描述，记录源码目录、安装目录、模块集合、机器人适配器、监听地址与生命周期模式。`./install.sh list --json` 可查看完整记录。更新器从安装记录及当前有效配置读取这些信息，不接受网页提交的任意目录、命令或下载地址。

支持两种生命周期：

- `foreground`：默认的普通进程模式，`./install.sh start` 在当前终端启动；更新器按同一安装身份停止和重新启动进程。
- `systemd-user`：由当前安装账户的用户级 systemd 管理器管理网关。安装只保存模式；显式运行 `start` 时才写入并启动该安装的用户服务。更新工作放在独立的用户级服务中，停止网关不会一并终止更新器。

例如，使用用户服务模式：

```bash
./install.sh install --service-mode systemd-user --yes
./install.sh start
./install.sh stop
```

后续安装和更新默认保留已存模式。变更模式前先停止当前安装，再运行带 `--service-mode foreground` 或 `--service-mode systemd-user` 的安装命令。`start` 与 `stop` 不临时覆盖模式。

用户服务要求 Linux 上存在可用的用户级 systemd 管理器及对应命令。安装不会自动启用开机启动，也不会修改登录驻留或系统权限；退出登录后服务是否继续运行取决于本机用户管理器配置。没有这些条件时使用 `foreground`。现有外部进程管理器或 root 系统服务不会被猜测、接管或静默关闭，需明确迁移到受支持的生命周期再使用统一更新。

## 网页检查与自动更新

安装并启动网关后，打开控制台的“设置 → 软件更新”：

- “检查更新”读取当前 Git 分支配置的远端 upstream，不会切换到 main，也不会修改源码。
- 有新版本时，左上角品牌标题右上角显示 **New！**；点击可跳到更新设置。
- “更新并重启”需要确认。后台固定本次检测的提交，只接受快进更新；本地修改、分叉、远端版本再次变化或仓库访问失败都会拒绝覆盖。
- 默认每60分钟自动检测，可设置15—1440分钟。勾选“空闲时自动安装”并保存后，才会自动执行安装；没有浏览器打开时也会检测。
- 更新前必须没有活动任务，并通过统一的设备安全就绪检查。接入设备时需要新鲜状态确认设备已处于可安全停机的状态；无法确认时拒绝更新。无设备入口须通过标准 has_motion_actuator() 契约明确声明没有执行器；缺失、未知或断连状态不会当成无执行器。
- 更新期间停止网关及其管理的组件。页面断开后会继续查询状态；关闭页面不会取消已受理的后台更新。

整个流程为：检查并固定版本 → 复核安全状态 → 沿已保存的生命周期停机 → 构建已选模块并切换安装代际 → 沿同一生命周期启动 → 核对实际运行版本。失败时尝试恢复旧源码及旧代际。网关恢复可用不等于机器人全部功能已经验收，运动、感知等能力仍需按接入与发布要求验证。

更新沿用已安装的模块、机器人适配器、解释器、安装目录和运行模式，编译并行上限为2。设备依赖由适配器声明；缺少必需的软件包、设备 SDK 或运行库时明确报告，不在后台等待 sudo 密码，也不会替换为另一种机器人来绕过检查。

私有仓库需要安装账户已有可用的 Git 读取权限。网页不收集令牌、密码或任意更新命令。自定义安装目录从受管启动器及安装描述识别；必要时可在部署环境设置 `NUWAX_UPDATE_INSTALL_DIR`，不能通过网页修改。

## 统一命令入口

命令行与网页调用同一个运行中的网关更新接口：

```bash
./install.sh update check
./install.sh update install --yes --wait
./install.sh update status
```

可用 `--url` 指定已运行网关的地址。远程地址应由使用者确认；客户端不保存 SSH 或 Git 密码。`--wait` 等待后台事务结果，客户端退出或等待超时不会取消已受理的更新。

旧文件名 `scripts/update_go2.py` 仅作兼容转发，支持相同的 `check`、`install`、`status` 命令。它不再调用独立的设备部署或双端构建编排；旧的 `plan/build/deploy/verify` 参数不属于这个更新客户端。

运动守卫、网络准备、执行器清单校验以及必要的系统服务依赖顺序仍有用途。这些组件服务于具体适配器及设备能力，不构成另一套按型号分流的软件更新流程。

## 支持范围

当前自动安装面向 Debian、Ubuntu及兼容发行版的 x86_64 / aarch64 Linux，依赖支持 Python 3.8—3.12。其他操作系统或架构不能据此假定可安装，先查看 `doctor` 和安装计划。

机器人类型来自现有注册表及安装依赖声明。新增设备需实现并注册适配器、补齐实际依赖和传感器/执行器协议，再完成硬件验证。通用装配入口不会自动生成真实标定或驱动；注册为骨架的适配器也不会因此变成完整产品。支持范围与验证状态见[发布与兼容性](发布与兼容性.md)。

## 缓存与恢复记录

更新成功后只清理受管安装目录中的可重建缓存，例如 `cache/build`、`cache/sources`、`cache/downloads` 和 `cache/slam2d-dependencies`。保留工具链、设备 wheel、配置、地图、模型、业务数据库、日志及当前/回退环境；只回收本更新器创建且未被配置引用的更早代际。未知目录保留，不运行全仓库 `git clean`。回退代际不能当作普通缓存删除。

构建或新网关启动失败时，更新器尝试恢复更新前的源码提交与安装链接，并核对旧网关运行版本。若恢复失败或进程被强制终止，状态显示需要人工恢复，不自动重复部署同一失败版本。详细事务记录和日志位于源码根的 `runtime_data/updates`。

数据格式迁移不会随源码与环境自动回退。重要数据仍需事先备份，恢复前必须确认旧版本与现有数据格式兼容。

## 手动更新与备份

正常更新优先使用上面的统一更新命令。网关无法运行、需要维护源码或调整安装方案时，可以手动操作。在源码根记录当前版本和安装描述：

```bash
git branch --show-current
git rev-parse HEAD
./install.sh list --json
./install.sh stop
```

先完成或取消正在运行的任务，确认设备安全停机，再停止网关。按数据的重要性保存可恢复副本，至少包括当前机器人方案、完整地图资产、记忆数据库及关联文件。数据库应在相关进程停止后保存；地图不能只保留缩略图。默认位置与自定义路径规则见[安全与数据说明](安全与数据说明.md)。

确认没有需要保留的源码修改：

```bash
git status --short
```

有修改时先处理其归属，不用强制覆盖或清理命令掩盖冲突。当前分支配置了上游、工作区干净时：

```bash
git pull --ff-only
./install.sh install --dry-run
./install.sh install --yes
./install.sh doctor
./install.sh start
```

`--ff-only` 遇到分叉会停止。更新后核对接口、数据和所选能力，再进行设备任务验证。使用自定义安装目录时，每个安装管理命令都带上原来的 `--install-dir`。

安装器默认沿用上次模块选择与运行模式。`--modules` 或 `--preset` 指定完整目标集合；增量加入能力使用 `add`：

```bash
./install.sh add navigation --yes
./install.sh remove perception --yes
```

这些操作前同样需要停止网关。移除模块时，依赖它的模块也会从目标方案移除，计划中会明确列出。

## 安装失败后如何恢复

安装器在独立目录创建新环境，依赖、构建和产物检查通过后才切换 `current`。下载、编译或模型准备失败时，上一个有效环境保留；安装日志位于安装根的 `logs/`，处理原因后重跑相同安装命令。

**手动安装保留旧环境，不表示手动更新的源码和业务数据已经自动回退。**启动器仍使用原源码目录。手动恢复时先恢复记录的源码版本，再核对配置和数据格式；存在未提交修改时先处理其归属，避免覆盖工作。

安装产物损坏时，停止网关后执行：

```bash
./install.sh install --repair --yes
./install.sh doctor
```

修复针对当前源码与模块选择，不是降级命令。保留的原始档案部署工具供其明确的部署场景使用，其中的 `rollback` 不适用于模块安装。统一更新保留当前与上一有效代际，但不承诺任意历史版本可一键切回；手动安装也可能回收未被配置引用的旧代际。

## 迁移与移除

安装描述和产物含绝对路径。换源码目录、磁盘或主机时，在新位置重新安装，显式迁移配置与数据并重新验证，不能只移动 `current` 链接。

暂停使用时执行 `stop`。模块管理支持移除可选模块，基础模块不能通过 `remove core` 删除。当前没有一键清空所有数据的卸载命令。完整退役前先核对数据去向、安装方式和自定义路径，再移除明确的安装产物；系统共享依赖、设备安全基础服务与现场数据不能随源码目录一并清理。
