# 贡献指南

Nuwax Embodied Harness（NEH，具身运行框架）当前面向有仓库访问权限的协作者。项目许可证待定，贡献与第三方材料引入按双方明确的授权执行，不默认授予开源或再分发权利。

## 适合参与的工作

设备接入、可复现故障修复、安装兼容性、公开文档和具名场景验证都可以独立贡献。先搜索已有问题，描述具体用户场景、现有行为、预期结果以及验证方法。

设备接入请先读[架构与机器人接入](架构与机器人接入.md)，记录传感器、数据格式、坐标时间、厂商依赖与运动执行边界。注册一个设备名称不等于完成该设备的功能支持。

## 准备修改

从维护者约定的开发分支开始；目前为 `refactor/map-explore-nav`。不要以旧 `main`（主分支）的架构说明推导当前行为。

使用独立分支提出修改，先明确改动范围及兼容性。代码内部旧名称仍保留，纯品牌修改不重命名配置键、协议字段、服务或持久数据。修改契约时同步生产方、消费方、绑定和示例。

注释、用户提示及公开文档使用中文；新增公开说明放在 `docs/公开文档/`。不要提交私有配置、现场地图、模型权重、运行日志或构建产物。

## 怎样验证

按修改的实际风险选择检查，不为文字改动编造实机成绩：

```bash
# 无设备、无依赖安装的计划检查
./install.sh --help
./install.sh install --preset basic --robot customrobot --json

# 安装器及部署入口静态检查；需要已安装相应检查工具
bash scripts/ci/check_deployment_installer.sh

# 代码分层检查
bash scripts/check_layering.sh
```

已安装基础模块时，无机器人检查可使用当前虚拟环境：

```bash
runtime_data/installation/current/venv/bin/python scripts/diagnostics/offline_platform_smoke.py
```

该检查使用合成数据，验证真实网关与工具流程，不能替代传感器、模型准确率或实机运动。部分独立测试和开发资料按仓库约定只留在维护者本机，新克隆不具备这些资料；不要声明远端已运行本地专有检查。

## 提出合并请求

PR（合并请求）写清用户触发条件、改动后的行为、测试命令与结果、设备和输入范围，以及仍未验证的部分。涉及配置或升级时补上迁移说明；涉及算法时提供同输入、同版本的可比较证据。

描述最终实现，避免堆放全部过程日志。失败与未运行分别列出，不以接口可响应代替功能完成。维护者审核后再安排合并和设备部署。

## 第三方依赖

记录来源、固定版本、许可、目标架构及下载方式；保留原版权与许可证。模型许可、厂商开发包许可和项目源码许可可能不同，不能用一种许可覆盖全部内容。当前没有新增项目级许可证。
