# 发布与兼容性

Nuwax Embodied Harness（NEH，具身运行框架）从固定的源码提交准备运行版本：五个程序优先使用云端预编译产物，FastLIO2 与 PointLIO 始终在设备本机从源码编译。软件检查通过只代表对应版本与环境，机器人现场功能需要另行验收。

## 获取哪个版本

首次执行[单命令安装入口](安装与更新.md#一条命令安装并打开网页)，在管理页选择模块。默认跟随 `main`（主分支）通道：只有云端源码检查与五程序预编译全部通过的提交才会进入通道。每个安装或更新任务固定一个完整提交，页面显示为 `git-提交前12位`。日常执行 `neh update` 即可，无需手工选择附件。默认每 30 分钟检查并提醒，自动安装默认关闭。

## 当前交付与验证范围

| 范围 | 当前说明 |
| --- | --- |
| 安装环境 | Linux x86_64 与 ARM64，Debian/Ubuntu 系；业务代码支持 Python 3.8—3.12（Go2 为 Ubuntu 20.04、Python 3.8） |
| 可安装机型 | `customrobot`（通用接入）、`go2`、`unitree_sim`（仿真设备） |
| 建图模块 | 二维、FastLIO2、PointLIO 可共同安装，也可搭配导航；运行哪条链由配置决定 |
| 更新方式 | 固定提交、候选版本独立准备、失败保留旧版本；同提交、同模块且配置无变化时跳过构建与重启 |
| 云端预编译 | 二维建图工作进程、几何运行时、导航程序、人物跟随、建图命令工具；平台 `focal-arm64`（Ubuntu 20.04、ARM64）与 `noble-x86_64`（Ubuntu 24.04、x86_64）；其它平台或附件不可用时本机编译 |
| LIO 编译与分发 | FastLIO2、PointLIO 不进预编译，不发布二进制；设备本机编译，出货预装前需取得兼容授权，见[许可说明](第三方许可证说明.md#lio-程序的源码编译与分发范围) |
| 仿真平台验证 | 当前版本在仿真 Go2 办公室场景通过实时建图中的选点导航、找目标与到达复核、运动中急停；有边界探索按时长结束但未完成子目标 |
| Go2 实机 | 当前版本尚未完成实机统一复验；旧版本保存的地图格式不迁移，升级后需重新建图 |
| 视觉与语义记忆 | 按所选模块准备推理依赖和模型；Jetson（嵌入式计算平台）需要匹配的厂商推理库；全模型推理未在所有设备上验收 |
| 访问与密码 | 管理页默认免密码，可设置密码；网页写入检查同源与会话 |
| 许可证 | 项目自有代码为 GPL-2.0-or-later（GNU 通用公共许可证第 2 版或更高版本）；第三方组件保留各自许可，见[第三方许可证说明](第三方许可证说明.md) |

## 升级时的变化

- **配置格式。** 当前版本的配置是 TOML（配置文本格式）方案文件（见[配置说明](配置说明.md)）。从较旧的版本升级时，旧格式的方案在更新过程中自动转换一次，转换后删除旧文件。
- **地图格式。** 地图目录格式已更换，旧版本保存的地图不能直接加载，需要重新建图。
- **旧管理程序。** 2026-10-23 之前安装的管理程序需对原安装目录重跑一次引导器，见[安装与更新](安装与更新.md#较旧的管理程序)。

## 名称兼容

产品名为 NEH；以下内部名称继续使用，不要做全仓库字符串替换：

| 保留内容 | 示例与原因 |
| --- | --- |
| Python/Rust（编程语言）包和程序 | `nuwax-*`、`nuwax_robot_bridge`；避免改变导入和构建 |
| 协议与工具标识 | 消息通道、响应字段和协议服务器名称；避免破坏客户端 |
| 已有设备目录 | 设备上的实际路径不随仓库改名移动 |

旧克隆可在仓库根更新远端地址：

```bash
git remote set-url origin https://github.com/Molun0301/nuwax-embodied-harness.git
```

合作方与自动化配置中的仓库链接也需核对。

## 设备投入使用前的验收

安装成功只说明文件、依赖和入口已准备好；现场还需核对传感器输入、定位与地图、运动执行、停止与异常恢复。视觉与模型组合要使用与设备软件栈匹配、已验证能加载的依赖。长期运行还需观察磁盘增长（地图、原始扫描暂存、建图记录、日志）、断线恢复与计算开销。

详细能力见[功能列表](功能列表.md)，安装与回退见[安装与更新](安装与更新.md)。
