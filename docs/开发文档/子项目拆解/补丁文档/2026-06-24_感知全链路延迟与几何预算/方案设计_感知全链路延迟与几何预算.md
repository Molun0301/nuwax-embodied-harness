# 方案设计：感知检测链路解耦与全链路延迟诊断

## 1. 背景与修正结论

实机日志显示 `perception.scene_ready` 的 `duration_ms=3320.427`，该字段不是 detector 单阶段耗时，而是感知服务在 `PerceptionService._process_image_locked` 中记录的 `stage_duration_ms.total`。用户已确认实机 `.env` 正确使用 `.engine`/TensorRT，因此本轮排查不得把开发机缺模型或 `.pt/.engine` 文件存在性作为主要根因。

持续感知确实存在检测频率配置 `NUWAX_PERCEPTION_STREAM_INTERVAL_SEC`，默认 `0.5s`。当前问题的关键不是“YOLO detector 是否存在”，而是现有 `video.detections` 发布被完整 `process_image` 链路同步拖住：detector 之后还要等待 segmentation、geometry、tracker、scene_description 等阶段完成，Web 检测框才刷新。

用户进一步明确：YOLO-World 检测及监控 Web 检测框应与记忆慢链路分离；同时记忆三角测量也需要高频检测/跟踪观测输入。因此本轮修复方向调整为：

1. 高频链路：视频帧 → YOLO-World detector → 2D tracker → `video.detections` → Web 检测框，同时向连续记忆/三角测量提供 bbox/track/ray 样本。
2. 慢链路：segmentation、geometry、scene_description、keyframe memory 固化、落盘和向量化可以继续存在，但不得同步阻塞高频检测链路。
3. 本轮不改点云预算、不改 `PointCloudProvider` API、不对 `pointcloud.frame` stream/provider 入口做下采样或限流；geometry 只从 fast path 移出，不在本轮做算法优化。
4. 监控 Web 不新增可见信息，继续只使用现有 `video.detections` 绘制检测框。

本方案的 OpenSpec 变更为：`openspec/changes/restore-yolo-tensorrt-latency/`。

## 3. 设计决策

### 3.1 建立 fast detection observation path

首版 SHALL 新增或拆出轻量检测入口，只做：

1. 从端侧视频源读取最新帧；
2. 调用 YOLO-World detector；
3. 调用 2D tracker 并附加 track_id；
4. 构造轻量 observation/context；
5. 发布 `video.detections`；
6. 向连续记忆摄入/三角测量提供同一份观测输入。

该路径 MUST NOT 等待 segmentation、geometry、scene_description、keyframe memory 写入、落盘或向量化。

### 3.2 高频检测同时服务 Web 与记忆三角测量

Web 检测框和记忆三角测量使用同一个高频观测来源。Web 使用 bbox/label/score/track_id 绘制框；记忆连续摄入使用 frame_id、timestamp、camera pose、bbox、track_id 和射线信息累积多视角样本。

关键帧只决定何时把当前语义结果固化为记忆、落盘或向量化；它不得决定是否执行 YOLO 检测，也不得决定 `video.detections` 是否发布。

### 3.3 慢链路 latest-only，不反压 fast path

segmentation、geometry、scene_description、keyframe memory 写入属于慢链路。慢链路可以消费最新 fast observation 做增强或固化，但不能让 fast detection tick 等待。

当慢链路仍在处理上一帧时，首版 SHOULD 使用 latest-only/coalescing：保留最新待处理观测，丢弃过期观测，避免形成无限队列和越来越旧的 scene summary。

### 3.4 geometry 本轮不做点云预算/入口改造

用户明确指出“给点云加预算”和“stream/provider 两条入口限流”方向偏离。本轮 SHALL 明确不做以下改动：

1. 不修改 `NUWAX_GEOMETRY_POINT_CLOUD_MAX_POINTS` 语义；
2. 不把现有 geometry 点云预算作为本轮 fast detection 修复项；
3. 不扩展 `PointCloudProvider.get_latest_point_cloud` 签名；
4. 不改 Go2 provider 点云拉取 API；
5. 不对 `pointcloud.frame` stream_bus payload 或 provider fallback 做下采样、限流、裁剪；
6. 不优化 geometry polygon/投影算法。

geometry 在本轮只作为 slow path enrichment 保留；它可以慢，但不允许拖慢 YOLO 检测、Web 检测框或连续三角测量观测输入。

### 3.5 热路径事件与 Web 保持轻量

`perception.scene_ready` 事件 SHALL 继续用于完整感知结果，保留阶段耗时和必要摘要。fast path 的 cadence/latency 诊断进入运行时状态、API、日志或测试钩子。

监控 Web 不新增可见信息：页面继续只使用现有 `video.detections` 绘制检测框，不增加新的指标、文本或布局元素。

## 4. 实施边界

首版实现范围：

1. fast detection observation path：detector + 2D tracker + `video.detections` 发布。
2. continuous observation ingest：fast context 能进入 `persist=False` 连续摄入或等价轻量适配器，用于三角测量射线累积。
3. slow/full perception 解耦：segmentation、geometry、scene_description、keyframe memory 固化使用 latest-only/coalescing，不阻塞 fast tick。
4. tracker 单写：tracker 状态只在 fast path 更新，slow path 消费带 track_id 的 snapshot。
5. 后端诊断：记录 detector duration、fast loop elapsed、`video.detections` interval、fast processed frames、continuous ingest count、full-chain total。
6. Web 保持现有布局和绘制链路。

非首版范围：

1. 不改 detector runtime 选择逻辑。
2. 不改点云预算配置。
3. 不改 point cloud provider API。
4. 不对 stream/provider 点云做限流或下采样。
5. 不优化 geometry polygon/投影算法。
6. 不新增 Web 可见诊断字段。

### 5.2 实机 HIL 验证

实机 HIL 报告 SHALL 记录以下字段：

| 字段 | 要求 |
| --- | --- |
| 模型路径 | 标明 `.engine` 路径与 detector backend/runtime。 |
| 输入图像 | camera_id、width、height、image_size。 |
| 检测节拍 | `NUWAX_PERCEPTION_STREAM_INTERVAL_SEC`、runtime running/enabled/auto_start、fast processed frames、`video.detections` 发布间隔、Web 观察到的检测框刷新间隔。 |
| fast 耗时 | detector duration、tracker duration、fast loop elapsed、publish interval 的 P50/P95/max。 |
| 连续摄入 | continuous observation ingest count、失败数、是否 `persist=False`。 |
| full-chain 耗时 | detector、segmentation、geometry、tracker、scene_description、total 的 P50/P95/max。 |
| 质量结论 | track_id 是否稳定、三角测量射线样本是否随 fast tick 累积、keyframe 固化是否仍可用。 |

若 `video.detections` 已接近配置频率但 full-chain total 仍高，说明检测框和三角测量输入已从慢链路解耦；full-chain 慢阶段作为后续独立优化项处理。若 `video.detections` 仍低频，应按 detector、tracker、video source、publish、runtime scheduling 排查，不回退到点云预算/provider/stream 限流方向。

## 6. 回滚与降级

若 fast/slow 解耦导致行为异常，可按以下顺序处理：

1. 回退到旧同步 full perception path，确认问题是否由解耦引入。
2. 保留 fast `video.detections`，临时关闭 slow path 后台消费，验证 Web 与 detector cadence。
3. 若 continuous ingest 太慢，临时只发布 Web overlay，不做记忆摄入，以定位 memory 投影/关联成本；随后单独优化 continuous ingest。
4. 若 track_id 抖动，确保 tracker 只在 fast path 单点更新，slow path 不重复 update。

## 8. 实施记录（2026-06-24）

### 8.1 本地代码实施

本次实施选择“先恢复检测框与连续观测节奏，再保留完整感知作为独立诊断/增强链路”的首版边界：

1. `PerceptionService.detect_current_frame_fast()` / `process_image_fast()` 新增快速检测观测入口，只执行：读取 latest 视频帧、发布底图、YOLO detector、2D tracker、track_id 附加、轻量 `Observation`/`PerceptionContext` 构造和 `video.detections` 发布。
2. 快速路径显式标记 `segmentation`、`geometry`、`scene_description` 为 `skipped_fast_path`，不调用对应 provider，也不发布 `perception.scene_ready` 完整感知事件。
3. `video.detections` 仍复用原 topic/payload 绘制链路；新增的 `overlay_phase`、`publish_interval_ms` 只在后端 payload/metadata 中用于测试和诊断，监控 Web 页面没有新增可见字段、文本或布局。
4. `PerceptionVideoRuntime._run_once_locked()` 改为每个 tick 调用 fast path；`NUWAX_PERCEPTION_STREAM_INTERVAL_SEC` 现在驱动 detector + tracker + overlay 的快速循环，而不是完整 `process_image` 总耗时。
5. 非关键帧连续摄入继续调用 `MemoryService.ingest_perception_observation(..., persist=False)`，用 fast context 的 bbox、track_id、frame_id、相机位姿等输入累积三角测量/射线样本，不落盘、不向量化。
6. 关键帧记忆写入改为后台 latest-only/coalescing：已有写入线程忙时只保留最新 pending job，避免慢记忆写入反压下一次 fast tick；fast tick 可继续推进。
7. 运行时状态 `metadata` 记录 `fast_processed_frames`、`continuous_ingest_count`、`fast_loop_duration_ms`、`detector_duration_ms`、`tracker_duration_ms`、`video_detections_interval_ms`、`last_full_stage_duration_ms_total` 和后台记忆写入计数；没有修改 `PerceptionRuntimeStatus` schema 字段。
8. `PerceptionService` 保留最近一次完整感知缓存 `get_latest_full_perception()`，fast context 不覆盖该 full-chain total 诊断来源。

### 8.2 明确未改范围

本次实施没有修改以下内容：

1. `NUWAX_GEOMETRY_POINT_CLOUD_MAX_POINTS` 语义；
2. `PointCloudProvider.get_latest_point_cloud` 签名；
3. Go2 provider 点云拉取 API；

5. geometry polygon/投影算法；

geometry 仍作为完整感知/慢链路增强阶段保留；本轮只保证高频 detector/tracker/overlay/continuous observation 不等待 geometry。
