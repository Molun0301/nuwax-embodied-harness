# 智能体与应用接入

Nuwax Robot Bridge 向上层应用提供机器人能力：读取状态、获取图像、管理地图、检索记忆，以及发起导航和探索任务。对话、模型选择和高层规划由你的应用负责。

网页和外部调用共用服务与任务机制。接入时先发现当前设备的能力，再按返回的参数结构调用。

## 选择入口

| 入口 | 适合的调用方 | 地址 |
| --- | --- | --- |
| MCP（模型上下文协议） | 已支持该协议的智能体 | `/mcp` |
| 智能体 HTTP（超文本传输协议）接口 | 自建应用、脚本与轻量客户端 | `/api/agent` |
| 公共能力接口 | 需要直接调用能力的前端或应用 | `/api/capabilities/{name}/invoke` |
| 浏览器控制台 | 人工观察、操作和调试 | `/console` |

下文示例假设网关已在本机 `8766` 端口运行。在远程智能体或容器中，请替换为调用方可达的网关地址。

## 先发现能力

仓库自带的[轻量客户端](../../clients/robot_client.py)只依赖 Python（编程语言）标准库，可以单文件复制到应用环境。

```bash
python3 clients/robot_client.py --url http://127.0.0.1:8766 info
python3 clients/robot_client.py --url http://127.0.0.1:8766 tools
python3 clients/robot_client.py --url http://127.0.0.1:8766 tools --name get_robot_status
```

目录提供真实工具名称和参数结构。可见工具会随机器人能力和配置变化；某项能力可被发现，也可能仍需要在调用时启动后端或等待数据。

直接访问接口也可读取相同入口信息：

```bash
curl -fsS http://127.0.0.1:8766/api/agent
curl -fsS http://127.0.0.1:8766/api/agent/tools
```

## 使用 MCP

在智能体客户端中添加 HTTP 类型的 MCP 服务器，地址填写 `http://127.0.0.1:8766/mcp`。客户端完成初始化后调用 `tools/list`（工具发现），按实际返回的名称和模式执行。

工具目录包含平台集合 `platform`、设备集合 `device`，以及部分独立工具。集合通过 `function` 选择能力，用 `parameters` 传入参数。例如，下面是读取机器人状态的工具调用参数片段：

```json
{
  "name": "platform",
  "arguments": {
    "function": "get_robot_status",
    "parameters": {}
  }
}
```

这是 `tools/call`（工具调用）的参数部分，前提是当前目录已公开该功能。独立工具直接接收其参数；名称和结构均以当前服务器发现结果为准，不需要硬编码一份工具全集。

## 调用与读取回执

确认目录中存在 `get_robot_status` 后，可以执行只读调用：

```bash
python3 clients/robot_client.py --url http://127.0.0.1:8766 \
  invoke get_robot_status --request-id status-demo-001 --arguments '{}'
```

`request_id` 是调用标识，便于查询同一次调用。每个新的业务操作使用新标识；如果响应丢失，先查询原标识，不盲目重发运动操作。

```bash
python3 clients/robot_client.py --url http://127.0.0.1:8766 call status-demo-001
python3 clients/robot_client.py --url http://127.0.0.1:8766 result --request-id status-demo-001
```

回执区分结果是否完整、是否仍待记录和是否创建了长任务。需要完整数据时，沿回执给出的结果或制品引用继续读取。

## 跟踪长任务

导航、探索、地图激活等操作可能返回 `task_id`（任务标识）。保存该标识，查询或等待原任务；下方的 `TASK_ID` 需替换为实际返回值：

```bash
python3 clients/robot_client.py task TASK_ID
python3 clients/robot_client.py wait TASK_ID --timeout-sec 30
python3 clients/robot_client.py result --task-id TASK_ID
```

这些命令默认连接本机；使用远端地址时，在子命令前添加 `--url`。

任务通常经过 `accepted`（已受理）、`running`（运行中），最终进入 `succeeded`（成功）、`failed`（失败）、`cancelled`（已取消）或 `timeout`（超时）。一次等待结束不等于任务结束；按返回状态与轮询建议继续查询。

需要取消时，客户端提供 `cancel TASK_ID`。取消回执表示请求已处理到相应阶段；涉及真实运动时，还应核对原任务的停止结果。关闭网页、退出客户端或等待超时不会自动取消已经受理的机器人任务。

任务历史并非全部持久化。网关重启后，不能假定旧任务可自动接着执行；探索恢复使用已成功保存的检查点，并重新完成定位和执行条件检查。

## 让调用对应可验证的结果

一个“去门口看看”的任务，可以按以下顺序组织：

1. 查询机器人、当前地图、定位与导航状态。
2. 从当前地图中的命名地点或记忆记录解析“门口”。
3. 对有效目标发起导航，保存任务标识并等待最终结果。
4. 到达后获取新的图像或感知结果。
5. 分别报告导航是否到达、现场看到了什么，并引用实际证据。

检索到物品、推断区域相邻、获得导航候选，都不等于路线已可执行。地图不匹配、只有观察位置或证据过期时，保留返回的具体原因。

## 读取语义地图

启用语义地图后，公共工具可提供区域与空间关系。主要入口包括：

| 工具 | 返回内容 |
| --- | --- |
| `get_semantic_map` | 区域边界、名称与候选状态 |
| `get_scene_graph` | 区域、连接口、物品和观察节点及邻接关系 |
| `get_scene_graph_node` | 节点位置、范围与证据引用 |
| `plan_scene_graph_route` | 区域之间的候选连接路线，不执行运动 |
| `render_scene_graph_image` | 带编号地图图像的制品与编号对照 |
| `update_scene_space_label` | 按预期修订修改区域名称 |

这组能力仍在实验阶段。修改名称使用当前区域标识和修订，冲突时重新读取；模型结果不能自行生成未经几何与运动链核验的目标坐标。

## 图像与其他制品

抓图或地图图像工具返回制品引用。先使用真实返回的 `artifact_id`（制品标识）下载，再把文件交给支持图像输入的模型。下面的标识需替换为真实值，输出路径应尚不存在：

```bash
python3 clients/robot_client.py artifact ARTIFACT_ID --output ./现场图像.jpg
```

工具中的文字摘要不等同于模型已经读取原始图像。完整的可复用任务提示词见 [Go2 提示词示例](Go2提示词示例.md)。
