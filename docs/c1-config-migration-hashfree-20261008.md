# 配置备份和迁移比较移除内容摘要

日期：2026-10-08。比较基线：`cb80236497088eb9d5358212dfe09b93cff53002`。

## 修改范围

- 配置备份使用事务目录内的 `nuwax.env.bak` 和 `go2-data-plane.env.bak`，不再对路径计算 SHA-256。两个实际调用方的文件名不同，事务目录仍隔离不同更新。
- 原 manifest 仍保存备份文件名，恢复按该字段读取。因此既有 64 位十六进制命名备份无需改名，也不需重新计算摘要。
- 单文件和目录迁移遇到已存在目标时，以成对的 1 MiB 块直接比较内容。相同内容沿用原文件，差异仍报告原冲突，不覆盖目标。
- 没有新缓存、锁或校验框架。打开和读取错误继续向上传播；提前发现差异后不再读尾部，因此不会遇到原摘要扫描可能在尾部遇到的读取错误。

这只是应用内命名和内容等价比较的移除，不是整个项目的哈希清理完成声明，也不修改制品来源或认证机制。

## 真实运行验证

在 CPython 3.8.20 / NumPy 1.24.4 / Pydantic 2.10.6 下：

- `scripts/check_hashfree_config_migration.py --baseline <旧 operations.py>`：12 项通过，无跳过
- 从 `scripts/ci/check_deployment_installer.sh` 原样提取的离线 `DeploymentContracts`：11 项通过

相同生产候选在先前 Python 3.12 环境也通过这两组检查，结果分开记录，不把 AST 语法检查当作 Python 3.8 运行验证。

聚焦检查覆盖两个实际配置名、manifest、原始内容和权限恢复、同事务重复备份、不同事务隔离、缺失原文件、旧文件名恢复、分块边界、相同大小及修改时间但内容不同、读失败、重复迁移和冲突保留。旧摘要调用的三个负例按预期触发，当前路径在摘要函数被替换成抛错函数时通过。

默认执行 `python3 -B scripts/check_hashfree_config_migration.py` 不依赖历史文件，12 项中运行 10 项并明确跳过 2 项历史专用检查。只有显式传入可信基线源文件时才加载并执行它。

## 边界

没有运行完整安装、systemd、真实主机配置、模型或 SDK 构建，也没有速度收益测量。递归迁移的原有非原子性和目标树内嵌套符号链接边界未扩展；不把这次变化描述成通用备份框架或新的安全策略。
