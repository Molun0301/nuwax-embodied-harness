# 单命令安装与端侧增量更新

Nuwax Embodied Harness（NEH，具身运行框架）在设备上获取源码、安装依赖并增量构建。维护者把代码推送到GitHub（代码托管平台）后，设备即可检查并安装新提交。云端只运行源码检查。

## 一条命令安装并打开网页

当前处于私有测试阶段。在目标Linux（操作系统）设备的普通用户终端，整段复制执行下面这一个命令。命令自动准备工具、引导账户授权、获取源码、安装独立管理程序并打开网页。

```bash
bash -c '
set -euo pipefail
umask 077
if [[ ${EUID} -eq 0 ]]; then
  echo "请以普通用户运行，安装服务时会自动请求管理员权限。" >&2
  exit 1
fi
if [[ $(uname -s) != Linux ]]; then
  echo "此安装入口仅支持Linux。" >&2
  exit 1
fi
NEH_ENTRY_TEMP=$(mktemp -d -t neh-entry.XXXXXXXX)
trap "rm -rf -- \"$NEH_ENTRY_TEMP\"" EXIT
if ! command -v gh >/dev/null 2>&1; then
  if ! command -v curl >/dev/null 2>&1; then
    sudo apt-get update
    sudo apt-get install --yes curl ca-certificates
  fi
  case "$(uname -m)" in
    x86_64) NEH_GH_ARCH=amd64; NEH_GH_SHA=bb766f710eef8ede859c18578c72c327597cd4c8a85b06001b1f3843c6019386 ;;
    aarch64|arm64) NEH_GH_ARCH=arm64; NEH_GH_SHA=7862c86c72f43df3a2d93ddde6f473285b4e2af61b494849846827e513ef6484 ;;
    *) echo "当前安装入口支持Linux x86_64和ARM64。" >&2; exit 1 ;;
  esac
  curl --fail --silent --show-error --location --retry 3 "https://github.com/cli/cli/releases/download/v2.102.0/gh_2.102.0_linux_${NEH_GH_ARCH}.tar.gz" -o "$NEH_ENTRY_TEMP/gh.tar.gz"
  printf "%s  %s\n" "$NEH_GH_SHA" "$NEH_ENTRY_TEMP/gh.tar.gz" | sha256sum --check --status
  tar -xzf "$NEH_ENTRY_TEMP/gh.tar.gz" -C "$NEH_ENTRY_TEMP" --strip-components=2 "gh_2.102.0_linux_${NEH_GH_ARCH}/bin/gh"
  export PATH="$NEH_ENTRY_TEMP:$PATH"
fi
if ! gh auth status --hostname github.com >/dev/null 2>&1; then
  export GH_CONFIG_DIR="$NEH_ENTRY_TEMP/github"
  unset GH_TOKEN GITHUB_TOKEN GH_ENTERPRISE_TOKEN GITHUB_ENTERPRISE_TOKEN
  gh auth login --hostname github.com --web --git-protocol https --skip-ssh-key
fi
gh auth token --hostname github.com > "$NEH_ENTRY_TEMP/token"
if ! gh api "repos/Molun0301/nuwax-embodied-harness/contents/get-neh.sh?ref=main" --header "Accept: application/vnd.github.raw+json" > "$NEH_ENTRY_TEMP/get-neh.sh"; then
  echo "当前GitHub账户无法读取测试仓库，请使用已获得测试权限的账户。" >&2
  exit 1
fi
unset GH_TOKEN GITHUB_TOKEN GH_ENTERPRISE_TOKEN GITHUB_ENTERPRISE_TOKEN GH_CONFIG_DIR
bash "$NEH_ENTRY_TEMP/get-neh.sh" --token-file "$NEH_ENTRY_TEMP/token" "$@"
' neh-install
```

首次运行会在GitHub官方页面授权，账户需要已有测试仓库读取权限。缺少系统工具或安装服务时，终端会请求管理员密码。已有有效登录直接复用，下载凭据只保存在当前用户可读的设备配置中。

首段源码下载会复用私有入口已使用的GitHub CLI（`gh`）及本次授权；匿名入口、或没有`gh`时继续使用Python下载，不会额外要求登录。下载遇到连接意外中断、超时或暂时性服务器错误时，每个请求最多尝试3次，重试分别等待1秒、2秒；HTTP 401、403、404及证书验证失败不会自动重试。连续失败会给出简短原因，可检查设备网络后重新运行原安装命令。GitHub登录成功后的TLS（传输层安全协议）连接中断不等于账户没有权限；无需因此重复授权，也不要关闭证书验证。

有桌面时自动打开网页；通过SSH（安全远程连接）连接无桌面设备时，终端打印设备网址，用电脑浏览器访问。管理端口优先使用8765；被其它程序占用时自动选择空闲端口，并记住实际地址。业务网关默认8766，管理入口会避开该端口。项目开源后可以使用匿名下载入口；当前测试命令负责私有授权，无需手工下载或挑选发行附件。

## 自定义安装位置

新安装默认位于 `~/Nuwax-embodied-harness`。已识别的旧默认安装 `~/.local/share/neh` 会继续使用原位置，不会自动搬迁；只有旧目录存在、但没有安装记录时，不影响新默认值。首次安装不用修改命令，在网页的“硬件检查”步骤即可选择位置：

1. 在“选择存放安装的文件夹”中输入目标设备上的父目录完整路径，如 `/mnt/data`，也可使用 `~/NEH 数据`。网页输入不需要加引号，不会展开 `$HOME`。
2. 或点击“浏览设备目录”，进入文件夹、使用“上一级”或输入目录路径导航，再选择文件夹。浏览的是运行 NEH 的设备，不是打开网页的电脑；该步骤只填入待保存路径。
3. 页面会先显示最终安装位置，例如 `/mnt/data/Nuwax-embodied-harness`。确认后点击“保存安装位置”，安装器会创建该文件夹。父目录不必为空，里面的其他文件保持不变；若直接选择已命名为 `Nuwax-embodied-harness` 的文件夹，会复用它，不再嵌套同名目录。
4. 已有的目标子文件夹为空，或是本管理入口此前使用但尚未安装完成的目录时，可以继续使用；若其中已有无关内容或属于其他安装，会明确指出冲突文件夹，不覆盖或删除文件。实际安装文件夹须属于当前设备用户、可写且不允许其他用户写入。
5. 确认“当前生效的安装位置”显示新路径，再继续选择模块、查看安装计划。路径尚未保存时不能进入下一步；保存失败会显示实际原因，生效路径保持不变，可修正或“放弃修改”。

网页保存的目录承载业务版本、源码与构建缓存、运行依赖、模型、业务配置及数据。轻量网页管理程序、管理设置、登录凭据和任务记录仍留在最初的管理根目录，原网址与 `bin/neh` 管理入口继续可用；网页会显示两处位置。系统依赖和服务文件仍使用操作系统的标准目录。刷新网页或重启管理程序会保留已保存的选择。

已有成功安装的位置只读，不能通过此页面迁移；有任务运行时也不能修改。首次安装失败或取消后，待任务结束且安全恢复完成，可返回“硬件检查”重选目录。切换位置不会复制、搬迁或删除先前目录的文件和缓存；安装计划必须重新生成。

如果还希望改变轻量管理程序的起始位置，仍可在运行上面的整段命令前将最后一行改为下面这样；`neh-install` 是 `bash -c` 的入口名称，需要保留，后面的参数才会完整传给安装器：

```bash
' neh-install --install-dir "$HOME/NEH 数据"
```

已有源码或已下载引导脚本时，可直接使用：

```bash
bash scripts/neh_private_install.sh --install-dir "$HOME/NEH 数据"
# 或在已准备下载授权的情况下：
bash get-neh.sh --install-dir "$HOME/NEH 数据" --token-file "$HOME/neh-token"
```

命令行的 `--install-dir`、`--home`、`NEH_HOME` 和终端交互输入仍表示完整安装路径，不会自动追加文件夹名称。`--home` 继续作为同义参数兼容。也可先设置 `export NEH_HOME="$HOME/NEH 数据"`，再运行安装命令；显式参数优先于环境变量，均未设置时使用默认目录。路径包含空格或中文时用引号包住，家目录可写为 `"$HOME/..."` 或 `"~/..."`。目标目录须由当前用户持有且其他用户不可写，不要用 `sudo` 执行整个安装命令。

需要交互选择时，在首条命令末尾添加 `--cli`（即 `' neh-install --cli`）。第一次在终端安装且未指定路径时，会先显示默认位置，输入目标目录或直接回车，再进入模块安装向导。无交互终端、`--configure` 无人值守安装及默认目录已存在的重跑不会询问位置。

命令行指定的位置作为管理根目录；如果之后未在网页另选业务目录，管理程序与业务内容都保存在其中。安装输出、网页首次安装页、安装计划和设备概览会显示实际业务位置。后续继续使用同一网页或原管理根目录中的命令入口，启动、业务更新与回退会沿用保存的业务位置，管理程序更新仍使用原管理根目录，无需重复传参。以下示例假设最初通过命令指定了 `"$HOME/NEH 数据"` 作为管理根目录：

```bash
"$HOME/NEH 数据/bin/neh" status
"$HOME/NEH 数据/bin/neh" start --wait
"$HOME/NEH 数据/bin/neh" plan update --stop-running
"$HOME/NEH 数据/bin/neh" update-manager --wait
"$HOME/NEH 数据/bin/neh" rollback --stop-running --wait
```

下面各节的示例使用默认管理目录；命令行自定义管理根目录后，请替换为该目录中的 `bin/neh`。只在网页改选业务位置时无需替换命令入口。重新运行引导安装要指定原管理目录；另选管理根目录会创建独立管理入口，不会搬迁旧配置和数据。同一用户的系统管理服务会指向新的管理根目录，所以已有设备日常更新应继续使用原管理入口。

## 在网页选择模块

保存安装位置后，选择机器人、功能模块和首次配置，查看安装计划中的位置与模块，再执行安装。二维建图、FastLIO2（快速激光惯性里程计）和PointLIO（逐点激光惯性里程计）可以共同安装，也可以各自搭配导航、视觉或记忆模块。安装器自动补齐模块依赖。

安装决定设备具备哪些程序。当前使用二维或三维链路、三维定位采用哪个后端，由机器人配置选择；已有合法选择会保留。三种算法共同安装不要求同时运行。切换链路或定位后端后，按配置页提示重启相关服务。

默认源码仓库为本项目，分支为`main`（主分支）；管理页“更新来源”可修改仓库和分支。版本显示为`git-提交前12位`，每次计划固定完整提交。安装准备时下载需要的第三方依赖和模型，再在设备构建所选程序，验证后切换运行版本。Git（版本控制工具）传输和依赖解析尚不能预知的下载量会显示未知。

当前自动入口面向Linux x86_64及ARM64（64位精简指令集架构），Python（编程语言）3.8—3.12；不同系统仍需实际开发依赖和设备环境满足要求。具体验证范围见[发布与兼容性](发布与兼容性.md)。

## 更新如何复用缓存

以修改PointLIO代码为例：维护者提交并推送 → 设备检查更新取得提交 → Git传输需要的新对象 → 在固定源码和构建目录中运行增量构建 → 验证新版本 → 切换并恢复运行。

- 未改动的原生对象文件和第三方库继续复用；头文件、依赖或构建参数变化时，由构建工具重建受影响目标。
- Python依赖按依赖输入、解释器、平台和设备配方封存。只改PointLIO源码时复用原环境；依赖输入变化时准备新环境。
- 模型位于持久数据区，使用已有模型下载器的缓存和校验。Jetson（嵌入式计算平台）的推理库仍需匹配厂商软件栈。
- 候选运行版本使用独立源码、程序和动态库，正在运行的程序不直接使用可变构建缓存。编译或验证失败保留旧版本；需要切换时沿原启动拥有方停止、切换、启动并检查。
- 同一提交、模块与配置均无变化时直接结束，无需重建或重启。

首次安装需要下载依赖和完整编译，耗时会明显高于后续更新。构建缓存应保留；安装根默认为`~/Nuwax-embodied-harness`，配置、地图、模型与业务数据独立保存。

## 命令行与无人值守

CLI（命令行界面）与网页调用同一管理引擎。以下命令使用新默认位置；已有旧安装或自定义管理根时，请使用原目录中的 `bin/neh`。首次安装以后，也可用下面的命令查看设备、源码版本和安装计划：

```bash
~/Nuwax-embodied-harness/bin/neh hardware
~/Nuwax-embodied-harness/bin/neh releases --refresh
~/Nuwax-embodied-harness/bin/neh plan install --robot customrobot --modules slam2d,fastlio2,pointlio,navigation
```

计划返回标识且没有阻塞项后执行：

```bash
~/Nuwax-embodied-harness/bin/neh apply 实际计划标识 --wait
~/Nuwax-embodied-harness/bin/neh start --wait
```

Go2选择`--robot go2`。宇树软件开发包和CycloneDDS（数据分发中间件）依赖由固定的官方来源下载，首次生成本机Python接口缓存，无需用户预先选择安装文件。设备网络、雷达、惯性输入和标定仍按实际设备配置。

无人值守可提供JSON（结构化数据格式）文件：

```json
{
  "action": "install",
  "robot": "customrobot",
  "modules": ["core"],
  "configuration": {},
  "stop_running": false
}
```

```bash
~/Nuwax-embodied-harness/bin/neh apply --file 安装配置.json --wait
```

更新沿用所选模块，运行中的业务需要明确允许切换时停机：

```bash
~/Nuwax-embodied-harness/bin/neh plan update --stop-running
~/Nuwax-embodied-harness/bin/neh apply 实际计划标识 --wait
```

关闭终端不会取消已受理任务，可用`jobs`、`job 实际任务标识 --wait`查看。管理程序通过`update-manager --wait`从同一源码分支更新；业务回退使用`rollback --wait`，运行中同时加`--stop-running`。回退使用本机保留的已验证版本；配置和业务数据是否兼容仍须核对。

## 维护者推送代码

维护者提交代码并推送目标分支即可。`.github/workflows/product-release.yml`检查引导脚本、Python兼容性和管理程序源码组装；默认工作流不编译机器人原生程序，也不生成模块组合发布矩阵。设备安装不等待云端构建附件。

历史`v0.1.0`发布资产和显式旧版本目录接口继续保留，以便已有安装迁移。日常源码安装和更新不需要修改`.github/release.json`、生成标签或等待重新打包。
