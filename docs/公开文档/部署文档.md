# 安装与部署

Nuwax Embodied Harness（NEH，具身运行框架）的正式使用入口是[轻量安装与自动更新](轻量安装与自动发布.md)：独立管理服务取得固定源码提交，在设备增量构建并保留配置与数据。

本文保留源码模块安装和开发机更新已有设备的流程，适用于开发、接入调试及维护既有源码安装。第一次获取源码请先读[安装前准备](安装前准备.md)。

当前计算主链使用 Rust（系统编程语言）与原生算法，Python（编程语言）负责服务编排和网关。旧版 ROS 2（机器人操作系统第二版）几何工作区及相关导航代理不再是本指南的安装路径。

下文命令在仓库根目录执行；Go2（宇树四足机器人）更新命令在开发机执行。

## 环境与模块

本机自动安装支持 Debian、Ubuntu（操作系统）系列，安装器使用 Python 3.8—3.12，按所选模块准备系统依赖和 Rust 工具链。公共计算工作区声明的 Rust 最低版本为 1.88。

基础网关、原生建图和本地视觉模型的资源需求不同，因此不提供一个覆盖所有组合的最低内存数字。安装器依据处理器和可用内存调整构建并行数；视觉模型还需匹配推理环境。Jetson（嵌入式计算平台）使用相应厂商张量库，Go2 接入依赖由安装器从固定官方来源准备。

| 模块 | 安装内容 | 运行前提 |
| --- | --- | --- |
| `core` | 基础网关、控制台、标准数据入口 | 实时数据需另行接入 |
| `geometry` | 几何运行时和地图能力 | 有效传感器、坐标与所选后端 |
| `slam2d` | 二维激光建图、图定位及雷达驱动 | 二维扫描、所需里程计与标定 |
| `fastlio2` / `pointlio` | 一种三维激光惯性定位前端 | 规范点云、惯性数据与外参 |
| `navigation` | 导航、探索及运动守卫相关程序 | 地图、定位、机体参数与执行器 |
| `perception` | 本地视觉依赖与模型 | 图像和可用推理环境 |
| `memory` | 本地文本、图像向量模型 | 可记录观察及相应模型配置 |
| `follow` | 人物跟随程序，并补齐视觉和导航 | 目标输入及完整运动执行链 |

`slam2d`、`fastlio2`、`pointlio` 可以共同安装，实际链路和定位后端由配置选择。语义地图的决策模型是独立配置项，不等同于安装 `memory` 模块。

## 编译并行与资源使用

安装器和受支持的源码更新、依赖构建入口共用一个任务预算：先读取 `--jobs`，其次是 `CARGO_BUILD_JOBS`、`CMAKE_BUILD_PARALLEL_LEVEL`，均未设置时自动探测。Go2 双端更新的 `--jobs` 只作用于开发机；`--remote-jobs` 只作用于设备，省略时两端各自探测，不把开发机核心数套到设备上。现行安装计划中显式配置的构建任务数同样优先。

自动预算取进程可用逻辑处理器数、CPU 控制组配额（不足一个核心的余量向上取整）与当前可用内存每任务 2 GiB 三者的限制，最少 1 个任务，不再设 8 或 16 核的固定上限。内存按宿主与控制组剩余额度取较小值；未知内存时使用 1 个任务。这个内存预算降低内存不足风险，但不能保证任何编译单元都不超额。显式并行数须为正整数，允许超过自动预算，需自行留意内存压力。

例如先查看自动方案，或明确使用 24 个任务：

```bash
./install.sh install --preset map3d --dry-run
./install.sh install --preset map3d --jobs 24 --yes
```

独立 CMake 和 Boost 构建使用此预算；Cargo 管理的 GTSAM、PGO 和二维原生构建通过 GNU Make jobserver 与 Rust 编译共享同一任务池，不再各自固定为 2，也不会每层再启动一整池任务。直接调用 `cargo build -j N` 时，Cargo 的任务池就是其原生子构建的预算，`CMAKE_BUILD_PARALLEL_LEVEL` 不再独立覆盖它。已有非 Unix Makefiles 的 CMake 缓存仍保留，原生子构建会明确警告并使用 Cargo 分配的 1 个任务；需要共享并行时，在新的构建目录使用 Unix Makefiles，工具不会自动清空旧缓存。

安装计划与构建日志会显示实际任务预算。可并行的源文件少、单个大型编译单元、链接或 LTO（链接时优化）、依赖下载和磁盘读写阶段仍可能只有少数核心繁忙，不能据总 CPU 使用率低就认定任务数没有生效。这里保留既有发布优化、各模块的依赖顺序、原生缓存及 Cargo 目标目录；仅改变任务数不会使已完成的原生产物重新编译。

调度实现遵循 [Cargo jobserver 契约](https://doc.rust-lang.org/cargo/reference/build-scripts.html#jobserver)；[CMake 并行环境变量](https://cmake.org/cmake/help/latest/envvar/CMAKE_BUILD_PARALLEL_LEVEL.html)在共享任务池的子构建中移除，避免它另建并发池。

## 本机按需安装

常用完整方案如下；不确定设备条件时先选基础接入：

| 方案 | 等效目标模块 | 用途 |
| --- | --- | --- |
| `--preset basic` | `core` | 标准设备接入、控制台与接口 |
| `--preset map2d` | `core,geometry,slam2d` | 二维激光建图 |
| `--preset map3d` | `core,geometry,fastlio2` | 三维激光惯性建图 |

方案不自动安装导航、视觉或本地记忆。`--preset` 与 `--modules` 互斥；两者都是完整目标，增量增加功能用 `add`。


以普通用户进入向导：

```bash
./install.sh
```

也可先查看某一方案，再执行安装。以下以三维建图和导航为例：

```bash
./install.sh install --modules core,fastlio2,navigation --dry-run
./install.sh install --modules core,fastlio2,navigation --yes
```

使用二维雷达时，在向导中选择二维模块，或以 `core,slam2d,navigation` 作为完整目标模块列表。Go2 可显式加 `--robot go2`；设备依赖默认从固定官方来源下载。

安装与后续管理：

```bash
./install.sh list
./install.sh doctor
./install.sh add perception memory
./install.sh add pointlio
./install.sh remove perception
./install.sh start
```

其中 `add pointlio` 增加PointLIO，保留已有FastLIO2；运行后端在配置中选择；`remove perception` 会连同依赖视觉的跟随模块移除。修改模块前先停止当前安装的网关。

默认安装根目录为 `runtime_data/installation/`，实际生效目录与设置路径通过 `list` 查看。安装器在独立环境中准备所选模块，校验成功后切换；失败保留上一有效安装。模块移除不会删除地图、模型和用户数据，也不会卸载系统共享依赖。模块安装不自动配置系统服务或启动机器人。

## 命令与参数速查

| 命令或参数 | 行为 |
| --- | --- |
| 无参数 / `manage` | 交互向导；无终端输入时只显示计划 |
| `install` | 安装完整目标，默认沿用已有选择 |
| `add` / `remove` | 增加或移除模块；自动处理依赖 |
| `list` | 查看当前模块、安装时间和初始配置路径 |
| `doctor` | 只读检查系统、解释器、所选设备依赖、软件包与安装产物；有阻断项返回1 |
| `start` / `stop` | 前台启动或停止当前安装的网关 |
| `--dry-run` | 只看计划，不代表前提和功能通过 |
| `--json` | 输出结构化计划/状态；`doctor --json` 包含诊断与退出状态 |
| `--yes` | 接受目标方案，省略交互确认；系统提权可能仍需输入密码 |
| `--python` / `--jobs` | 指定兼容解释器或限制编译并行数 |
| `--install-dir` | 更换专属安装目录；后续管理带上同一路径 |
| `--wheel-dir` | 提供与目标设备和解释器匹配的厂商安装包 |
| `--repair` | 按当前源码修复安装，不是回退源码 |

安装过程显示五个阶段，详细命令输出写入安装目录的 `logs/`。查看日志中的首个错误，修复后重试相同命令。首次下载和原生编译耗时取决于网络、磁盘和设备，当前不承诺固定安装时长。

## 配置与运行方式

### 模块安装

使用 `./install.sh list` 给出的初始配置位置，并用 `./install.sh start` 启动当前安装。全新安装默认监听本机；保存机器人方案后的实际配置位置见[配置说明](配置说明.md)。需要指定其他安装根目录时，各次管理命令使用一致的 `--install-dir`。

### 开发启动

手工准备依赖的开发环境可使用[配置示例](../../.env.example)和[网关启动器](../../scripts/start_gateway.sh)。第一次创建配置、确认根目录尚无 `.env` 时执行：

```bash
cp -n .env.example .env
```

按真实设备修改配置后启动：

```bash
bash scripts/start_gateway.sh
```

`NUWAX_BOOTSTRAP_ENV_FILE` 可指定基础配置文件，`NUWAX_USER_CONFIG_ENV_FILE` 可指定统一用户覆盖文件。设置页显示实际来源、保存位置与生效范围，按页面提示应用变更。

### 机器人配置方案

控制台支持为每种机器人选择、另存和应用多份方案，私有配置保存在对应机器人配置目录。方案、凭据、地图与模型均不属于公开源码。

`NUWAX_GEOMETRY_PIPELINE` 选择整条建图、探索和导航链：`slam_2d` 为二维，`lio_3d` 为三维。三维导航另需实测机体外形与支撑距离。选择合法链路后，页面会继续检查程序、输入及标定是否齐备。

## 更新已有安装

受管模块安装通过统一网关更新入口更新。命令行与控制台“设置 → 软件更新”调用同一个运行中的网关接口，前置条件、运行模式与恢复规则见[升级与恢复](升级与恢复.md)。

在已启动网关的安装主机上执行；更新前先完成或取消正在运行的任务，并确认设备可以安全停机：

```bash
# 查看参数
./install.sh update --help

# 检查当前分支的上游更新
./install.sh update check

# 确认更新并等待后台事务结果
./install.sh update install --yes --wait

# 查看更新状态
./install.sh update status
```

默认连接本机 `http://127.0.0.1:8766`；可用 `--url` 指定已运行网关的地址。更新沿用受管安装的模块、机器人适配器、安装目录与运行模式，客户端退出或等待超时不会取消已受理的更新。

### 从开发机更新Go2源码部署

已有Go2源码与系统服务部署使用[Go2更新入口](../../scripts/update_go2.py)，在开发机仓库执行：

```bash
python3 scripts/update_go2.py plan
python3 scripts/update_go2.py build
python3 scripts/update_go2.py deploy
python3 scripts/update_go2.py verify
```

默认固定当前分支的远端提交；包含本机未提交修改时加`--source workspace`，固定本机已提交版本用`--source head`。`--jobs`和`--remote-jobs`分别控制两端构建。四个子命令都会连接设备，`plan`写入本次辅助脚本和计划，`build`包含远端准备与构建；只读参数说明用`--help`。

部署沿原系统服务入口执行，保留设备配置与业务数据。安装前检查目标漂移和载荷，安装后核对落盘文件/权限及服务状态，失败尝试恢复旧内容和服务。未激活的按需组件如实报告，成功结果不表示已完成机器人现场运动验收。

## 系统服务与生产档案

系统服务模板位于 [deploy/systemd](../../deploy/systemd)。主要组件包括网关、几何运行时、导航、人物跟随、运动守卫和按需激活服务；Go2 另有设备数据与视频组件。服务之间存在配置和启动依赖，应使用对应部署流程安装整组模板。

设备端源码安装、本机模块安装和上述Go2更新是现行入口。旧档案部署器、旧产品打包发布器和旧配置bootstrap已退役。`go2-jetson`档案仍供原生几何打包与运行诊断读取服务/角色，不是额外的一键安装入口。

## 验证与排障

网关运行后，先检查接口与控制台：

```bash
curl -fsS http://127.0.0.1:8766/api/health
curl -fsS http://127.0.0.1:8766/api/health/full
curl -fsS http://127.0.0.1:8766/api/agent/tools
```

打开 [控制台](http://127.0.0.1:8766/console)，按“数据到达 → 功能就绪 → 任务结果”的顺序核对。

| 现象 | 优先检查 |
| --- | --- |
| 网关正常但没有地图 | 当前链路、有效雷达/惯性或里程计、外参、几何程序与日志 |
| 地图能显示但导航不可用 | 当前地图定位、支撑与净空、机体参数、运动守卫及真实执行器 |
| 视频正常但没有识别 | 模型路径、后端、类别范围、推理环境与感知阶段错误 |
| 记忆没有物体坐标 | 当前记忆库、相机标定、几何证据，是否只是观察位置 |
| 设置保存后未生效 | 当前机器人方案、实际来源、重启范围及运行值确认 |
| 更新失败 | 本次计划与构建日志、源码漂移、目标依赖和安装回执 |

控制台日志可按来源、级别、请求与任务筛选并导出。默认日志目录为 `runtime_data/logs/`，由 `NUWAX_LOG_DIR` 调整。

宿主机网关当前不提供用户登录或令牌身份认证；能力公开标记用于控制工具暴露。远程访问应放在受控网络中，或通过现有远程连接与访问代理提供边界。连接中的 `127.0.0.1` 始终指调用者自身；容器访问宿主机时须使用容器可达的宿主机地址。

本机源码升级、模块失败恢复与数据迁移见[升级与恢复](升级与恢复.md)，按现象定位问题见[常见问题与排障](常见问题与排障.md)。
