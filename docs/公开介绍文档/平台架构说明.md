# 平台架构说明

## 1. 项目定位

`nuwax_robot_bridge` 是部署在机器人宿主机上的具身能力运行时。

它不负责上层对话和会话，而是负责：

1. 连接机器人和底层 SDK。
2. 采集状态、图像、地图和位姿。
3. 执行运动、导航、感知、记忆和音频等能力。
4. 通过统一接口把这些能力暴露给上层系统。

当前默认支持机器人为 Go2（Unitree Go2），G1（Unitree G1）入口骨架已定义但尚未实现。

## 2. 分层结构

整体结构可以理解为五层：

1. 机器人连接层
   负责机器人 SDK、传感器和硬件能力接入，通过 `drivers/<robot_name>/`、`drivers/common/`、`drivers/sensor/` 和 `adapters/` 实现。
2. 平台运行时层
   负责任务、事件、状态、安全和能力编排，通过 core/ 实现。
3. 能力服务层
   负责感知、地图、定位、导航、记忆、音频等正式能力，通过 services/ 实现。
4. 提供者接口层
   定义机器人装配与服务层之间的标准边界，通过 providers/ 实现。
5. 对外网关层
   负责通过 `MCP + HTTP + 事件流 + 制品下载` 对外暴露能力，通过 gateways/ 实现。

## 3. 核心模块职责

### 3.1 机器人连接层（drivers/）

```

services/
└── geometry/
```

## 4. 平台输入输出总览

### 4.1 平台输入（从机器人/硬件获取）

平台从机器人获取的既包括原始传感器数据，也包括 Go2 官方 DDS 提供的位姿与点云，以及平台几何侧车提供的地图和服务状态。

| 输入类别 | 具体数据 | 获取接口 | 说明 |
|---------|---------|---------|------|
| 图像数据 | 前置相机图像帧 | `ImageProvider.capture_image()` | Go2 通过 VideoClient 获取 |
| 相机参数 | 焦距、分辨率、畸变系数 | `ImageProvider.get_camera_info()` | 相机内参 |
| 机器人状态 | 关节角度、角速度、温度等 | `StateProvider.get_robot_state()` | 整机状态快照 |
| 关节状态 | 各关节位置/速度/力矩 | `StateProvider.get_joint_states()` | 列表形式返回 |
| IMU 数据 | 加速度、角速度 | `StateProvider.get_imu_state()` | 机身惯性测量单元原始数据 |
| 点云数据 | 3D 点云帧 | `PointCloudProvider.get_latest_point_cloud()` | 深度传感器原始数据 |
| 位姿与里程计 | 官方 DDS 位姿数据 | `LocalizationProvider` 内部消费 | 用于平台定位与导航运行时 |
| 平台地图话题 | `/map` / `grid_map` / `cost_map` | `MapProvider` 内部消费 | 默认来自平台几何侧车；缺失时由平台运行时基于 Go2 DDS 点云补图 |
| 安全状态 | 碰撞、异常标志 | `SafetyProvider.get_safety_state()` | 安全守卫状态 |

### 4.2 平台内部构建产物（不属于外部输入）

以下数据主要是平台运行时整理、融合或补算后的产物：

| 构建产物 | 构建方式 | 构建组件 |
|---------|---------|---------|
| 位姿数据（map frame） | 消费官方 DDS 位姿后再统一到平台契约 | `LocalizationProvider` |
| TF 坐标树 | 按当前运行态维护 | Go2 数据面运行时 |
| 占据栅格地图 | 由平台 geometry 工作空间或 Go2 宿主机 DDS 点云建图结果提供，统一映射到平台地图契约，不涉及 Go2 机器人侧 ROS2 资产 | `Go2SparseGlobalMapBuilder` |
| 代价地图 | 由平台 geometry 工作空间或 Go2 宿主机 DDS 点云代价图结果提供，统一映射到平台地图契约，不涉及 Go2 机器人侧 ROS2 资产 | `Go2CostMapper` |
| 语义地图 | 点云 + 视觉语义融合 | `services/memory/semantic_map_builder.py` |
| 导航状态 | Go2 官方执行链状态或平台运行态状态 | `NavigationProvider.get_navigation_state()` |
| 探索状态 | 前沿探索器状态 | `ExplorationProvider.get_exploration_state()` |

### 4.3 平台输出（对上层系统）

| 输出类别 | 具体数据 | 暴露接口 | 说明 |
|---------|---------|---------|------|
| 能力清单 | 已注册能力列表 | `GET /api/capabilities` | 平台能力查询 |
| 工具调用 | MCP 工具执行 | `POST /mcp` | JSON-RPC 格式的主入口 |
| 任务管理 | 任务状态/进度 | `GET /api/tasks/{id}` | 异步任务追踪 |
| 健康状态 | 运行时健康摘要 | `GET /api/health` | 机器人型号、启动时间等 |
| 事件流 | 实时事件订阅 | `GET /events/stream` | SSE 格式的任务/系统事件 |
| WebSocket 事件 | 实时事件推送 | `WS /events/ws` | WebSocket 双向通道 |
| 制品下载 | 图像/视频/文件 | `GET /artifacts/{id}` | 图片、日志、快照等大对象 |
| 调试页面 | HTML 运维页面 | `GET /` | 快速查看运行时状态 |
| 安全策略 | 访问控制策略 | `GET /api/security/policy` | 允许网段、令牌等 |
| 运行时视图 | 能力矩阵、状态快照 | `GET /api/runtime/views` | 平台运行时快照 |

## 6. 典型调用链路

一个典型调用的流向如下：

1. 容器内上层系统发起工具调用。
2. 宿主机网关收到请求，通过 capability_registry 路由到具体能力。
3. 能力服务通过 providers 调用机器人入口或适配器执行实际动作或采集数据。
4. 任务管理器（TaskManager）负责任务生命周期管理，支持进度更新、取消和超时。
5. 结果通过标准契约返回给网关。
6. 网关再把结构化结果返回给上层系统。

如果结果中包含图片、日志、快照等大对象，则通过制品通道（artifacts）提供下载地址。

## 7. 当前核心能力

当前已具备下面这些能力模块：

1. 机器人状态与安全状态采集。
2. 图像采集与观察记录。
3. 本地视觉检测与云端语义识别。
4. 关键帧驱动的视频感知运行时与到点 burst 复核。
5. 地图、定位、导航与探索。
6. 语义空间记忆闭环：命名地点、对象实例、观察事件、向量检索、巡检位姿规划与到点复核。
7. 任务管理、事件流和制品管理。
8. TTS 文本播报。

## 8. 视觉与记忆链路

当前视觉链路采用"双识别"结构：

1. 本地识别默认优先使用 `YOLO26n + TensorRT`，负责稳定、实时的目标检测。
2. 云端识别负责开放词表语义、关系描述和细粒度补充。
3. 平台默认不是"每帧全量重检测"，而是"关键帧驱动 + 到点 burst 复核"。
4. 两者合并后写入统一感知结果。
5. 感知结果不会把整张 SLAM 地图写入向量库，而是先投影到 `map frame`，再生成对象实例和观察事件。
6. 记忆库当前按 `place_nodes / object_instances / episodic_observations` 三类集合组织。
7. 导航层消费 inspection pose，而不是直接消费对象中心点。

当前记忆向量链路默认配置如下：

1. 平台启动时默认不会自动启用记忆库。
2. 上层系统需要先通过 `MCP` 工具显式选择并启用命名记忆库。
3. 记忆库启用后，文本向量默认使用 `BAAI/bge-m3`，图像向量默认使用 `openai/clip-vit-base-patch32`。
4. 如果宿主机没有配置在线向量模型，运行时会使用轻量模式（hashing 文本向量），并把原因写入日志。

当前记忆侧的三层对象职责是：

1. `ObservationEvent`
   表示一次带空间锚定的原始观察事实。
2. `SemanticInstance`
   表示跨帧关联后的持续对象实体。
3. `SemanticMemoryEntry`
   表示面向上层消费的摘要条目。

## 9. 扩展原则

平台的扩展方式固定如下：

1. 新机器人通过 `drivers/<robot>` 接入，需实现 RobotAssemblyBase 并提供 manifest。
2. 新传感器和新地图来源通过 `adapters/` 或 `providers/` 接入。
3. 新视觉模型通过统一检测器后端接口接入。
4. 上层工具接口尽量不因底层模型或硬件变化而改变。

## 10. 对外接口

平台当前对外主要暴露四类接口：

1. `MCP`
   工具调用主入口。
2. `HTTP`
   调试、状态查询和补充调用入口。
3. `SSE/WebSocket`
