# YOLO 分割检测归一化：去除新对象的深复制

## 改动

`services/perception/detectors.py::_normalize_yolo_result` 将刚生成的分割契约直接交给已有的 `normalize_detection_2d` 构造入口，不再先创建检测，再深复制整个检测及两份多边形属性来补充分割字段。没有新增缓存、哈希、后台任务或锁。

原始模型的多边形先经 `tolist` 和有限数值筛选构成新列表；结构化分割持有独立的坐标元组。输出仍不修改模型数组，不把两个检测的可变多边形属性共享。词表增强、通用外部检测归一化和其他拥有方边界的复制未调整。

## 离线测量

环境：Python 3.8.10、Pydantic 2.10.6、NumPy 1.24.4、OpenCV 4.10.0，Linux x86_64。测量日期：2026-10-13。

夹具使用正常导入的 `YoloWorldDetectorBackend` 及生产辅助函数，只将归一化方法分别绑定为改动前与候选源码；不加载模型。输入为 640×480 BGR8 图像契约、分数 0.8、类别 0、框 `[70,70,130,130]`，分割为中心 `(100,100)`、半径 30 的等角多边形。每个场景在一个进程内交替执行旧/新实现共 5 对，每个计时块连续调用 3 次；表中为每块单次平均耗时的中位数。不是 5 个独立进程。计时前进行 GC；内存另用单次 `tracemalloc` 测量，不纳入计时。

| 检测数量 | 每个多边形点数 | 原实现 ms | 新实现 ms | 原 Python 峰值字节 | 新 Python 峰值字节 |
| --- | --- | --- | --- | --- | --- |
| 1 | 4 | 0.226 | 0.138 | 24,494 | 16,806 |
| 20 | 128 | 14.587 | 6.011 | 1,192,776 | 1,067,080 |
| 64 | 512 | 281.206 | 153.505 | 13,252,424 | 12,047,712 |
| 64 | 无分割 | 1.388 | 1.387 | 188,600 | 188,728 |

20×128 和 64×512 分割场景的归一化耗时分别下降约 59% 和 45%；无分割对照基本不变。数值只表示这段 Python 输出归一化，不包含图像解码、模型推理、词表增强、跟踪或完整管线；不能解释为相机帧率或 GPU 提升。`tracemalloc` 不是进程 RSS，也不衡量 GPU 内存。

## 正确性与回归

同一夹具的改动前后完整契约输出逐项一致，仅排除每次构造自动生成的时间戳。检查了输入数组未被修改、一个检测的属性修改不影响另一检测、两份多边形属性互不影响，以及结构化分割坐标不与可变属性共享。新回归还禁止新建检测后再调用 `model_copy`，保留原来的中心点别名关系。
