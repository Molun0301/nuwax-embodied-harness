- 批量 token 改动的处置不同：它已按正确性与确定性 SQL 工作减少保留，但性能资格仍未通过，不能归入“测得提速”

## 当前优先级调整（2026年10月7日）

用户将机身高度变化、运行坐标抖动、建图漂移以及重定位、地面、支撑和净空误判归为独立的3D链路专项，暂时搁置。用户报告此前实机重定位很准确，并认为门槛应结合实际波动制定，不能因过严判定令功能不可用；这些反馈是后续专项输入，不代表专项问题已经解决。

此处重定位验收门槛单独按用户决定从2 cm改为5 cm，其他判定与限制不变，尚未在新门槛下重跑完整组合。以下计划中涉及该专项的闭环、定位精度、抖动漂移与支撑／净空判定策略调整暂停；当前优先继续跨模块性能、并发解耦、重复计算、复制、锁竞争和阻塞问题。原始失败与诊断记录保留。

## 后续分阶段计划

以下按风险与依赖排序。每阶段单独完成生产调用链审查、最小改动、验证和普通 Git 发布；硬件阶段受阻时，可先推进后续不依赖硬件的小范围工作。

1. **补齐生产运动闭环与真实负载基线。** 在允许既有所需 socket／组播、具备设备接入的环境运行已准备的 OFF／ON、观察过期归零及真实回执检查，再补持续障碍自动恢复。预期得到可定位的端到端故障与时延分布，验收输出必须对应同一源码、release配置、真实源时间和执行器回执；不更换传输冒充通过，不放宽障碍、TTL或50／75 ms门槛
2. **定义 quick 工作上限，再处理变化几何。** 先明确零预算的对外语义及有效路线接续，再评估可中断的有界搜索；真正增量 PCT 必须建立稳定 delta 谱系、删除／重置规则和动态距离依赖。预期减少已过时工作及新图全量构建；用完整冷构造、路径位模式和变化障碍对照验收，不能用固定 halo 近似或直线替代完整路线
3. **优先削减记忆召回的全量重建。** 5000条合成记录的串行查询中位数约1.058 s，为返回3项重建了约5066个源模型和5064个缓存点。先厘清当前源数据校验、投影版本绑定与分阶段模型构建成本；只有能保持源校验、词法／live-only路径、错误行为与最终复核，才试验减少完整模型还原。紧凑投影仍是设计问题，不是已证明可行的替换方案。目标是降低 JSON／模型重建工作；时延结论需先通过 A/A，再做固定配对测量。读连接并发改造另作一阶段，不能直接删除共享 SQLite 锁
4. **继续梳理输入、建图与跨模块重复工作。** 测量 NavigationMap3D 准入后再次校验的占比，核对内部可信入口；为 raw／通用输入建立真实 producer 身份契约后，才考虑去除其内容 fingerprint。预期减少重复解析和点扫描；依赖冲突、重放、重启、换源与旧接口对照，保留不可信入口的完整验证
5. **深化感知、语义与前端分工。** 分开测量模型计算、完整 payload／共享内存序列化、同步订阅回调、前端资源更新及 GPU帧耗时；再选择占比最高的一段改动。预期减少锁内工作、无用完整快照和重复绘制；需覆盖慢订阅者、重入、重连、页面恢复及制品释放。BFCache、真实后端联动与视频端到端延迟单独补验
6. **补齐任务持久化与安装构建验收。** 显式任务回收先与持久回执、消费者生命周期协调；缓存保留后做真实首次／二次构建、选项变化及回退比较。预期让回收安全可解释、更新确实复用产物；增量编译收益要由编译记录证明，缓存容量治理不能误删当前／回退代际
7. **完成通用接入与公开交付矩阵。** 逐项核对设备适配、坐标／时间／标定、停止执行、模块依赖与启动关闭；用标准接口隔离 Go2私有能力。预期让新设备接入边界清楚且可复现；每种机型分别验收，发布文档明确已实现、未验证和待开发，并为当前工作分支补上合适的 CI 触发与汇总入口

## 完成条件与范围

- 正确性：路径、地形、净空、障碍、取消、拥有方、源时间与回执权限按既有契约通过；任何有意行为变化单独说明
- 性能：同一配置与输入先验证 A/A稳定性，再按预先确定的进程数比较 A/B；报告冷／热、P95／最大值、阶段墙钟及整进程 CPU／RSS，不混用或隐藏失败
- 解耦：避免没有证据收益的新校验、锁、复制与内容 hash；必要的安全校验和事务一致性不能为提速删除
- 发布：每阶段核对最终源码、测试范围、提交和远端 SHA；复用仍有效的证据与构建缓存，不为汇总重复执行大批测试，不用历史通过代替当前受影响链路验收
