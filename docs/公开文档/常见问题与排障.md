# 常见问题与排障

适用于 Nuwax Embodied Harness（NEH，具身运行框架）。先确定问题发生在安装、启动、设备接入还是任务执行阶段，保留第一次失败的原因。

## 安装与更新

| 现象 | 原因与处理 |
| --- | --- |
| 仓库不存在或无法下载 | 核对仓库 `Molun0301/nuwax-embodied-harness`、分支与网络；公开源码可匿名下载 |
| 提示不能使用管理员账号 | 回到普通用户终端执行；需要系统权限时安装入口会单独请求密码 |
| 下载超时、证书或软件源错误 | 查看任务详细日志中实际失败的来源，修复网络、代理或系统证书后重试；不要关闭证书验证 |
| 系统依赖安装失败，并列出“包列表刷新失败的源” | 失效的软件源本身不会中止安装，只有缺少的包确实装不上才失败；修复或停用列出的源后重试 |
| 编译被系统结束 | 多为内存不足；检查可用内存和磁盘，保留日志中的真实编译错误 |
| Jetson（嵌入式计算平台）张量库不可用 | 准备与厂商软件栈匹配的 `torch/torchvision`（张量与视觉库），不要覆盖为普通电脑的构建 |
| 已有安装任务正在执行 | 等它结束或在管理页取消；不要删除锁文件抢占 |
| 显示“当前版本领先”或“版本已分叉” | 后台不会自动安装更旧或分叉的提交；确认要切换时手动执行 `neh update`，会安装通道当前提交 |
| 显示“云端编译中” | 开发分支的云端预编译尚未发布，每 15 分钟重查；立即编译用 `neh update --local-build` |
| 同一失败版本没有自动重试 | 后台更新跳过失败过的版本；查看失败原因并处理后手动 `neh update` |
| 更新一直等待设备空闲 | 先完成或取消任务、保存地图或结束地图会话、停止运动，并核对维护时间窗 |
| 旧管理程序无法更新到新版本 | 按[安装与更新](安装与更新.md#较旧的管理程序)对原安装目录重跑一次引导器 |

管理页“任务”中每个任务都有步骤记录和“详细日志”（与终端输出一致，密码和令牌等已隐藏），失败时直接显示提取出的原因；命令行用 `neh jobs`、`neh job 任务标识 --wait`。中断后重试会复用已有缓存。

## 网页打不开

管理页使用安装输出的实际地址（默认端口从 8765 开始）；业务网关在 8766，只监听设备本机。从其它电脑打开控制台请用 `http://设备地址:管理端口/console`。

在设备上检查（修改过端口时替换 8766）：

```bash
neh status
curl -fsS http://127.0.0.1:8766/api/health
ss -ltn 'sport = :8766'
```

连接被拒绝时，先确认业务已启动（`neh start --wait`）。从另一台电脑打不开管理页时，检查设备地址、防火墙与网络边界；调用者的 `127.0.0.1` 永远指调用者自己。远程访问方法见[安全与数据说明](安全与数据说明.md)。

## 业务启动失败

`neh start --wait` 或管理页返回的原因会列出已退出的组件及其日志末尾。组件日志在 `安装根/data/logs/组件名.log`（如 `gateway.log`、`geometry.log`），监督者输出在 `安装根/logs/runtime.log`。常见原因：配置中的值与已装模块不一致（例如选了 `pointlio` 却没装该模块）、设备地址不可达、端口被占用。

## 网关响应但没有数据

```bash
curl -fsS http://127.0.0.1:8766/api/health
python3 clients/robot_client.py --url http://127.0.0.1:8766 info
```

基础安装不会生成设备数据。`customrobot`（通用接入）需要接入方发布标准输入，并且发布到网关实际使用的同一个装配。有状态没有视频，检查相机来源；有视频没有地图，检查是否已开始建图或加载地图，以及雷达、惯性或里程计输入、时间与标定。

## 地图、导航与识别

| 现象 | 核对顺序 |
| --- | --- |
| 开始建图失败 | 所选定位前端的模块与程序 → 传感器连续输入 → 时间与坐标 → 外参 → 返回的错误 |
| 建图中途会话进入故障 | 状态中的故障原因；常见为传感器断流、定位前端退出、原始扫描暂存写满。再次开始建图或加载地图即重建 |
| 加载地图后不能导航 | 重定位是否成功（失败时状态里有原因，可移动机器人后调用 `relocalize_active_map` 重试）→ 目标落点 → 机体参数 → 运动执行端 |
| 加载的地图提示“只能查看” | 这是缺少完整二维定位图的二维故障保存图，不能重定位或续建 |
| 想用另一个名字保存 | 保存时直接给新名字；新名字已有地图会被拒绝。在已保存地图上续建后另存，原地图不变 |
| 导航停在“等待导航输入” | 消息写明缺失项（定位、占据栅格、位姿、导航栈输入等），输入就绪后自动继续 |
| 有路径但不移动 | 任务阶段、运动守卫状态（健康接口 `motion_guard`）、执行端与急停状态 |
| 运动守卫连接失败 | 守卫在第一次运动时按需启动；查看 `motion_guard.log`。Go2 需 `unitree_sdk2py`（安装器自动准备）与正确的 DDS（数据分发服务）网卡；通用设备需配置 `motion_guard.backend` 与 `motion_guard.control_factory` |
| 写了禁行区后地图或导航异常 | 查看几何运行时日志与导航任务消息中的禁行区读取原因 |
| 取消后机器人还在动 | 查询原任务与运动守卫状态；网页断开不等于停止，需要时调用 `stop_all_motion` |
| 视频没有检测结果 | 识别是否开启、模型路径、类别、后端与推理错误 |
| 物品没有空间坐标 | 相机内外参、深度或点云几何证据、记忆库是否为当前地图；“仅观察”不等于坐标丢失 |
| 找目标没有前往 | 返回结果中的候选与原因：没有候选、多个候选需要澄清、候选没有当前地图上的位置 |
| 语义区域名字不准 | 查看观察证据与候选状态，人工修改或补充观察；当前为实验能力 |

不要通过随意放宽时效、净空、停止或输入检查来消除报错，先确认设备与环境符合功能要求。

## 设置保存了却没变化

按[配置说明](配置说明.md)核对：保存的是不是当前方案、该项是否需要重启业务、`安装根/run/config.toml` 中的实际值。程序路径与模块由安装决定，添加功能需要安装对应模块。

## 提交问题时提供什么

在仓库[问题列表](https://github.com/Molun0301/nuwax-embodied-harness/issues)使用模板，提供：

1. 源码提交、分支、系统架构、安装方式（一行安装或源码模块安装）。
2. 完整操作步骤、期望结果与实际结果。
3. 首条错误、发生时间、任务标识和相关组件日志片段。
4. 是否在实机上发生，设备与传感器型号，能否用合成或脱敏记录复现。

不要附上配置方案文件中的密钥、私有场地地图、含人脸的视频或整个运行目录；先给能定位问题的最小脱敏片段。
