# 局部路径展示投影审计（2026-10-13，暂不修改生产实现）

`RouteFollower::local_path_for_display()` 会将当前 `Path3D` 投影为 `Vec<[f64; 3]>`。`PlannerWorker` 在每次命令发布时取该展示向量，并在状态读取时持现有输入锁克隆它。候选方案是在安装局部路径时生成不可变投影，通过 `Arc<Vec<_>>` 交接；持锁时只复制共享引用，原来的公开 Vec 返回值在解锁后复制。

## 初步操作模型

云环境在 Runtime 基线编译期间被替换，原构建未完成，无法保存或运行其测试二进制。恢复 Rust 1.88.0 后，仅用独立 `rustc -O --edition=2021` 操作模型比较上述两种所有权方式，**没有实施生产缓存修改**。

模型包括具有位置、时间戳、四元数、坐标系字段的合成 pose 数组；基线每轮投影全部位置，候选每轮复制预建的 `Option<Arc<Vec<[f64; 3]>>>`。另测量现有 Vec 状态返回，以及单独的 Mutex 快照捕获。每组 200,000 次，五对新进程按 AB/BA 交替；构造在计时外，结果经过 `black_box` 与相等断言。运行时已协调暂停其他工作线程的性能探针和编译。

| 操作 | 点数 | 基线 | 候选 |

| 展示投影/共享引用 | 256 | 150.37 | 3.99 |
| 展示投影/共享引用 | 2,048 | 2,086.11 | 3.95 |
| 原 Vec 状态返回 | 32 | 17.02 | 22.88 |
| 原 Vec 状态返回 | 256 | 82.98 | 84.43 |

快照捕获包含上锁、复制、解锁和丢弃结果的总操作耗时，并非直接测得的锁占用时间或竞争等待长尾。原 Vec 状态返回仍需复制全部坐标；小向量会增加引用计数开销。空路径也包含在原始日志中，没有发现需要引入空投影分配的理由。

## 决定和边界

暂不采用此缓存：小路径的绝对收益只有数十至数百纳秒，2,048 点投影约节省 2 微秒，尚不足以证明值得增加缓存字段、公开 trait 方法和失效维护；32 点状态返回在本模型中反而略慢。现有生产文件、公开 Vec API、版本/消息合同、命令首次交付与最新位姿复核、原期限及取消栅栏均未改变。

这是决定“暂缓实现”的操作级探索，**不是生产 Runtime 基线对照、20 Hz 延迟、实机 CPU 或安全资格验收**。未运行此前准备的 Runtime 诊断或新增回归，也不宣称它们通过。后续只有真实剖析显示该路径占据显著成本，或长路径持锁造成可测竞争时，才值得重新评估；优先调查毫秒级重复查询或大对象处理。
