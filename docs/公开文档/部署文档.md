# 部署与运行边界

NEH（具身运行框架）的普通安装、更新、通道设置、回退和卸载统一见[安装与更新](安装与更新.md)。管理页准备软件版本，业务控制台提供设备、地图和任务操作。

## 选择使用入口

| 场景 | 文档入口 |
| --- | --- |
| 在设备安装和日常更新 | [安装与更新](安装与更新.md) |
| 准备系统、传感器和标定 | [安装前准备](安装前准备.md) |
| 从源码开发、修改模块或维护已有源码安装 | [源码开发安装](开发工具使用指南.md#源码开发安装)与[源码更新恢复](开发工具使用指南.md#源码更新与恢复) |
| 开发机向已有 Go2（宇树四足机器人）源码部署推送 | [从开发机更新 Go2](开发工具使用指南.md#从开发机更新go2源码部署) |
| 绑定自己的设备与运动执行器 | [架构与机器人接入](架构与机器人接入.md) |

安装成功后，使用[配置说明](配置说明.md)确认机器人方案、真实输入、程序和监听地址，再启动所选业务。全新配置默认监听本机；修改过地址或已有配置时，以实际运行值为准。

## 系统服务与生产档案

系统服务模板位于 [deploy/systemd](../../deploy/systemd)。主要组件包括网关、几何运行时、导航、人物跟随、运动守卫和按需激活服务；Go2 另有设备数据与视频组件。服务之间存在配置和启动依赖，应使用对应部署流程安装整组模板。

设备端源码安装、本机模块安装和上述Go2更新是现行入口。旧档案部署器、旧产品打包发布器和旧配置bootstrap已退役。`go2-jetson`档案仍供原生几何打包与运行诊断读取服务/角色，不是额外的一键安装入口。

## 验证与排障

网关运行后，先检查接口与控制台：

```bash
curl -fsS http://127.0.0.1:8766/api/health
curl -fsS http://127.0.0.1:8766/api/health/full
curl -fsS http://127.0.0.1:8766/api/agent/tools
```

打开 [控制台](http://127.0.0.1:8766/console)，按“数据到达 → 功能就绪 → 任务结果”的顺序核对。

| 现象 | 优先检查 |
| --- | --- |
| 网关正常但没有地图 | 当前链路、有效雷达/惯性或里程计、外参、几何程序与日志 |
| 地图能显示但导航不可用 | 当前地图定位、支撑与净空、机体参数、运动守卫及真实执行器 |
| 视频正常但没有识别 | 模型路径、后端、类别范围、推理环境与感知阶段错误 |
| 记忆没有物体坐标 | 当前记忆库、相机标定、几何证据，是否只是观察位置 |
| 设置保存后未生效 | 当前机器人方案、实际来源、重启范围及运行值确认 |
| 更新失败 | 本次计划与构建日志、源码漂移、目标依赖和安装回执 |

控制台日志可按来源、级别、请求与任务筛选并导出。默认日志目录为 `runtime_data/logs/`，由 `NUWAX_LOG_DIR` 调整。

宿主机网关当前不提供用户登录或令牌身份认证；能力公开标记用于控制工具暴露。远程访问应放在受控网络中，或通过现有远程连接与访问代理提供边界。连接中的 `127.0.0.1` 始终指调用者自身；容器访问宿主机时须使用容器可达的宿主机地址。

本机源码升级、模块失败恢复与数据迁移见[安装与更新](安装与更新.md)，按现象定位问题见[常见问题与排障](常见问题与排障.md)。
