# 常见问题与排障

适用于 Nuwax Embodied Harness（NEH，具身运行框架）。先区分发生在下载源码、安装、启动、设备接入还是任务执行阶段，保留第一次失败的原因。

## 安装入口问题

| 现象 | 原因与处理 |
| --- | --- |
| 仓库不存在或无权访问 | 当前仓库私有，确认账号拥有权限；新地址为 `Molun0301/nuwax-embodied-harness` |
| 找不到 `install.sh` | 进入源码根目录；当前开发版要选择 `refactor/map-explore-nav` 分支 |
| `Permission denied`（权限不足） | 源码压缩包可能未保留执行位，尝试 `bash install.sh`；不要因此改用管理员运行整个安装器 |
| 不支持 Python（编程语言）版本 | 安装3.8—3.12解释器，用 `--python /实际路径/python3` 指定；启动安装器自身也需至少3.8 |
| 提示不能使用管理员账号 | 返回普通用户终端运行；安装系统包时脚本单独请求管理员权限 |
| 非交互环境只显示计划 | 自动化执行使用 `install --modules ... --yes`，明确完整模块选择 |
| Go2 厂商依赖缺失 | 按设备软件环境准备 `unitree_sdk2py`、`cyclonedds` 安装包，用 `--wheel-dir` 指定；核对架构和解释器 |
| Jetson（嵌入式计算平台）张量库不可用 | 准备匹配厂商软件栈的 `torch/torchvision`（张量与视觉库），不要直接覆盖为普通电脑构建 |
| 下载超时、证书或软件源错误 | 查看日志中实际失败的来源，修复网络、代理或系统证书后重跑；不要关闭证书验证 |
| 编译被系统结束 | 检查可用内存、磁盘和系统记录，先减少为 `--jobs 1`；保留日志中的真实编译错误 |
| 已有网关占用或其它安装正在执行 | 沿原管理入口停止网关，等待正在执行的安装结束，不删除锁文件抢占 |
| `current` 状态损坏 | 先保留现有状态并检查实际链接和清单；不要凭空创建成功清单，必要时换独立安装目录重新安装 |

安装日志位于 `runtime_data/installation/logs/`；自定义安装目录时对应为该目录下的 `logs/`。进程每隔一段时间提示仍在处理，并给出详细日志路径。中断后重试会复用可用缓存，不表示逐条断点续传。

## 网页打不开

在网关所在主机的另一个终端执行；修改过端口时替换8766：

```bash
curl -fsS http://127.0.0.1:8766/api/health
ss -ltn 'sport = :8766'
```

连接被拒绝时，查看启动终端是否已经退出、地址端口是否正确。端口被其它服务占用时，配置自己的空闲端口，配套修改制品访问地址和客户端地址，不直接结束不明进程。

本机可访问、另一台电脑不可访问时，先检查监听地址、连接方式及网络边界。新模块安装默认只监听本机，可使用[远程连接方法](安全与数据说明.md)。调用者的 `127.0.0.1` 永远指调用者自己。

## 网关响应但没有数据

```bash
curl -fsS http://127.0.0.1:8766/api/health/full
python3 clients/robot_client.py --url http://127.0.0.1:8766 info
```

基础网关安装不会生成设备数据。`customrobot`（通用机器人）需要开发者发布标准输入；确认发布给网关实际使用的同一个装配，不能在另一个独立进程中创建内存对象就期待数据自动出现。

有状态但没有视频，检查相机来源与真实帧；有视频但没有地图，检查雷达、惯性或里程计、时间与标定。地图有画面却不更新时，检查当前建图状态和数据源时间，区分静态地图资产与实时采集。

基础安装的某些可选界面查询可能返回 `403`（禁止访问），并明确说明“能力未向智能体暴露”。这与账号登录无关，应对照 `/api/agent/tools` 的实际目录及当前能力配置确认支持范围；不要仅为消除日志就开放全部工具。

## 地图、导航与识别问题

| 现象 | 核对顺序 |
| --- | --- |
| 建图启动失败 | 模块程序 → 传感器连续输入 → 时间坐标 → 标定 → 后端错误 |
| 激活地图后不能导航 | 激活结果 → 定位/重定位 → 目标落点 → 机体支撑和净空 → 执行器 |
| 有路径但等待或不移动 | 任务阶段、规划耗时、局部可行性、速度许可与守卫反馈；保留实际等待原因 |
| 导航准备或计算很慢 | 保留地图规模、原始请求、版本和阶段耗时；当前复杂三维场景仍有长尾限制 |
| 取消后仍显示收尾 | 查询原任务与真实停止反馈；网页断开不等于停止 |
| 视频没有检测结果 | 感知是否启用、模型路径、类别范围、后端和推理错误 |
| 物品没有空间坐标 | 相机内外参、有效几何证据和地图绑定；“仅观察”不等于坐标丢失 |
| 语义区域名字不准确 | 查看观察证据与候选状态，人工修订或补充观测；当前为实验能力 |

不要通过随意放宽时效、净空、停止或输入检查消除报错。先确认设备接入与真实环境符合功能要求。

## 设置保存了却没变化

按[配置说明](配置说明.md)检查机器人方案、保存目标、显式进程环境覆盖和待重启范围。安装器管理的程序路径、未安装模块开关还受安装选择限制；添加功能需要真实安装对应模块。

## 提交问题时提供什么

使用仓库[问题列表](https://github.com/Molun0301/nuwax-embodied-harness/issues)中的模板，提供：

1. 源码提交、分支、系统架构、Python版本，以及模块安装或系统服务的安装方式。
2. 完整操作步骤、期望结果与实际结果。
3. 首条错误、发生时间、任务标识和相关阶段日志。
4. 是否在实机上发生，设备与传感器型号，能否用合成或脱敏记录复现。

不要附上完整 `.env`、访问密钥、私有场地图、含人脸的视频或全部运行目录。先分享能定位问题的最小脱敏片段；需要现场资料时再确定授权范围。
