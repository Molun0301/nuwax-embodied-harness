# 指定保存点云完成后的请求收敛

## 调用链与改动

网页完整点云模式通过 `DensePointCloudLayer._poll()` 调用 `/api/pointcloud/dense`。原实现下载完指定保存资产后仍每 500 毫秒请求一次空尾块。指定资产的同一安装代次不可变，地图/点云来源事件已负责失效与重新加载。

现在只在以下三个条件同时成立时结束轮询：显示来源包含 `assigned_source`、已经接受有效分块元数据、已载入点数等于总点数。界面仍显示已下载资源。隐藏后再次显示复用完整资源；显式重载、安装代次变化、地图清除和断线仍沿现有来源事件路径处理。部分下载、失败重试、实时来源与旧保存来源保持轮询。

没有修改 HTTP、WebSocket 或 MCP 的公开合同，没有删除数据字段，也没有新增锁、摘要或跨请求缓存。点云模块及页面入口版本参数同步更新。

## 有界测量

在 Node 中导入实际网页模块，以可控 fetch 和虚拟时钟交付一个两点指定保存资产，推进 60 秒：

- 修改前：121 次请求，载入 2 点，仍有 1 个定时器
- 修改后：1 次请求，载入 2 点，没有后续定时器

这是确定性的重复请求计数，不是实机、网络延迟、吞吐量、浏览器或 WebGL 性能测量。输入很小是为了隔离完成后的重复轮询；不据此推算大地图速度。

## 验证

`node scripts/check_dense_pointcloud_polling.mjs`：9 项通过。覆盖完成后静止、隐藏/显示、同来源显式重载、安装代次切换、清除、空结果、分块下载及 503 重试、实时来源持续轮询与增长、旧保存来源持续轮询与增长。

`node scripts/check_assigned_pointcloud_pairing.mjs`：22 项通过。实际 Three/网页模块在 CPU 环境验证指定来源配对、过期响应隔离、地图清除、断线/重连、事务中断、重复重置和资源释放。使用 JavaScript 生成的测试数据，未注入设备采集样本。

`node scripts/check_dense_pointcloud_polling.mjs --measure` 可单独输出当前版本的虚拟时间请求计数。脚本语法检查与差异空白检查通过。

Python 文件未改动；本阶段不声称新增 Python 3.8.10 运行验证或实机验证。
