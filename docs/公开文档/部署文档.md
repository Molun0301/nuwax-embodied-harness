## 设备上运行的程序

| 程序 | 职责 | 何时启动 |
| --- | --- | --- |
| 设备管理程序（`neh`，端口默认 8765） | 安装、更新、配置、启停业务；转发业务控制台与接口 | 系统服务，开机运行 |
| 业务监督者（`python -m scripts.supervisor`） | 唯一负责启动、看护和停止下列业务组件 | 由管理程序在“启动业务”时拉起 |
| 网关（端口默认 8766，只监听本机） | 控制台、MCP、HTTP 接口、任务、感知与记忆 | 随业务启动，退出后自动重启 |
| Go2 视频推流 | 把 Go2 相机画面写进共享内存 | Go2 且开启视频时随业务启动 |
| 运动守卫 | 统一仲裁所有运动命令、急停、超时归零 | 第一次需要运动时按需启动 |
| 导航栈 | 全局与局部规划、路径跟随 | 第一次导航或探索时按需启动 |
| 几何运行时 | 定位、建图、地图文件、导航桥、探索 | 第一次需要地图或定位时按需启动 |
| 人物跟随 | 视觉跟随 | 第一次跟随时按需启动 |

按需启动的组件在第一次被功能用到时才启动，照顾低性能设备；它们退出后不会自动重启，下一次使用时再启动。停止业务时按网关、视频、跟随、几何运行时、导航栈、运动守卫的顺序停止。

几何运行时或导航栈重启后不会恢复之前的地图会话或导航目标：地图需要重新加载，进行中的导航任务会以失败结束。网关重启后任务记录清空，不会自动续跑。

## 访问入口

| 入口 | 地址 |
| --- | --- |
| 管理页 | `http://设备地址:8765/`（以安装输出为准） |
| 业务控制台 | 经管理页转发：`http://设备地址:8765/console`；在设备本机也可直接打开 `http://127.0.0.1:8766/console` |
| MCP（模型上下文协议） | 设备本机 `http://127.0.0.1:8766/mcp`；远程见[智能体接入](智能体接入.md) |

## 验证与排障

网关运行后，在设备上检查接口：

```bash
neh status
curl -fsS http://127.0.0.1:8766/api/health
curl -fsS http://127.0.0.1:8766/api/agent/tools
```

`neh status` 给出业务是否运行、网关是否健康；健康接口的 `processes` 列出各组件的进程状态与退出码，其余字段给出机器人装配、运动守卫、几何运行时连接与会话、活动任务、输入桥、感知与记忆状态。按“数据到达 → 功能就绪 → 任务结果”的顺序核对。

| 现象 | 优先检查 |
| --- | --- |
| 业务启动失败 | `neh start --wait` 或管理页任务返回的原因，其中列出已退出的组件及其日志末尾 |
| 网关正常但没有地图 | 当前建图链、雷达/惯性或里程计输入、外参、几何运行时日志 |
| 地图能显示但导航不可用 | 是否已定位（加载地图后会自动重定位）、目标落点、机体参数、运动守卫与执行端 |
| 视频正常但没有识别 | 是否开启识别、模型路径、类别、推理环境与识别错误 |
| 记忆没有物体坐标 | 当前记忆库、相机标定、几何证据，是否只是观察位置 |
| 设置保存后未生效 | 该项是否需要重启业务，见[配置说明](配置说明.md) |
| 更新失败 | 管理页任务的详细日志与失败原因 |

日志位置（`安装根` 默认 `~/Nuwax-embodied-harness`）：

| 日志 | 位置 |
| --- | --- |
| 网关结构化日志 | `安装根/data/logs/nuwax_robot_bridge.log` |
| 各组件输出 | `安装根/data/logs/组件名.log`，如 `gateway.log`、`geometry.log`、`nav_stack.log` |
| 业务监督者 | `安装根/logs/runtime.log` |
| 管理任务 | 管理页任务详情中的“详细日志” |

控制台“日志”页可按等级、来源、组件、请求和任务筛选并导出。
