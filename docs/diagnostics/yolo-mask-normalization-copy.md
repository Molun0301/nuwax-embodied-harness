# YOLO 分割检测归一化：去除新对象的深复制

## 改动

`services/perception/detectors.py::_normalize_yolo_result` 将刚生成的分割契约直接交给已有的 `normalize_detection_2d` 构造入口，不再先创建检测，再深复制整个检测及两份多边形属性来补充分割字段。没有新增缓存、哈希、后台任务或锁。

原始模型的多边形先经 `tolist` 和有限数值筛选构成新列表；结构化分割持有独立的坐标元组。输出仍不修改模型数组，不把两个检测的可变多边形属性共享。词表增强、通用外部检测归一化和其他拥有方边界的复制未调整。

## 离线测量

环境：Python 3.8.10、Pydantic 2.10.6、NumPy 1.24.4、OpenCV 4.10.0，Linux x86_64。测量日期：2026-10-13。

夹具使用正常导入的 `YoloWorldDetectorBackend` 及生产辅助函数，只将归一化方法分别绑定为改动前与候选源码；不加载模型。输入为 640×480 BGR8 图像契约、分数 0.8、类别 0、框 `[70,70,130,130]`，分割为中心 `(100,100)`、半径 30 的等角多边形。每个场景在一个进程内交替执行旧/新实现共 5 对，每个计时块连续调用 3 次；表中为每块单次平均耗时的中位数。不是 5 个独立进程。计时前进行 GC；内存另用单次 `tracemalloc` 测量，不纳入计时。

| 检测数量 | 每个多边形点数 | 原实现 ms | 新实现 ms | 原 Python 峰值字节 | 新 Python 峰值字节 |
| --- | --- | --- | --- | --- | --- |
| 1 | 4 | 0.226 | 0.138 | 24,494 | 16,806 |
| 20 | 128 | 14.587 | 6.011 | 1,192,776 | 1,067,080 |
| 64 | 512 | 281.206 | 153.505 | 13,252,424 | 12,047,712 |
| 64 | 无分割 | 1.388 | 1.387 | 188,600 | 188,728 |

20×128 和 64×512 分割场景的归一化耗时分别下降约 59% 和 45%；无分割对照基本不变。数值只表示这段 Python 输出归一化，不包含图像解码、模型推理、词表增强、跟踪或完整管线；不能解释为相机帧率或 GPU 提升。`tracemalloc` 不是进程 RSS，也不衡量 GPU 内存。

## 正确性与回归

同一夹具的改动前后完整契约输出逐项一致，仅排除每次构造自动生成的时间戳。检查了输入数组未被修改、一个检测的属性修改不影响另一检测、两份多边形属性互不影响，以及结构化分割坐标不与可变属性共享。新回归还禁止新建检测后再调用 `model_copy`，保留原来的中心点别名关系。

```bash
python -m pytest -q tests/unit/test_yolo_detection_contract.py tests/test_perception_snapshot_v18.py tests/test_observation_photo_v18.py
python -m py_compile services/perception/detectors.py tests/unit/test_yolo_detection_contract.py
git diff --check
```

未执行真实模型推理、收费接口、机器人调用或实机帧率测试。项目使用固定的 Pydantic 2.10.6 契约；本次不声称支持 Pydantic 1。

## 后续：复用不可变坐标和已计算的有符号面积

同日继续检查剩余归一化开销。生产路径不再把每个已过滤坐标先保存为可变列表、随后重新转换为坐标元组，而是在过滤时创建独立的 `(x, y)` 元组，构造分割时只创建外层元组。两个输出属性仍各自创建独立的可变坐标列表，Pydantic 校验入口保持不变。质心计算复用刚计算的有符号面积，不重复遍历多边形；保留原来的加法次序、方向符号、退化阈值和舍入。

正常导入的后端、生产 `_WorkerResult` 适配层和真实契约用于离线夹具；没有模型加载、假契约或校验旁路。一次 `cProfile` 的累计时间中，提取多边形约占 36%，构建分割约占 62%，Pydantic 校验约占 22%；这些调用互相包含，不能相加。不同分配阶段的耗时受 Python GC 影响，因此没有用单次 profile 耗时作为改进结论。

原始计时样本、各进程峰值及夹具/测量参数保存在 [三进程 A/B 结果 JSON](yolo-mask-normalization-points-results.json)，便于后续复核。

验证采用 **3 个独立 Python 3.8.10 进程**。各进程从改动前源码绑定原有四个方法到正常构造的后端，与正常导入的改后后端对比；其余生产辅助函数和模型完全相同。每个场景交替执行 7 对计时块，轮换先后顺序，每块调用 3 次，块前执行 GC。以下为各进程块内单次平均值的中位数，单位 ms：

| 检测数 × 点数 | 进程 1 原/新 | 进程 2 原/新 | 进程 3 原/新 |
| --- | --- | --- | --- |
| 1 × 4 | 0.139 / 0.140 | 0.152 / 0.143 | 0.143 / 0.141 |
| 20 × 128 | 6.390 / 5.422 | 6.990 / 6.805 | 6.696 / 5.544 |
| 64 × 512 | 156.353 / 134.908 | 156.363 / 145.363 | 151.340 / 138.761 |
| 64 × 无分割 | 1.345 / 1.466 | 1.436 / 1.357 | 1.412 / 1.521 |

大多边形场景在三个进程中缩短约 7.0%–13.7%，中等场景缩短约 2.7%–17.2%；小场景和未修改的无分割路径存在明显计时噪声，不声称有收益。单进程探索曾测出约 25% 的大场景收益，未在独立进程中复现，因此不将该值作为最终结论。

分别测量的 `tracemalloc` 峰值在三个进程中一致：1×4 为 16,806 → 16,470 字节，20×128 为 1,067,080 → 1,018,904 字节，64×512 为 12,047,712 → 11,494,704 字节（减少约 4.6%），无分割为 188,728 → 188,728 字节。测量只覆盖归一化，不是 RSS、GPU 显存或端到端吞吐量。

全部夹具逐项比较完整输出（仅排除自动时间戳）。新增回归覆盖正反方向、负坐标、NumPy 和列表输入、非法点过滤顺序、浮点转换异常顺序、退化面积、小正面积但无质心、输入与两份输出属性之间的修改隔离，以及每个有效多边形只计算一次面积。上述三组测试共 **61 passed**；编译检查和 `git diff --check` 通过。
