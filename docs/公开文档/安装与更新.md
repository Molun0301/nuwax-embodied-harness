# 安装与更新

NEH（具身运行框架）由独立的设备管理程序安装、更新和管理业务版本。管理网页和 `neh` 命令使用同一个任务流程；普通用户从公开仓库匿名安装。

## 一条命令安装并打开网页

在目标 Linux（操作系统）设备的普通用户终端执行，终端需有 curl（下载工具）：

```bash
curl -fsSL https://raw.githubusercontent.com/Molun0301/nuwax-embodied-harness/main/get-neh.sh | bash
```

安装入口按需准备 Python（编程语言）和 Git（版本控制工具），组装管理程序并安装系统服务；有桌面时自动打开管理页，远程终端会打印网址。安装系统依赖或系统服务时，终端会单独请求管理员密码。

- **管理页端口**默认从 8765 开始，复用本安装已保存的端口；被占用时自动选空闲端口（8765—8865），并避开业务端口 8766。**以安装输出的实际网址为准。**
- **管理页**负责软件安装与维护；**业务控制台**负责地图、任务和设备操作。管理页监听所有网卡，业务网关只监听本机，远程浏览器经管理页地址访问控制台（`http://设备地址:管理端口/console`）。访问控制见[安全与数据说明](安全与数据说明.md)。
- 命令入口链接到 `~/.local/bin/neh`。该目录不在 PATH（命令搜索路径）中时，按提示设置后重开终端，或使用安装输出中的完整路径。

管理页打开后，选择安装目录、机器人（`customrobot` 通用接入、`go2`、`unitree_sim` 仿真设备）和模块，点“开始安装”。只有存在阻止安装的问题、需要先停止正在运行的业务、或已知下载量达到 1 GiB 时，才停在确认页说明原因。

| 模块 | 内容 |
| --- | --- |
| `core` | 基础网关、控制台、标准数据接入 |
| `geometry` | 定位与地图运行时，可使用设备自带里程计 |
| `slam2d` | 二维激光建图、图定位与思岚雷达驱动 |
| `fastlio2` / `pointlio` | 三维激光惯性定位前端，两者可共同安装 |
| `navigation` | 导航、探索与运动守卫 |
| `perception` | 本地视觉检测与跟踪 |
| `memory` | 本地文本与图像向量模型 |
| `follow` | 人物跟随，自动补齐视觉与导航 |

安装的模块决定有哪些程序；实际运行哪条建图链和哪个定位前端由配置决定（见[配置说明](配置说明.md)）。系统和传感器准备见[安装前准备](安装前准备.md)，第一次接入见[快速上手](快速上手.md)。

## 日常更新与恢复

软件更新只有一套逻辑：`neh update`、管理页“立即更新”与业务控制台“设置 → 软件更新”是同一个更新任务。它依次完成：检查通道 → 必要时先更新管理程序 → 准备候选版本（取源码、下载或编译程序、准备依赖与模型）→ 等设备空闲 → 停止业务、切换版本、启动 → 健康检查；任一步失败都恢复上一有效版本。关闭终端或网页不会取消已受理的任务；发起更新的网页在版本变化后自动刷新。

| 命令 | 用途 |
| --- | --- |
| `neh` 或 `neh status` | 当前版本、模块、运行状态与更新提醒 |
| `neh update --check` | 只检查更新 |
| `neh update` | 准备并安装新版本，等待结果 |
| `neh update --local-build` | 云端预编译尚未完成时立即本机编译 |
| `neh jobs` / `neh job 任务标识 --wait` | 查询任务或继续等待 |
| `neh start --wait` / `neh stop --wait` / `neh restart --wait` | 启动、停止、重启业务并等待结果 |
| `neh rollback --stop-running --wait` | 切回本机保留的上一有效版本 |
| `neh password --stdin` | 设置或修改管理页密码（至少 8 个字符）；`--disable` 取消密码 |

**通道。** 默认通道为 `main`（主分支），只在云端检查与预编译全部通过后前进。需要跟随开发分支时：

```bash
neh channel branch:分支名称
neh channel main
```

后台自动更新只安装比当前版本新的提交；当前版本领先或与通道分叉时只显示实际关系。手动更新安装通道当前提交，不论新旧或分叉，确认框会写明切换方向。

**失败与重试。** 下载、构建或候选检查失败时保留旧版本；切换或启动失败时自动回退。后台更新失败过的版本会被后台跳过；手动更新总会重新执行。回退程序不会逆转数据格式变化，升级前保存重要的配置、地图和记忆数据。

**配置随更新保留。** 更新沿用当前配置方案；较旧的版本升级时，旧格式的配置方案会在候选版本中一次性转换为新格式。

`neh plan update --stop-running` 与 `neh apply 计划标识 --wait` 保留给需要逐项审查计划的场景，普通更新直接运行 `neh update`。

## 检查提醒与空闲安装

默认档位 `notify`（仅提醒）：约每 30 分钟检查一次（带随机抖动），发现更新后提醒，由用户点击安装。

```bash
neh auto-update off
neh auto-update notify
neh auto-update idle --window 02:00-05:00
```

| 档位 | 行为 |
| --- | --- |
| `off`（关闭） | 关闭后台检查，仍可手动检查和更新 |
| `notify`（仅提醒，默认） | 定时检查并提醒 |
| `idle`（空闲时安装） | 以较低优先级准备候选，设备空闲且处于维护时间窗时安装 |

时间窗用设备本地时间，格式 `HH:MM-HH:MM`。

**空闲门禁**（手动与后台更新共用）：没有运行中的任务；没有正在进行的建图或探索（更新会重启业务、中断建图，请先保存地图或结束地图会话）；NEH 没有在控制运动（运动守卫没有活动租约）。业务未运行视为空闲。更新只重启软件，不要求电机断电，机器人站立或趴下均可。条件不满足时等待并显示原因。

## 云端预编译与本机缓存

云端为以下五个程序提供预编译：

| 程序 | 用途 |
| --- | --- |
| `nuwax-slam-2d-worker` | 二维建图工作进程 |
| `nuwax-geometry-runtime` | 几何运行时（定位、建图、导航桥、探索） |
| `nuwax-nav-stack` | 导航程序 |
| `nuwax-person-follow` | 人物跟随程序 |
| `nuwax-mapping-cli` | 建图命令工具 |

目标平台为 `focal-arm64`（Ubuntu 20.04、64 位 ARM，面向 Go2）和 `noble-x86_64`（Ubuntu 24.04、64 位 x86）。设备按源码与构建输入计算指纹：本机已有同指纹程序就复用，否则按索引下载并核对摘要；附件缺失或校验不符时回到本机编译。其它系统和架构走本机编译。

FastLIO2（快速激光惯性里程计）与 PointLIO（逐点激光惯性里程计）始终由设备获取固定源码、在本机增量编译，不提供二进制。两个程序包含 Dimensional Inc. 的 Apache-2.0 包装与 `dimensionalOS/dimos-module-fastlio2` 的 GPL-2.0 算法；设备或镜像出货预装其编译产物前需取得兼容授权，见[第三方许可证说明](第三方许可证说明.md#lio-程序的源码编译与分发范围)。

开发分支的提交没有云端索引时，设备显示“云端编译中”并每 15 分钟重查；需要立即编译时用 `neh update --local-build`。main 通道暂时不可读或没有更新的提交时，设备保留当前安装，稍后再查，不降级。Python 依赖和模型按设备配方下载与缓存，不在预编译附件里。

推送通过后多久能看到提醒：定时检查间隔约 27—33 分钟，加上云端构建时间、设备离线时间和下载缓存传播时间，没有固定的到达时限。

本机源码、构建目录和依赖缓存会保留供增量构建，目前没有统一容量上限，长期维护时按实际占用检查。当前版本与回退版本、配置、地图和模型不能当作缓存删除。

维护者推送后，CI（持续集成）运行源码检查和五程序预编译，附件发布在公开 Release（发布集合）`neh-prebuilt-v1`：`index-完整提交.json` 对应固定提交，`channels-main.json` 对应 main 通道。许可与对应源码要求见[第三方许可证说明](第三方许可证说明.md)。

## 自定义安装位置

新安装默认位于 `~/Nuwax-embodied-harness`。管理页“硬件检查”可选择目标设备上的父目录，保存前显示最终位置，例如选择 `/mnt/data` 后使用 `/mnt/data/Nuwax-embodied-harness`。最终文件夹已有无关内容或属于其它安装时会报告冲突；目录须由当前用户持有且其它用户不可写。已有安装的业务位置不能在页面上改，迁移需重新安装并显式迁移配置与数据。

管理程序本身也放到自定义位置时，给安装入口传完整路径：

```bash
curl -fsSL https://raw.githubusercontent.com/Molun0301/nuwax-embodied-harness/main/get-neh.sh | bash -s -- --install-dir "$HOME/NEH 数据"
```

`--home` 与 `--install-dir` 同义，环境变量 `NEH_HOME` 也可指定，显式参数优先。重跑引导时使用原目录；另选目录会创建一套独立的安装。

终端交互安装用 `bash -s -- --cli`。无人值守安装可提交 JSON（结构化数据格式）计划：

```json
{
  "action": "install",
  "robot": "customrobot",
  "modules": ["core"],
  "configuration": {},
  "stop_running": false
}
```

```bash
neh apply --file 安装配置.json --wait
```

`configuration` 里写配置键与值，例如 `{"gateway.public_base_url": "http://设备地址:8765"}`；键名见[配置说明](配置说明.md)。Go2 用 `"robot": "go2"`，厂商依赖按固定官方配方准备，传感器、网络和标定仍按设备配置。

## 较旧的管理程序

2026-10-23 之前安装的管理程序不能自行更新到当前版本，也拿不到新的系统依赖助手（`/usr/local/libexec/neh-system-helper`，管理程序更新时不会更新它）。对**原安装目录**重跑一次引导器即可，会请求管理员密码，请在没有安装任务运行时执行：

```bash
curl -fsSL https://raw.githubusercontent.com/Molun0301/nuwax-embodied-harness/main/get-neh.sh | bash -s -- --install-dir '<原安装目录>' --no-browser
```

引导器读取已有安装记录，切换管理程序版本并保留原业务与数据；之后日常更新使用 `neh update`，单独更新管理程序可用 `neh update-manager --wait`。

## 卸载与数据保留

```bash
neh uninstall
```

卸载先确认没有安装任务、业务能安全停止，再停止本安装的业务与管理服务，移除程序和命令链接。默认保留配置、地图、模型、缓存和其它业务数据，结果会显示实际目录。

确认要同时删除本安装的配置、地图、模型与业务数据时：

```bash
neh uninstall --purge
```

执行前核对目录与备份。系统共享依赖按操作系统的软件包管理方式处理。
