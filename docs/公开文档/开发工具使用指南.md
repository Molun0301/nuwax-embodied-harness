# 开发工具使用指南

统一入口为[`scripts/dev_tools.py`](../../scripts/dev_tools.py)。目前整理了LIO（激光惯性里程计）建图效果对比和导航测试台，供开发机反复比较算法、参数及输入场景。两项工具均在本机运行。

## 环境与入口

以下命令在仓库根目录执行，使用Python 3.10或更新版本。普通点云导入、历史迁移、对比网页及导航服务只使用Python标准库；原生LIO重放转换额外需要NumPy（数值数组库）和LCM（轻量通信与编组库），可使用已安装项目核心依赖的解释器。三维页面复用仓库内已有渲染库，需要浏览器支持WebGL（三维图形接口）。

```bash
python3 scripts/dev_tools.py list
python3 scripts/dev_tools.py doctor
python3 scripts/dev_tools.py lio --help
python3 scripts/dev_tools.py nav --help
```

`doctor`只检查环境，不安装依赖或构建程序。没有导航二进制时会明确显示；建图对比仍可独立使用。下列示例中的`/path/to/...`是需替换的输入路径。

## LIO建图效果对比

页面保留原有两幅点云同步视角、俯视/侧视、轨迹开关、高度/时间着色和时间筛选。参考与候选均可切换；数据来自导入文件，没有自动配准、拉直或强制闭合。

### 先试用合成数据

```bash
python3 scripts/dev_tools.py lio demo --workspace runtime_data/lio_demo
python3 scripts/dev_tools.py lio serve --workspace runtime_data/lio_demo
```

打开[本机建图对比](http://127.0.0.1:18769/)。演示明确标注为合成数据，仅用于核对工具操作。`demo`要求新目录，重复运行请更换`--workspace`。服务用Ctrl+C（中断快捷键）停止。

### 加入自己的两组结果

```bash
python3 scripts/dev_tools.py lio add \
  --workspace runtime_data/lio_compare --id fast-baseline --title Fast基线 \
  --cloud /path/to/fast.xyzt --poses /path/to/fast-轨迹.jsonl \
  --source-label 同一段原始采集记录 --reference

python3 scripts/dev_tools.py lio add \
  --workspace runtime_data/lio_compare --id point-candidate --title Point候选 \
  --cloud /path/to/point.xyzt --poses /path/to/point-轨迹.jsonl \
  --source-label 同一段原始采集记录 --change 本轮参数变化说明

python3 scripts/dev_tools.py lio serve
python3 scripts/dev_tools.py lio report
```

省略`--workspace`时使用`runtime_data/lio_compare/`。版本标识允许字母、数字、短横线和下划线，重复标识会拒绝覆盖。文件复制到工作目录，日后查看不依赖原输入位置。

输入格式：

| 输入 | 约定 |
| --- | --- |
| `.xyzt`点云 | 无文件头；每点4个小端float32（32位浮点数）：地图坐标X、Y、Z，单位米；第四项为相对采集秒数，共16字节。不能直接将机体点云或点云文件头当作此格式 |
| 轨迹 | JSON（结构化数据格式）数组，或逐行JSON；每项含整数`timestamp_ns`、位置`p:[x,y,z]`及单位四元数`q:[x,y,z,w]`。时间非负且非递减，坐标与点云在同一地图系 |
| 时间零点 | 默认首个位姿时间。若点云时间相对原始记录起点，请明确传`--source-base-ns 整数纳秒值` |
| 最终静态地图 | 加`--static-map`；仍输入XYZT，时间可全为零。没有配套轨迹时提供内容为`[]`的轨迹文件，轨迹指标为不可用，页面停用时间筛选 |

轨迹示例：

```json
{"timestamp_ns":1000000000,"p":[0.0,0.0,0.4],"q":[0.0,0.0,0.0,1.0]}
```

### 从原生重放输出生成点云

历史原生重放目录中的三份文件可直接复用：`重放结果.json`、`原生位姿与点云.lcm`、`原生轨迹.jsonl`。

```bash
python3 scripts/dev_tools.py lio from-replay \
  --folder /path/to/原生重放目录 --workspace runtime_data/lio_compare \
  --id fast-replay --title Fast同源重放 --source-label 采集记录与参数说明
```

工具从`重放结果.json`读取原生`command`中的外参、输出通道和雷达坐标名称，以及`source_base_ns`、`poses`、`clouds`。只接纳同时间戳且与轨迹文件完全对应的输出；缺帧、坐标系不一致或数量不符会报错。点云先由雷达外参变到机体，再按估计位姿变到地图系。

默认按5厘米体素和10秒时间段做显示采样，可通过`--voxel-size`和`--time-bin-seconds`修改；往返不同时间段仍分别保留。转换记录保存外参命令、原输入位置、采样参数及原重放错误数量。此命令转换已完成的重放输出，不重新运行LIO估计器，不把原重放的失败记录改成成功。

### 迁移历史三维对照

历史目录需含`版本清单.json`和其中引用的点云、轨迹：

```bash
python3 scripts/dev_tools.py lio import \
  --from /path/to/旧三维对照 --workspace runtime_data/lio_imported
python3 scripts/dev_tools.py lio serve --workspace runtime_data/lio_imported
```

默认导入全部；加一个或多个`--id 版本标识`可以只导入指定结果，关联参考会递归带入。目标目录必须为空，原数据不会修改；任何缺失或格式错误都使整次导入失败。旧评价保存在清单的`legacy_metadata`中，当前轨迹指标从实际轨迹重算。

`report`写出`对比报告.json`，包含首末水平距离、轨迹长度、高度跨度、帧数及来源。没有外部真值时，这些数值不代表绝对精度；未返回同一位置的记录不能据首末距离评价闭合。显示采样点数也不等于算法实际处理点数。

## 导航测试台

测试台复用当前仓库的真实三维规划与跟随算法，提供直线、绕障、多层坡道、楼梯、断层、过高台阶、低净空，以及厚层起伏、不规则缺测、粗糙坡道绕障场景。运动部分包含地面与速度响应模型；结果表示开发机模拟行为。

### 构建和交互使用

Linux开发机需准备Rust 1.88或更新工具链及项目原生构建依赖。已有`.nuwax-test-env/env.sh`时启动脚本复用该环境；普通开发环境使用`PATH`中的Cargo（Rust构建工具），默认缓存放在`runtime_data/navigation_simulator_build/`。详细环境见[开发者部署说明](部署文档.md)。

```bash
python3 scripts/dev_tools.py nav build
python3 scripts/dev_tools.py nav serve
```

打开[本机导航测试台](http://127.0.0.1:18898/)。选择场景和预设，或在图上选择起点/目标，然后开始模拟。可暂停、继续、重置、插入障碍、回看轨迹和导出结果。页面中的Z是机体高度；选地面后由测试台加上机体到支撑面的高度。

源码或算法变动后重新执行`nav build`；`nav serve`直接启动指定二进制，不隐式重建。`--binary /path/to/nuwax-navigation-simulator`可选择明确的构建。旧入口`bash scripts/diagnostics/start_navigation_simulator.sh`继续支持构建后启动，`--help`只显示参数。

每次默认创建`runtime_data/navigation_simulator/时间-随机标识/`，启动时打印位置。`--data-dir`可显式指定，同一目录有进程占用时会拒绝启动。默认加载内置合成场景，以及本机`runtime_data/navigation_simulator/recording.json`登记的实机地图。没有本机登记时仅加载合成场景；已登记但文件缺失或配置错误时明确报错。加`--synthetic-only`可只加载合成场景。

本机已整理的原地图为“9月18日最新代码遥控建图-1512”，完整806525点和10434帧配套轨迹，提供12个七米预设。启动`nav serve`即可在场景下拉框选择。此数据为本机实录，不随仓库发布；新环境需要自行准备实录。

本机登记文件的路径相对该文件所在目录，也支持绝对路径。示例：

```json
{"name":"9月18日最新代码遥控建图-1512","cloud":"datasets/recorded/地图.xyzt","poses":"datasets/recorded/轨迹.jsonl"}
```

### 导入实录地图

显式提供`--cloud`和`--poses`会覆盖本机登记；该次覆盖不修改登记文件。

```bash
python3 scripts/dev_tools.py nav serve \
  --cloud /path/to/map.xyzt --poses /path/to/body-轨迹.jsonl
```

点云格式与建图对比相同，轨迹同样支持数组或逐行JSON。两项必须同时提供，文件错误会报错，不会静默换成合成数据。轨迹必须是配套机体位姿；最终静态图的空轨迹不能作为导航实录输入。地图点云用于几何判断，轨迹用于生成距离约7米的预设；无适合预设时可以网页选点或提供自定义请求。

### 自动运行和结果

```bash
python3 scripts/dev_tools.py nav run --scene straight --timeout 120
python3 scripts/dev_tools.py nav run --scene obstacle --timeout 120
python3 scripts/dev_tools.py nav run --request /path/to/导航请求.json --timeout 120
```

自定义请求示例，朝向单位为弧度：

```json
{"scene_id":"straight","start":[0,0,0.4,0],"goal":[7,0,0.4,0],"speed_mps":1.0}
```

通过`--scene`选择场景，`--case`选择预设；省略用例取该场景第一项。场景和用例清单在输出目录的`scenes.json`与`场景标识-cases.json`中。`--cloud`及`--poses`也适用于自动运行，导入场景标识固定为`recorded`。

| 产物或退出码 | 含义 |
| --- | --- |
| `运行结果.json` | 自动运行最终状态、是否触发墙钟超时及详细结果路径 |
| `results/运行标识.json` | 请求、实际终态、逐帧轨迹、路径变化、指标、二进制文件元数据和输入位置；网页运行也自动保存 |
| `原生模拟.log` | 原生规划及跟随诊断 |
| 退出码0 | 自动运行确实到达，或交互服务正常停止 |
| 退出码1 | 算法失败、自动执行超时或工具运行错误；查看结果和日志 |
| 退出码2 / 130 | 命令参数错误 / 自动运行被人工中断 |

`--timeout`控制自动执行墙钟上限，超时会取消、关闭原生工作进程并保留失败记录；`--startup-timeout`单独限制场景加载。二进制元数据是文件属性记录，不证明它对应某个源码提交。模拟结果不能代替Go2等实机的传感器、执行器及运动验收。

需要连续验收多个预设时，使用矩阵入口。它复用原生进程，并按50毫秒真实节拍推进，给后台局部规划保留执行时间：

```bash
python3 scripts/diagnostics/navigation_matrix.py
python3 scripts/diagnostics/navigation_matrix.py --synthetic-only \
  --include 'thick-undulating|irregular-ground|rough-ramp-obstacle'
python3 scripts/diagnostics/navigation_matrix.py \
  --request /path/to/请求.json --data-dir /path/to/本轮结果
```

`--include`按“场景标识/用例标识”正则筛选；`--timeout`与`--sim-seconds`分别限制每例墙钟和模拟时长，默认各180秒。输出目录保留`矩阵请求.json`、`矩阵结果.json`和各例请求、完整结果、最新状态、原生诊断；已有矩阵证据的目录不能覆写。可达例须同时满足原生到达终态、实际三维位置与朝向要求、实际末速停稳及运动复核零拒绝；不可达例须明确拒绝且零位移。时间耗尽、缺少验收字段或运行器错误都不能计为通过。

新增复杂地面的点云保留厚度、扰动与缺测，运动模型使用独立定义的物理地面；物理真值仅驱动模拟世界，不作为导航的地面成员输入。实录地图没有独立物理真值，其地面响应属于几何近似。地图与原始起始姿态相交时保留拒绝证据，不能因为原轨迹曾通过该处就抹去现有占据或改写验收结果。

## 工具归属与维护

| 能力 | 固定源码位置 |
| --- | --- |
| 发现与环境检查 | `scripts/dev_tools.py` |
| LIO导入、指标、历史迁移与服务 | `scripts/diagnostics/lio_compare.py`、`tool_data.py` |
| 原生重放点云转换 | `scripts/diagnostics/lio_replay_export.py` |
| LIO三维对比页面 | `gateways/http/static/lio-compare/` |
| 导航服务和自动运行 | `scripts/diagnostics/navigation_simulator.py` |
| 导航预设矩阵与独立到达验收 | `scripts/diagnostics/navigation_matrix.py` |
| 原生扫描逐帧交付与末端缺测验证 | `scripts/diagnostics/fastlio_scan_delivery.py` |
| 原生、公共里程计与规范变换接收记录 | `scripts/diagnostics/capture_lio_delivery.py` |
| 导航原生程序 | `scripts/diagnostics/navigation_simulator_native/`，直接依赖生产算法库 |
| 导航页面 | `gateways/http/static/nav-simulator/` |

相关专项工具继续使用各自入口：[`inspect_mapping_recording.py`](../../scripts/diagnostics/inspect_mapping_recording.py)检查原始录制，[`native_lio_smoke.py`](../../scripts/diagnostics/native_lio_smoke.py)验证原生建图链，[`run_sustained_navigation.py`](../../scripts/run_sustained_navigation.py)执行持续导航工作线程专项检查。它们的输入及验收范围不同，不能将结果混为一次全链验收。

`fastlio_scan_delivery.py`通过隔离通信通道驱动已构建FastLIO2程序，用`--base-ns`选择源时间起点，保存二进制身份、逐帧源时间及下一帧前的交付结果。`--imu-shortfall-ns 1`验证真实末端缺1纳秒仍被拒绝。该工具使用静态合成点云，只验证输入同步及输出交付；定位与运动仍由对应整链任务验收。`capture_lio_delivery.py`用`--url`连接实际通信地址，记录独立订阅器收到各阶段消息的宿主时刻；停止信号会正常保存摘要。订阅器时间不能冒充生产线程内部处理时间，未配置的发布通道也不能按丢包解释。

工具代码、页面和本指南随仓库维护；现场记录、转换结果、运行日志和本机构建缓存留在`runtime_data/`，开发任务记录留在本机开发文档。修改导航依赖后需同步原生程序的`Cargo.lock`并以`nav build`验证锁定构建；其他诊断程序的编译不属于该入口。
