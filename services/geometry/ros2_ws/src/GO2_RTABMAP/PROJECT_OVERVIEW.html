项目总览

通过统一入口脚本 ./go2.sh 提供三种互斥模式，共享同一套底层节点 （odom_tf_broadcaster · cloud_to_scan · cmd_vel_bridge）， 上层根据模式叠加 RTAB-Map（mapping / localization）+ Nav2（可选）+ Frontier Explorer（仅探索）。

建图模式 (--new / -m)

启动 RTAB-Map 增量 SLAM。机器狗每走一段就把当前 3D 点云作为关键帧入图，形成位姿图（pose graph）。回环 / proximity-by-space 触发图优化（GTSAM/g2o），地图通过 /map 实时反馈给 Nav2。

🧠 SLAM 核心

RTAB-Map 节点订阅 /utlidar/cloud_deskewed（运动补偿后的 3D 点云）和 /utlidar/robot_odom。

  • Mem/IncrementalMemory: true 持续添加新节点
  • Reg/Strategy: 1 ICP（无视觉，纯激光）
  • Reg/Force3DoF: true 平面运动假设
  • RGBD/LinearUpdate: 0.05m 5cm 触发新关键帧
  • RGBD/AngularUpdate: 0.05 rad ≈3° 触发新关键帧
  • Rtabmap/DetectionRate: 3 Hz 节流控制 CPU
  • Rtabmap/CreateIntermediateNodes: true 路径稠密化但不进图谱
🔬 ICP 与栅格

L1 是 4 线稀疏 lidar，点法线估计极易出错。本项目禁用法线分割，全部用纯高度分类地面/障碍。

  • Icp/PointToPlane: true
  • Icp/VoxelSize: 0.10 m
  • Icp/MaxCorrespondenceDistance: 0.20 m（建图）
  • Grid/NormalsSegmentation: false 不依赖法线
  • Grid/MaxGroundHeight: -0.15 m 地面阈值
  • Grid/MaxObstacleHeight: 1.0 m 忽略天花板
  • Grid/CellSize: 0.10 m

占用栅格的"黏性"（Sticky obstacles）

为了防止机器狗原地小转一圈就把已观测到的墙"擦掉"，配置不对称对数概率更新：

🟢 命中

GridGlobal/ProbHit: 0.85 → log-odds +1.73 每次（很快累积成饱和）

🔴 未命中

GridGlobal/ProbMiss: 0.45 → log-odds −0.20 每次（缓慢）

需要约 15 次连续 miss 才能清除一个饱和障碍 ≈ 5s @ 3Hz。真实可移动物体仍能清除，但短促回头不会。

定位模式 (--localization / -l)

载入之前 SLAM 出来的 .db 文件，进入只读重定位模式。RTAB-Map 把数据库中所有节点加载进 Working Memory，对当前激光帧用 ICP 匹配存档点云，匹配上之后发布 map → odom TF，让 Nav2 知道机器狗在世界中的真实位置。

🔓 与建图模式的关键差异
  • Mem/IncrementalMemory: false 不再添加节点
  • Mem/InitWMWithAllNodes: true 全图加载到 WM
  • Icp/MaxCorrespondenceDistance: 1.0 m
    （vs 建图的 0.2m，更宽容，因为初次重定位位姿误差可能很大）
  • Icp/Iterations: 30（vs 建图 20）
  • RGBD/ProximityMaxGraphDepth: 0 全图搜索 proximity 闭环
  • RGBD/StartAtOrigin: false 用上次保存的位姿做猜测
  • 启动时不加 --delete_db_on_start
📍 初始位姿与重定位状态

启动后看 RTAB-Map 日志：

  • local map = 0 → 还没重定位成功
  • local map = N (N>0) → ✅ 重定位完成

未重定位时 Nav2 会报 "Robot is out of bounds of the costmap!"。

触发重定位：

  1. RViz 工具栏 2D Pose Estimate 在地图上点+拖
  2. 命令行发 /initialpose
  3. 把机器狗物理摆回上次建图的起点

探索模式 (--explore / -e)

在建图基础上叠加 frontier_explorer.py。它周期性扫描 /map，找出"已知 free 区域与未知区域的边界"（frontier），聚类后选择最优簇作为 Nav2 目标点。机器狗自动驶过去 → 雷达扫到新区域 → 地图扩张 → frontier 收缩 → 直到全部消失，探索结束。

🔍 Frontier 检测算法
  1. 把 /map 转 numpy 数组：0=free, -1=unknown, >0=occupied
  2. frontier 像素 = free 且 4-邻域中至少有一个 unknown
  3. 对 frontier 像素做 8 连通区域标记（scipy.ndimage.label）
  4. 过滤掉 size < min_frontier_size（默认 10 cells）
  5. 每个簇算质心 → 候选目标
🏆 目标打分（贪心 + 距离惩罚）

score = size − α × dist_in_cells

  • size = 该簇 frontier 像素数（越多越优先）
  • dist = 机器狗到簇质心的欧氏距离（cell 单位）
  • α = distance_weight = 0.5
  • 取最大 score 作为下一个目标

失败处理：黑名单 + 看门狗

🚫 失败黑名单

Nav2 返回任何非 SUCCEEDED 状态时：

  • 把当前目标加入黑名单：(x, y, expire_time)
  • TTL 默认 blacklist_ttl: 60s
  • 所有距离 < blacklist_radius: 0.5m 的候选都被过滤
  • 连续失败 max_consecutive_failures: 5 次后停止探索
⏱ 启动宽限期 + 目标超时

针对 Nav2 BT navigator 在 Foxy + CycloneDDS 下偶发段错误：

  • startup_grace_period: 8s 等 Nav2 内部 action chain 完全就绪
  • goal_timeout: 60s 超时则 cancel + 黑名单 + 找新前沿
  • 避免 result_future 永远不回调时整个探索器死锁

自定义节点详解

项目共写了 4 个 Python 节点，每个解决一个具体的桥接/转换问题。代码都在 src/go2_nav/scripts/。

📡 cloud_to_scan.py
PointCloud2 → LaserScan，Nav2 障碍层用

核心问题：Livox L1 输出的 /utlidar/cloud_deskewed 在 odom 系，但 Nav2 obstacle layer 期望 base_link 系的 LaserScan。

实现：

  • numpy 向量化解析 PointCloud2（避免 sensor_msgs_py 慢）
  • tf2 查 odom→base_link（用 Time(0) 取最新）
  • 四元数 → 旋转矩阵自己算（避免 tf2_geometry_msgs 依赖）
  • 高度切片：z ∈ [-0.20, +0.30] 在 base_link 系下抓墙不抓地面
  • 极坐标 binning：每个角度槽取最小距离
  • QoS：sub=BEST_EFFORT（匹配 GO2 发布器），pub=RELIABLE（Nav2 默认）
📍 odom_tf_broadcaster.py
/utlidar/robot_odom → TF odom→base_link

核心问题：GO2 内置驱动也发 TF，但 DDS QoS 配置偶尔与 ROS 2 端不匹配，导致 TF 缺失。

实现：极简，订阅 Odometry → 转 TransformStamped → broadcast。仅此而已。这是冗余路径，确保 TF 一定有。

🐕 cmd_vel_bridge.py
geometry_msgs/Twist → unitree_api/Request

核心问题：Nav2 输出 /cmd_vel（Twist），GO2 需要 Sport API（JSON 包裹的 Request 消息，api_id=1008 Move）。

实现：

  • 速度限幅：max_vx=0.4, max_vy=0.2, max_vyaw=0.8
  • JSON 序列化为 {"x":vx,"y":vy,"z":vyaw}
  • cmd_timeout=0.5s 超时自动发零速（防失控）
  • 每收到 Twist 立即 publish + 0.1s 定时器兜底超时
🚀 frontier_explorer.py
自主探索：找前沿 + 发 NavigateToPose 目标

核心问题：纯自主建图，机器狗自己决定下一步去哪。

实现：

  • 3s 周期 tick，订阅 /map（QoS=TRANSIENT_LOCAL）
  • numpy + scipy.ndimage 做 frontier 检测和 8 连通标记
  • score = size − α·dist 选最优簇
  • Nav2 NavigateToPose action client 异步发送
  • 失败黑名单（半径过滤 + TTL 过期）
  • 启动宽限期 + 目标超时看门狗（防 BT navigator 崩死）
  • RViz MarkerArray 可视化：簇球 + 目标箭头 + 黑名单 X + 状态文本

cloud_to_scan（高度切片）

关键：切片高度是在 base_link 系下的相对值。GO2 base_link 在身体中心（≈30cm 离地），所以地面 z ≈ −0.30。设 min_height=-0.20, max_height=+0.30 抓"膝盖到头顶"那段，避开地面、避开天花板。

启动顺序与故障恢复

⚠ 已知问题
  • Foxy + CycloneDDS rmw 偶发 bt_navigator 段错误（serdata.cpp:308 invalid data size）
  • Nav2 lifecycle 报 active ≠ bt_navigator 的内部 action chain 完全就绪
  • RTAB-Map 数据库目录不存在会 SIGABRT 拖垮整个 launch
✅ 缓解措施
  • go2.sh 启动前先 pkill 残留进程，mkdir -p db 目录
  • 探索器 startup_grace_period: 8s
  • 探索器 goal_timeout: 60s + cancel + 黑名单
  • 失败计数到 5 整体退出，不死循环
