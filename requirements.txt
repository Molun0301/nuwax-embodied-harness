# - services/geometry/remote_provider.py:12 顶层 `import grpc`（无守护）
# - services/geometry/proto_gen/geometry_runtime_pb2.py 依赖 `google.protobuf`
#
# 【版本约束硬证据】geometry_runtime_pb2.py 头部声明 "Protobuf Python Version: 5.29.0"，
# 且运行时执行 `_runtime_version.ValidateProtobufRuntimeVersion(PUBLIC, 5, 29, 0, ...)`，
# 即要求安装的 protobuf 主版本==5 且 >=5.29.0，否则导入即抛 VersionError。
# 对应 grpcio 需 1.68.x 一线（同期 protobuf 5.29 生态）。
#
# 【Py3.8 兼容性——实机实证已确认无冲突】
# 锁定依据（2026-06-12 CX-08 实机复核）：实机 192.168.31.245(unitree@) 已恢复，SSH 实证：
#   $ python3 --version            -> Python 3.8.10
#   $ pip show grpcio protobuf     -> grpcio 1.70.0 / protobuf 5.29.6
# 即实机 Py3.8.10 上 protobuf 5.29.6 + grpcio 1.70.0 正在正常运行（虽官方无 cp38 wheel，
# 实机已成功安装，Jetson 侧由源码/第三方 wheel 满足），与 geometry_runtime_pb2.py:5/12
# 运行时断言（protobuf 主版本==5 且 >=5.29.0）一致。此前"5.29 无 cp38 → 须降版重生成 pb2"
# 的顾虑经实机实证证伪，无需改 pb2。按实机实装精确版本锁定：
