# 开发工具使用指南

本页提供开发机的 LIO（激光惯性里程计）建图对比、导航测试台、源码安装和已有 Go2（宇树四足机器人）开发推送。算法开发工具统一入口为[`scripts/dev_tools.py`](../../scripts/dev_tools.py)；普通设备安装与日常维护见[安装与更新](安装与更新.md)。

## 环境与入口

以下命令在仓库根目录执行，使用Python 3.10或更新版本。普通点云导入、历史迁移、对比网页及导航服务只使用Python标准库；原生LIO重放转换额外需要NumPy（数值数组库）和LCM（轻量通信与编组库），可使用已安装项目核心依赖的解释器。三维页面复用仓库内已有渲染库，需要浏览器支持WebGL（三维图形接口）。

```bash
python3 scripts/dev_tools.py list
python3 scripts/dev_tools.py doctor
python3 scripts/dev_tools.py lio --help
python3 scripts/dev_tools.py nav --help
```

`doctor`只检查环境，不安装依赖或构建程序。没有导航二进制时会明确显示；建图对比仍可独立使用。下列示例中的`/path/to/...`是需替换的输入路径。

## LIO建图效果对比

页面保留原有两幅点云同步视角、俯视/侧视、轨迹开关、高度/时间着色和时间筛选。参考与候选均可切换；数据来自导入文件，没有自动配准、拉直或强制闭合。

### 先试用合成数据

```bash
python3 scripts/dev_tools.py lio demo --workspace runtime_data/lio_demo
python3 scripts/dev_tools.py lio serve --workspace runtime_data/lio_demo
```

打开[本机建图对比](http://127.0.0.1:18769/)。演示明确标注为合成数据，仅用于核对工具操作。`demo`要求新目录，重复运行请更换`--workspace`。服务用Ctrl+C（中断快捷键）停止。

### 加入自己的两组结果

```bash
python3 scripts/dev_tools.py lio add \
  --workspace runtime_data/lio_compare --id fast-baseline --title Fast基线 \
  --cloud /path/to/fast.xyzt --poses /path/to/fast-轨迹.jsonl \
  --source-label 同一段原始采集记录 --reference

python3 scripts/dev_tools.py lio add \
  --workspace runtime_data/lio_compare --id point-candidate --title Point候选 \
  --cloud /path/to/point.xyzt --poses /path/to/point-轨迹.jsonl \
  --source-label 同一段原始采集记录 --change 本轮参数变化说明

python3 scripts/dev_tools.py lio serve
python3 scripts/dev_tools.py lio report
```

省略`--workspace`时使用`runtime_data/lio_compare/`。版本标识允许字母、数字、短横线和下划线，重复标识会拒绝覆盖。文件复制到工作目录，日后查看不依赖原输入位置。

输入格式：

| 输入 | 约定 |
| --- | --- |
| `.xyzt`点云 | 无文件头；每点4个小端float32（32位浮点数）：地图坐标X、Y、Z，单位米；第四项为相对采集秒数，共16字节。不能直接将机体点云或点云文件头当作此格式 |
| 轨迹 | JSON（结构化数据格式）数组，或逐行JSON；每项含整数`timestamp_ns`、位置`p:[x,y,z]`及单位四元数`q:[x,y,z,w]`。时间非负且非递减，坐标与点云在同一地图系 |
| 时间零点 | 默认首个位姿时间。若点云时间相对原始记录起点，请明确传`--source-base-ns 整数纳秒值` |
| 最终静态地图 | 加`--static-map`；仍输入XYZT，时间可全为零。没有配套轨迹时提供内容为`[]`的轨迹文件，轨迹指标为不可用，页面停用时间筛选 |

轨迹示例：

```json
{"timestamp_ns":1000000000,"p":[0.0,0.0,0.4],"q":[0.0,0.0,0.0,1.0]}
```

### 从原生重放输出生成点云

历史原生重放目录中的三份文件可直接复用：`重放结果.json`、`原生位姿与点云.lcm`、`原生轨迹.jsonl`。

```bash
python3 scripts/dev_tools.py lio from-replay \
  --folder /path/to/原生重放目录 --workspace runtime_data/lio_compare \
  --id fast-replay --title Fast同源重放 --source-label 采集记录与参数说明
```

工具从`重放结果.json`读取原生`command`中的外参、输出通道和雷达坐标名称，以及`source_base_ns`、`poses`、`clouds`。只接纳同时间戳且与轨迹文件完全对应的输出；缺帧、坐标系不一致或数量不符会报错。点云先由雷达外参变到机体，再按估计位姿变到地图系。

默认按5厘米体素和10秒时间段做显示采样，可通过`--voxel-size`和`--time-bin-seconds`修改；往返不同时间段仍分别保留。转换记录保存外参命令、原输入位置、采样参数及原重放错误数量。此命令转换已完成的重放输出，不重新运行LIO估计器，不把原重放的失败记录改成成功。

### 迁移历史三维对照

历史目录需含`版本清单.json`和其中引用的点云、轨迹：

```bash
python3 scripts/dev_tools.py lio import \
  --from /path/to/旧三维对照 --workspace runtime_data/lio_imported
python3 scripts/dev_tools.py lio serve --workspace runtime_data/lio_imported
```

默认导入全部；加一个或多个`--id 版本标识`可以只导入指定结果，关联参考会递归带入。目标目录必须为空，原数据不会修改；任何缺失或格式错误都使整次导入失败。旧评价保存在清单的`legacy_metadata`中，当前轨迹指标从实际轨迹重算。

`report`写出`对比报告.json`，包含首末水平距离、轨迹长度、高度跨度、帧数及来源。没有外部真值时，这些数值不代表绝对精度；未返回同一位置的记录不能据首末距离评价闭合。显示采样点数也不等于算法实际处理点数。

## 导航测试台

测试台复用当前仓库的真实三维规划与跟随算法，提供直线、绕障、多层坡道、楼梯、断层、过高台阶、低净空，以及厚层起伏、不规则缺测、粗糙坡道绕障场景。运动部分包含地面与速度响应模型；结果表示开发机模拟行为。

### 构建和交互使用

Linux开发机需准备Rust 1.88或更新工具链及项目原生构建依赖。已有`.nuwax-test-env/env.sh`时启动脚本复用该环境；普通开发环境使用`PATH`中的Cargo（Rust构建工具），默认缓存放在`runtime_data/navigation_simulator_build/`。详细环境见[开发者部署说明](部署文档.md)。

```bash
python3 scripts/dev_tools.py nav build
python3 scripts/dev_tools.py nav serve
```

打开[本机导航测试台](http://127.0.0.1:18898/)。选择场景和预设，或在图上选择起点/目标，然后开始模拟。可暂停、继续、重置、插入障碍、回看轨迹和导出结果。页面中的Z是机体高度；选地面后由测试台加上机体到支撑面的高度。

源码或算法变动后重新执行`nav build`；`nav serve`直接启动指定二进制，不隐式重建。`--binary /path/to/nuwax-navigation-simulator`可选择明确的构建。旧入口`bash scripts/diagnostics/start_navigation_simulator.sh`继续支持构建后启动，`--help`只显示参数。

每次默认创建`runtime_data/navigation_simulator/时间-随机标识/`，启动时打印位置。`--data-dir`可显式指定，同一目录有进程占用时会拒绝启动。默认加载内置合成场景，以及本机`runtime_data/navigation_simulator/recording.json`登记的实机地图。没有本机登记时仅加载合成场景；已登记但文件缺失或配置错误时明确报错。加`--synthetic-only`可只加载合成场景。

本机已整理的原地图为“9月18日最新代码遥控建图-1512”，完整806525点和10434帧配套轨迹，提供12个七米预设。启动`nav serve`即可在场景下拉框选择。此数据为本机实录，不随仓库发布；新环境需要自行准备实录。

本机登记文件的路径相对该文件所在目录，也支持绝对路径。示例：

```json
{"name":"9月18日最新代码遥控建图-1512","cloud":"datasets/recorded/地图.xyzt","poses":"datasets/recorded/轨迹.jsonl"}
```

### 导入实录地图

显式提供`--cloud`和`--poses`会覆盖本机登记；该次覆盖不修改登记文件。

```bash
python3 scripts/dev_tools.py nav serve \
  --cloud /path/to/map.xyzt --poses /path/to/body-轨迹.jsonl
```

点云格式与建图对比相同，轨迹同样支持数组或逐行JSON。两项必须同时提供，文件错误会报错，不会静默换成合成数据。轨迹必须是配套机体位姿；最终静态图的空轨迹不能作为导航实录输入。地图点云用于几何判断，轨迹用于生成距离约7米的预设；无适合预设时可以网页选点或提供自定义请求。

### 自动运行和结果

```bash
python3 scripts/dev_tools.py nav run --scene straight --timeout 120
python3 scripts/dev_tools.py nav run --scene obstacle --timeout 120
python3 scripts/dev_tools.py nav run --request /path/to/导航请求.json --timeout 120
```

自定义请求示例，朝向单位为弧度：

```json
{"scene_id":"straight","start":[0,0,0.4,0],"goal":[7,0,0.4,0],"speed_mps":1.0}
```

通过`--scene`选择场景，`--case`选择预设；省略用例取该场景第一项。场景和用例清单在输出目录的`scenes.json`与`场景标识-cases.json`中。`--cloud`及`--poses`也适用于自动运行，导入场景标识固定为`recorded`。

| 产物或退出码 | 含义 |
| --- | --- |
| `运行结果.json` | 自动运行最终状态、是否触发墙钟超时及详细结果路径 |
| `results/运行标识.json` | 请求、实际终态、逐帧轨迹、路径变化、指标、二进制文件元数据和输入位置；网页运行也自动保存 |
| `原生模拟.log` | 原生规划及跟随诊断 |
| 退出码0 | 自动运行确实到达，或交互服务正常停止 |
| 退出码1 | 算法失败、自动执行超时或工具运行错误；查看结果和日志 |
| 退出码2 / 130 | 命令参数错误 / 自动运行被人工中断 |

`--timeout`控制自动执行墙钟上限，超时会取消、关闭原生工作进程并保留失败记录；`--startup-timeout`单独限制场景加载。二进制元数据是文件属性记录，不证明它对应某个源码提交。模拟结果不能代替Go2等实机的传感器、执行器及运动验收。

需要连续验收多个预设时，使用矩阵入口。它复用原生进程，并按50毫秒真实节拍推进，给后台局部规划保留执行时间：

```bash
python3 scripts/diagnostics/navigation_matrix.py
python3 scripts/diagnostics/navigation_matrix.py --synthetic-only \
  --include 'thick-undulating|irregular-ground|rough-ramp-obstacle'
python3 scripts/diagnostics/navigation_matrix.py \
  --request /path/to/请求.json --data-dir /path/to/本轮结果
```

`--include`按“场景标识/用例标识”正则筛选；`--timeout`与`--sim-seconds`分别限制每例墙钟和模拟时长，默认各180秒。输出目录保留`矩阵请求.json`、`矩阵结果.json`和各例请求、完整结果、最新状态、原生诊断；已有矩阵证据的目录不能覆写。可达例须同时满足原生到达终态、实际三维位置与朝向要求、实际末速停稳及运动复核零拒绝；不可达例须明确拒绝且零位移。时间耗尽、缺少验收字段或运行器错误都不能计为通过。

新增复杂地面的点云保留厚度、扰动与缺测，运动模型使用独立定义的物理地面；物理真值仅驱动模拟世界，不作为导航的地面成员输入。实录地图没有独立物理真值，其地面响应属于几何近似。地图与原始起始姿态相交时保留拒绝证据，不能因为原轨迹曾通过该处就抹去现有占据或改写验收结果。

### 局部规划开关与对照

页面“速度与干扰”区的“局部规划”默认勾选。取消勾选后开始的这一轮跳过SCAN局部A*搜索和样条避障优化，机器人直接沿PCT全局路线行驶；闭环控制器、实测障碍、实际机身检查、停车和重新全局规划保持不变。全局路线前方被实测障碍挡住时，机器人先停稳，再按当前地图重新做全局规划，不在局部绕行。

运行中开关锁定。诊断区“局部规划”显示本轮模式和原生局部规划次数，关闭时次数不累计。导出文件名带“局部规划开启/关闭”，结果中的`request.local_planning`和状态`local_planning`记录本轮模式。

```bash
python3 scripts/dev_tools.py nav run --scene obstacle --timeout 120
python3 scripts/dev_tools.py nav run --scene obstacle --timeout 120 --no-local-planning
python3 scripts/diagnostics/navigation_matrix.py --synthetic-only --data-dir /path/to/局部开启
python3 scripts/diagnostics/navigation_matrix.py --synthetic-only --no-local-planning --data-dir /path/to/局部关闭
```

自定义请求可写`"local_planning": false`，省略时开启。对比两组时保持同一场景、起终点、速度和障碍，并比较到达结果、模拟时间、全局规划次数、停车次数和实际轨迹。关闭组只作对照数据；生产导航没有该开关，局部规划始终开启。

工具代码、页面和本指南随仓库维护；现场记录、转换结果、运行日志和本机构建缓存留在`runtime_data/`，开发任务记录留在本机开发文档。修改导航依赖后需同步原生程序的`Cargo.lock`并以`nav build`验证锁定构建；其他诊断程序的编译不属于该入口。

## 源码开发安装

以下内容面向源码开发、设备接入与已有源码安装。普通用户使用[安装与更新](安装与更新.md)。

### 环境与模块

本机自动安装支持 Debian、Ubuntu（操作系统）系列，安装器使用 Python 3.8—3.12，按所选模块准备系统依赖和 Rust 工具链。公共计算工作区声明的 Rust 最低版本为 1.88。

基础网关、原生建图和本地视觉模型的资源需求不同，因此不提供一个覆盖所有组合的最低内存数字。安装器依据处理器和可用内存调整构建并行数；视觉模型还需匹配推理环境。Jetson（嵌入式计算平台）使用相应厂商张量库，Go2 接入依赖由安装器从固定官方来源准备。

| 模块 | 安装内容 | 运行前提 |
| --- | --- | --- |
| `core` | 基础网关、控制台、标准数据入口 | 实时数据需另行接入 |
| `geometry` | 几何运行时和地图能力 | 有效传感器、坐标与所选后端 |
| `slam2d` | 二维激光建图、图定位及雷达驱动 | 二维扫描、所需里程计与标定 |
| `fastlio2` / `pointlio` | 一种三维激光惯性定位前端 | 规范点云、惯性数据与外参 |
| `navigation` | 导航、探索及运动守卫相关程序 | 地图、定位、机体参数与执行器 |
| `perception` | 本地视觉依赖与模型 | 图像和可用推理环境 |
| `memory` | 本地文本、图像向量模型 | 可记录观察及相应模型配置 |
| `follow` | 人物跟随程序，并补齐视觉和导航 | 目标输入及完整运动执行链 |

`slam2d`、`fastlio2`、`pointlio` 可以共同安装，实际链路和定位后端由配置选择。语义地图的决策模型是独立配置项，不等同于安装 `memory` 模块。

### 编译并行与资源使用

安装器和受支持的源码更新、依赖构建入口共用一个任务预算：先读取 `--jobs`，其次是 `CARGO_BUILD_JOBS`、`CMAKE_BUILD_PARALLEL_LEVEL`，均未设置时自动探测。Go2 双端更新的 `--jobs` 只作用于开发机；`--remote-jobs` 只作用于设备，省略时两端各自探测，不把开发机核心数套到设备上。现行安装计划中显式配置的构建任务数同样优先。

自动预算取进程可用逻辑处理器数、CPU 控制组配额（不足一个核心的余量向上取整）与当前可用内存每任务 2 GiB 三者的限制，最少 1 个任务，不再设 8 或 16 核的固定上限。内存按宿主与控制组剩余额度取较小值；未知内存时使用 1 个任务。这个内存预算降低内存不足风险，但不能保证任何编译单元都不超额。显式并行数须为正整数，允许超过自动预算，需自行留意内存压力。

例如先查看自动方案，或明确使用 24 个任务：

```bash
./install.sh install --preset map3d --dry-run
./install.sh install --preset map3d --jobs 24 --yes
```

独立 CMake 和 Boost 构建使用此预算；Cargo 管理的 GTSAM、PGO 和二维原生构建通过 GNU Make jobserver 与 Rust 编译共享同一任务池，不再各自固定为 2，也不会每层再启动一整池任务。直接调用 `cargo build -j N` 时，Cargo 的任务池就是其原生子构建的预算，`CMAKE_BUILD_PARALLEL_LEVEL` 不再独立覆盖它。已有非 Unix Makefiles 的 CMake 缓存仍保留，原生子构建会明确警告并使用 Cargo 分配的 1 个任务；需要共享并行时，在新的构建目录使用 Unix Makefiles，工具不会自动清空旧缓存。

安装计划与构建日志会显示实际任务预算。可并行的源文件少、单个大型编译单元、链接或 LTO（链接时优化）、依赖下载和磁盘读写阶段仍可能只有少数核心繁忙，不能据总 CPU 使用率低就认定任务数没有生效。这里保留既有发布优化、各模块的依赖顺序、原生缓存及 Cargo 目标目录；仅改变任务数不会使已完成的原生产物重新编译。

调度实现遵循 [Cargo jobserver 契约](https://doc.rust-lang.org/cargo/reference/build-scripts.html#jobserver)；[CMake 并行环境变量](https://cmake.org/cmake/help/latest/envvar/CMAKE_BUILD_PARALLEL_LEVEL.html)在共享任务池的子构建中移除，避免它另建并发池。

### 本机按需安装

常用完整方案如下；不确定设备条件时先选基础接入：

| 方案 | 等效目标模块 | 用途 |
| --- | --- | --- |
| `--preset basic` | `core` | 标准设备接入、控制台与接口 |
| `--preset map2d` | `core,geometry,slam2d` | 二维激光建图 |
| `--preset map3d` | `core,geometry,fastlio2` | 三维激光惯性建图 |

方案不自动安装导航、视觉或本地记忆。`--preset` 与 `--modules` 互斥；两者都是完整目标，增量增加功能用 `add`。


以普通用户进入向导：

```bash
./install.sh
```

也可先查看某一方案，再执行安装。以下以三维建图和导航为例：

```bash
./install.sh install --modules core,fastlio2,navigation --dry-run
./install.sh install --modules core,fastlio2,navigation --yes
```

使用二维雷达时，在向导中选择二维模块，或以 `core,slam2d,navigation` 作为完整目标模块列表。Go2 可显式加 `--robot go2`；设备依赖默认从固定官方来源下载。

安装与后续管理：

```bash
./install.sh list
./install.sh doctor
./install.sh add perception memory
./install.sh add pointlio
./install.sh remove perception
./install.sh start
```

其中 `add pointlio` 增加PointLIO，保留已有FastLIO2；运行后端在配置中选择；`remove perception` 会连同依赖视觉的跟随模块移除。修改模块前先停止当前安装的网关。

默认安装根目录为 `runtime_data/installation/`，实际生效目录与设置路径通过 `list` 查看。安装器在独立环境中准备所选模块，校验成功后切换；失败保留上一有效安装。模块移除不会删除地图、模型和用户数据，也不会卸载系统共享依赖。模块安装不自动配置系统服务或启动机器人。

### 命令与参数速查

| 命令或参数 | 行为 |
| --- | --- |
| 无参数 / `manage` | 交互向导；无终端输入时只显示计划 |
| `install` | 安装完整目标，默认沿用已有选择 |
| `add` / `remove` | 增加或移除模块；自动处理依赖 |
| `list` | 查看当前模块、安装时间和初始配置路径 |
| `doctor` | 只读检查系统、解释器、所选设备依赖、软件包与安装产物；有阻断项返回1 |
| `start` / `stop` | 前台启动或停止当前安装的网关 |
| `--dry-run` | 只看计划，不代表前提和功能通过 |
| `--json` | 输出结构化计划/状态；`doctor --json` 包含诊断与退出状态 |
| `--yes` | 接受目标方案，省略交互确认；系统提权可能仍需输入密码 |
| `--python` / `--jobs` | 指定兼容解释器或限制编译并行数 |
| `--install-dir` | 更换专属安装目录；后续管理带上同一路径 |
| `--wheel-dir` | 提供与目标设备和解释器匹配的厂商安装包 |
| `--repair` | 按当前源码修复安装，不是回退源码 |

安装过程显示五个阶段，详细命令输出写入安装目录的 `logs/`。查看日志中的首个错误，修复后重试相同命令。首次下载和原生编译耗时取决于网络、磁盘和设备，当前不承诺固定安装时长。

### 配置与运行方式

#### 模块安装

使用 `./install.sh list` 给出的初始配置位置，并用 `./install.sh start` 启动当前安装。全新安装默认监听本机；保存机器人方案后的实际配置位置见[配置说明](配置说明.md)。需要指定其他安装根目录时，各次管理命令使用一致的 `--install-dir`。

#### 开发启动

手工准备依赖的开发环境可使用[配置示例](../../.env.example)和[网关启动器](../../scripts/start_gateway.sh)。第一次创建配置、确认根目录尚无 `.env` 时执行：

```bash
cp -n .env.example .env
```

按真实设备修改配置后启动：

```bash
bash scripts/start_gateway.sh
```

`NUWAX_BOOTSTRAP_ENV_FILE` 可指定基础配置文件，`NUWAX_USER_CONFIG_ENV_FILE` 可指定统一用户覆盖文件。设置页显示实际来源、保存位置与生效范围，按页面提示应用变更。

#### 机器人配置方案

控制台支持为每种机器人选择、另存和应用多份方案，私有配置保存在对应机器人配置目录。方案、凭据、地图与模型均不属于公开源码。

`NUWAX_GEOMETRY_PIPELINE` 选择整条建图、探索和导航链：`slam_2d` 为二维，`lio_3d` 为三维。三维导航另需实测机体外形与支撑距离。选择合法链路后，页面会继续检查程序、输入及标定是否齐备。

### 更新已有安装

受管模块安装通过统一网关更新入口更新。命令行与控制台“设置 → 软件更新”调用同一个运行中的网关接口，前置条件、运行模式与恢复规则见[安装与更新](安装与更新.md)。

在已启动网关的安装主机上执行；更新前先完成或取消正在运行的任务，并确认设备可以安全停机：

```bash
# 查看参数
./install.sh update --help

# 检查当前分支的上游更新
./install.sh update check

# 确认更新并等待后台事务结果
./install.sh update install --yes --wait

# 查看更新状态
./install.sh update status
```

默认连接本机 `http://127.0.0.1:8766`；可用 `--url` 指定已运行网关的地址。更新沿用受管安装的模块、机器人适配器、安装目录与运行模式，客户端退出或等待超时不会取消已受理的更新。

#### 从开发机更新Go2源码部署

已有Go2源码与系统服务部署使用[Go2更新入口](../../scripts/update_go2.py)，在开发机仓库执行：

```bash
python3 scripts/update_go2.py plan
python3 scripts/update_go2.py build
python3 scripts/update_go2.py deploy
python3 scripts/update_go2.py verify
```

默认固定当前分支的远端提交；包含本机未提交修改时加`--source workspace`，固定本机已提交版本用`--source head`。`--jobs`和`--remote-jobs`分别控制两端构建。四个子命令都会连接设备，`plan`写入本次辅助脚本和计划，`build`包含远端准备与构建；只读参数说明用`--help`。

部署沿原系统服务入口执行，保留设备配置与业务数据。安装前检查目标漂移和载荷，安装后核对落盘文件/权限及服务状态，失败尝试恢复旧内容和服务。未激活的按需组件如实报告，成功结果不表示已完成机器人现场运动验收。


## 源码更新与恢复

以下规则适用于 `install.sh` 创建的源码模块安装；独立管理程序使用[安装与更新](安装与更新.md)。

### 安装描述与运行模式

安装器在当前代际的 `manifest.json` 中保存 `deployment` 描述，记录源码目录、安装目录、模块集合、机器人适配器、监听地址与生命周期模式。`./install.sh list --json` 可查看完整记录。更新器从安装记录及当前有效配置读取这些信息，不接受网页提交的任意目录、命令或下载地址。

支持两种生命周期：

- `foreground`：默认的普通进程模式，`./install.sh start` 在当前终端启动；更新器按同一安装身份停止和重新启动进程。
- `systemd-user`：由当前安装账户的用户级 systemd 管理器管理网关。安装只保存模式；显式运行 `start` 时才写入并启动该安装的用户服务。更新工作放在独立的用户级服务中，停止网关不会一并终止更新器。

例如，使用用户服务模式：

```bash
./install.sh install --service-mode systemd-user --yes
./install.sh start
./install.sh stop
```

后续安装和更新默认保留已存模式。变更模式前先停止当前安装，再运行带 `--service-mode foreground` 或 `--service-mode systemd-user` 的安装命令。`start` 与 `stop` 不临时覆盖模式。

用户服务要求 Linux 上存在可用的用户级 systemd 管理器及对应命令。安装不会自动启用开机启动，也不会修改登录驻留或系统权限；退出登录后服务是否继续运行取决于本机用户管理器配置。没有这些条件时使用 `foreground`。现有外部进程管理器或 root 系统服务不会被猜测、接管或静默关闭，需明确迁移到受支持的生命周期再使用统一更新。

### 网页检查与自动更新

安装并启动网关后，打开控制台的“设置 → 软件更新”：

- “检查更新”读取当前 Git 分支配置的远端 upstream，不会切换到 main，也不会修改源码。
- 有新版本时，左上角品牌标题右上角显示 **New！**；点击可跳到更新设置。
- “更新并重启”需要确认。后台固定本次检测的提交，只接受快进更新；本地修改、分叉、远端版本再次变化或仓库访问失败都会拒绝覆盖。
- 默认每60分钟自动检测，可设置15—1440分钟。勾选“空闲时自动安装”并保存后，才会自动执行安装；没有浏览器打开时也会检测。
- 更新前必须没有活动任务，并通过统一的设备安全就绪检查。接入设备时需要新鲜状态确认设备已处于可安全停机的状态；无法确认时拒绝更新。无设备入口须通过标准 has_motion_actuator() 契约明确声明没有执行器；缺失、未知或断连状态不会当成无执行器。
- 更新期间停止网关及其管理的组件。页面断开后会继续查询状态；关闭页面不会取消已受理的后台更新。

整个流程为：检查并固定版本 → 复核安全状态 → 沿已保存的生命周期停机 → 构建已选模块并切换安装代际 → 沿同一生命周期启动 → 核对实际运行版本。失败时尝试恢复旧源码及旧代际。网关恢复可用不等于机器人全部功能已经验收，运动、感知等能力仍需按接入与发布要求验证。

更新沿用已安装的模块、机器人适配器、解释器、安装目录和运行模式，编译并行上限为2。设备依赖由适配器声明；缺少必需的软件包、设备 SDK 或运行库时明确报告，不在后台等待 sudo 密码，也不会替换为另一种机器人来绕过检查。

源码更新使用公开仓库。自定义安装目录从受管启动器及安装描述识别；必要时可在部署环境设置 `NUWAX_UPDATE_INSTALL_DIR`，不能通过网页修改。

### 统一命令入口

命令行与网页调用同一个运行中的网关更新接口：

```bash
./install.sh update check
./install.sh update install --yes --wait
./install.sh update status
```

可用 `--url` 指定已运行网关的地址。远程地址应由使用者确认；客户端不保存 SSH 或 Git 密码。`--wait` 等待后台事务结果，客户端退出或等待超时不会取消已受理的更新。

已有Go2源码与系统服务部署由开发机调用`scripts/update_go2.py plan/build/deploy/verify`，使用现存双端构建和部署流程；它与上面的网关软件更新客户端各有适用安装。源码选择、连接副作用和失败恢复见[部署文档](开发工具使用指南.md#从开发机更新go2源码部署)。

运动守卫、网络准备、实际执行器初始化以及必要的系统服务依赖顺序仍有用途。这些组件服务于具体适配器及设备能力，不构成另一套按型号分流的软件更新流程。

### 支持范围

当前自动安装面向 Debian、Ubuntu及兼容发行版的 x86_64 / aarch64 Linux，依赖支持 Python 3.8—3.12。其他操作系统或架构不能据此假定可安装，先查看 `doctor` 和安装计划。

机器人类型来自现有注册表及安装依赖声明。新增设备需实现并注册适配器、补齐实际依赖和传感器/执行器协议，再完成硬件验证。通用装配入口不会自动生成真实标定或驱动；注册为骨架的适配器也不会因此变成完整产品。支持范围与验证状态见[发布与兼容性](发布与兼容性.md)。

### 缓存与恢复记录

更新成功后只清理受管安装目录中的临时下载 `cache/downloads`，保留 `cache/build`、`cache/sources` 和 `cache/slam2d-dependencies` 中可复用的构建产物、固定版本源码、依赖及路径/所有者记录，避免下次更新从空缓存开始。编译器仍按源码、依赖和构建选项决定哪些产物需要重建；保留缓存不保证每次都无需编译。安装器继续按当前模块选择清理已退出模块的专属缓存，共享缓存保留到没有相关模块使用时。

缓存没有自动容量上限：固定源码版本变化可能留下历史源码目录，Rust 目标目录及其中的历史产物也不会按更新次数或字节数自动淘汰。保留工具链、设备 wheel、配置、地图、模型、业务数据库、日志及当前/回退环境；只回收本更新器创建且未被配置引用的更早代际。未知目录保留，不运行全仓库 `git clean`。回退代际不能当作普通缓存删除。

构建或新网关启动失败时，更新器尝试恢复更新前的源码提交与安装链接，并核对旧网关运行版本。若恢复失败或进程被强制终止，状态显示需要人工恢复，不自动重复部署同一失败版本。详细事务记录和日志位于源码根的 `runtime_data/updates`。

数据格式迁移不会随源码与环境自动回退。重要数据仍需事先备份，恢复前必须确认旧版本与现有数据格式兼容。

### 手动更新与备份

正常更新优先使用上面的统一更新命令。网关无法运行、需要维护源码或调整安装方案时，可以手动操作。在源码根记录当前版本和安装描述：

```bash
git branch --show-current
git rev-parse HEAD
./install.sh list --json
./install.sh stop
```

先完成或取消正在运行的任务，确认设备安全停机，再停止网关。按数据的重要性保存可恢复副本，至少包括当前机器人方案、完整地图资产、记忆数据库及关联文件。数据库应在相关进程停止后保存；地图不能只保留缩略图。默认位置与自定义路径规则见[安全与数据说明](安全与数据说明.md)。

确认没有需要保留的源码修改：

```bash
git status --short
```

有修改时先处理其归属，不用强制覆盖或清理命令掩盖冲突。当前分支配置了上游、工作区干净时：

```bash
git pull --ff-only
./install.sh install --dry-run
./install.sh install --yes
./install.sh doctor
./install.sh start
```

`--ff-only` 遇到分叉会停止。更新后核对接口、数据和所选能力，再进行设备任务验证。使用自定义安装目录时，每个安装管理命令都带上原来的 `--install-dir`。

安装器默认沿用上次模块选择与运行模式。`--modules` 或 `--preset` 指定完整目标集合；增量加入能力使用 `add`：

```bash
./install.sh add navigation --yes
./install.sh remove perception --yes
```

这些操作前同样需要停止网关。移除模块时，依赖它的模块也会从目标方案移除，计划中会明确列出。

### 安装失败后如何恢复

安装器在独立目录创建新环境，依赖、构建和产物检查通过后才切换 `current`。下载、编译或模型准备失败时，上一个有效环境保留；安装日志位于安装根的 `logs/`，处理原因后重跑相同安装命令。

**手动安装保留旧环境，不表示手动更新的源码和业务数据已经自动回退。**启动器仍使用原源码目录。手动恢复时先恢复记录的源码版本，再核对配置和数据格式；存在未提交修改时先处理其归属，避免覆盖工作。

安装产物损坏时，停止网关后执行：

```bash
./install.sh install --repair --yes
./install.sh doctor
```

修复针对当前源码与模块选择，不是降级命令。保留的原始档案部署工具供其明确的部署场景使用，其中的 `rollback` 不适用于模块安装。统一更新保留当前与上一有效代际，但不承诺任意历史版本可一键切回；手动安装也可能回收未被配置引用的旧代际。

### 迁移与移除

安装描述和产物含绝对路径。换源码目录、磁盘或主机时，在新位置重新安装，显式迁移配置与数据并重新验证，不能只移动 `current` 链接。

暂停使用时执行 `stop`。模块管理支持移除可选模块，基础模块不能通过 `remove core` 删除。源码模块安装没有一键清空所有数据的卸载命令；独立管理程序使用 `neh uninstall`。完整退役前先核对数据去向、安装方式和自定义路径，再移除明确的安装产物；系统共享依赖、设备安全基础服务与现场数据不能随源码目录一并清理。
