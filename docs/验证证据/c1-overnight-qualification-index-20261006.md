## 构建和功能接受边界

- 使用既有原生SDK与缓存，Cargo jobs=2、CMake jobs=1；离线依赖预检使用已安装的GTSAM/Metis/Cephes，没有SDK重建或依赖回退
- 本夜为**混合 test profile**：MLS planner与nav-runtime为opt-level=3，其余受测Rust包通常为opt-level=0、debug=0；各阶段feature、二进制、源摘要和命令在对应记录中明确。**不是统一release构建**
- 每个阶段保留实际编译与执行身份；后续配置或仅测试模块变化不会把早期运行追认成最新整个工作树的全量重跑。最终Geometry隔离候选包含最新测试模块并实际编译，28次隔离运行合计包括14次baseline和14次candidate，只涵盖两个控制selector
- 改动前原生基线为32通过、3节拍失败、2个未执行观察基准；冷接触域阶段为45通过、同类3失败、4个未执行微基准。后续诊断阶段6通过、1失败，并不抹去前面的失败或证明稳定实时性。详见[原始基线](c1-native-planner-baseline-20261006.md)和[节拍归因](c1-cadence-attribution-20261006.md)
- 原75ms消费节拍、50ms计算限制、实时障碍检查、观察TTL、命令归零和拥有方退休条件均未放宽。没有新全局锁、跨RPC持锁、跨陈旧观察缓存、应用内容哈希或复制点云拥有方

## 真实通行性覆盖与未完成的闭环

1. 原始窄门组合实际覆盖32cm机体/33cm正例及32cm接触负例；Scan另有33cm正例/30cm负例。原基线已运行，不为汇总重复执行
2. 校准坡道用完整机体和独立命令积分，440个合成50ms步骤到达，误差0.047395m；模拟中单次follower.step墙钟峰值85.062ms，因此不是实时通过。见[校准坡道补充](c1-passability-supplement-20261006.md)
3. 封闭墙体90°弯用真实朝向规划器与SurfaceFollower，293个合成步骤到达原3D目标，位置误差0.117092m，在既有0.12m区域内；没有宣称到达精确坐标或最优路线。见[墙体直角弯](c1-wall-bounded-turn-20261006.md)
4. 真正的 assigned-map 恢复→Relocalize→LCM/PlannerWorker/Scan→生产MotionGuard→运动组合**仍未运行通过**。普通执行及一次获准重试在AF_UNIX创建处均被EPERM阻断；ON未重试，未换传输规避。已保存编译通过、失败日志及未来获准环境的精确命令，见[生产组合](c1-assigned-navigation-composition-20261006.md)
5. 地图变化后生产目标保留、等待、从实际pose重规划的拥有方交接已源码核对；持续障碍→真实归零→自动绕行→原目标到达仍无完整组合证据。不能以测试手动提交新路线替代此项，见[恢复审计](c1-map-change-recovery-audit-20261006.md)
6. 实际浏览器显示QA仍未验证；先前记录为ERR_BLOCKED_BY_CLIENT且当时服务未绑定，不能概括成WebGL不可用，见[显示资格记录](c1-assigned-saved-cloud-display-qualification.md)。地理编码地点路线的assigned权限配对仍是较低优先级未完成项
