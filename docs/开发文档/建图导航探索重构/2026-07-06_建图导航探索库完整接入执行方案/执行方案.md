## 0. RALPLAN-DR 摘要

### 0.1 原则（Principles）

1. **不回退 ROS2，不做双轨，也不留隐式 fallback**：本仓已完成去 ROS2，后续接入只允许 LCM/nuwax native runtime；任何失败都写成 blocker，不恢复 rclpy/r2r/Nav2/DDS，也不允许 `_nav2_action_provider`、旧 go2/RTAB-Map/Nav2 脚本或 legacy map activation 在默认路径静默兜底。
2. **先把通信闭环做真，再接算法闭环**：`real-lcm`、LCM fingerprint、typed payload、通道观测必须先通过；fake backend 只用于 contract/unit test。
3. **优先接已有平台接口，缺口只做 additive API**：优先复用现有 `GeometryRuntime` gRPC facade、`GeometryRuntimeProvider`、`MapProvider`、`NavigationProvider`、`ExplorationProvider`、`LocalizationProvider`；库有能力但平台没接口的，单列接口扩展，不偷塞到 metadata。
4. **明确区分 graph/dry-run 与 runtime**：`nuwax-nav-stack` 当前主要是 profile + module graph + dry-run 编排，不可直接宣称“导航运行时完成”。运行时执行器必须在本仓 runtime 或 dimos 新 runtime 层补齐。
5. **验收以端到端证据为准**：cargo / Python 编译 / no-ROS2 gate / LCM wire golden / gRPC smoke / Go2 实机冒烟都必须有记录；当前已提供 `/home/ml/Deeprob/dimos/.nuwax-test-env` Rust/Cargo 环境，接入后本仓 Rust 验证不能再因工具链不可用标 `UNKNOWN`，只有缺目标机/实机权限等外部条件时才能标 `NOT RUN`。

### 0.2 Top 3 决策驱动

1. **当前本仓已经准备好平台边界**：`geometry_runtime.proto` 已有控制、定位、地图、导航、探索、输入发布 gRPC facade（`services/geometry/nuwax_geometry_runtime/proto/geometry_runtime.proto:137-168`），Python provider 已有对应调用与 NavigationProvider shim（`services/geometry/geometry_runtime_provider.py:473-522`, `:658-772`）。
2. **当前失败集中在真实接线，不在 ROS2 删除**：最终验收报告记录 real-lcm、wire-format、导航 RPC 真实路径 3 项 FAIL，cargo tree UNKNOWN、Go2 实机 NOT RUN（`07_最终删除与实机验收报告.md:49-59`）。
3. **dimos 库主体已可作为路径依赖，但部分能力仍停在基础/编排层**：`nuwax-transport` 的 `real-lcm` feature 为空（`nuwax-transport/Cargo.toml:26-31`），`nuwax-codec` 当前 fingerprint 仍是 FNV-1a、非 lcm-gen MurmurHash64A（`nuwax-codec/src/lcm.rs:19-22`, `:85-94`）；`nuwax-nav-stack` 明确核心职责是 graph/dry-run/smoke，而非完整 runtime（`nuwax-nav-stack/Cargo.toml:12-18`, `src/lib.rs:47-52`）。

### 0.3 可行方案比较

| 方案 | 内容 | 优点 | 风险 / 缺点 | 结论 |
|---|---|---|---|---|
| A. **在现有 `nuwax-geometry-runtime` 内做完整接入** | 扩展 Rust runtime：接 real LCM、typed codecs、mapping/nav/explore runtime adapters；Python 仍通过 gRPC facade | 改动边界最小；复用本仓已准备 provider/gateway；最符合“接入当前项目已准备接口” | Rust runtime 会变厚，需要模块拆分和测试严控 | **采纳** |
| B. 新增独立 `nuwax-nav-explore-runtime` 进程 | 保持 geometry runtime 只做 facade，另起进程跑 nav/explore/mapping | 进程职责更纯；未来可独立部署 | 需要新生命周期、端口、健康检查、systemd、Python provider；当前平台接口需要更多改造 | 作为后续拆分，不作为本次主线 |
| C. 只接 `nuwax-nav-stack --dry-run`，把导航/探索继续标 UNIMPLEMENTED | 风险低、容易过静态门 | 不满足“完整接入”；不能验收 Go2 导航/探索 | 拒绝 |
| D. Python 直接调用 dimos crates 的 CLI/FFI | 少改 Rust runtime | 破坏 LCM-first runtime 边界；Python 要承担生命周期/状态一致性 | 拒绝 |

### 0.4 ADR

- **Decision**：采用方案 A。以现有 `services/geometry/nuwax_geometry_runtime` 为唯一 native runtime 接入点，补齐 `real-lcm`、typed message codec、mapping/nav/explore runtime adapters，并通过当前 Python provider/gRPC facade 暴露给平台。
- **Drivers**：复用已有接口、避免新增进程复杂度、按真实端到端闭环验收。
- **Alternatives considered**：新独立 runtime、dry-run-only、Python 直调，均不作为本次主线。
- **Why chosen**：当前项目已经把 `GeometryRuntimeProvider` 设为导航优先 backend（`services/geometry/runtime.py:3206-3218`），继续扩展这个边界能最少破坏平台代码；但同一段代码仍有 `_nav2_action_provider` fallback，Phase 0 必须先硬删除/硬隔离该 fallback，避免“优先 native、失败走 legacy”的双轨事实。
- **Consequences**：需要先确认本仓消费的 dimos LCM/codec/protocol 来源与已验证版本一致；本仓 runtime Cargo deps 会从 protocol/transport/codec/tf 扩到 mapping/nav/exploration；Rust 侧必须新增较多集成测试；默认导航/探索路径会在短期内宁可返回 `RUNTIME_NOT_READY`，也不能落回旧 Nav2/脚本路径。
- **Follow-ups**：若 runtime 过厚，待本次端到端稳定后再拆 `nuwax-runtime-orchestrator`/独立进程。

### 1.3 本仓真实缺口

1. **Cargo deps 未接功能 crate**：当前 runtime 只依赖 `nuwax-protocol`、`nuwax-transport`、`nuwax-codec`、`nuwax-tf`（`services/geometry/nuwax_geometry_runtime/Cargo.toml:24-27`），尚未链接 `nuwax-mapping`、`nuwax-exploration`、`nuwax-nav-stack`、`nuwax-nav-simple-planner`、`nuwax-explore-wavefront` 等。
2. **real LCM 仍不可用**：`NUWAX_LCM_BACKEND=real` 会被强制 fallback 到 fake（`lcm_runtime.rs:421-436`）。
3. **payload 仍是本仓 ad-hoc bytes**：`PublishOdom` / `PublishPointCloud` 注释明确 TODO typed encoding + MurmurHash64A 对账（`server.rs:388-399`）。
4. **导航 goal/cancel 仍 UNIMPLEMENTED**：`SetNavigationGoal` 与 `CancelNavigation` 返回 `status="UNIMPLEMENTED"`（`server.rs:261-305`）。
5. **OccupancyGrid SHM 未接**：`GetOccupancyGridShm` 仍 unimplemented（`server.rs:203-205`）。
6. **start script 与 Rust main 参数语义不一致**：`start_nuwax_geometry_runtime.sh` 传 `--port/--ready-file/--lcm-url`（`start_nuwax_geometry_runtime.sh:50-54`），Rust `main.rs` 只读 env（`main.rs:49-71`），需要统一为 env 或补 CLI parser。
7. **存在隐式历史导航 fallback 风险**：`_resolve_navigation_backend()` 在 remote provider 不连通时仍返回 `_nav2_action_provider`（`runtime.py:3206-3218`）。即使该字段当前多为 `None`，执行方案必须要求删除该 fallback 或让它只在显式 `legacy/manual` 诊断路径返回硬错误，不能作为正式 `NavigationProvider`。
8. **存在 Python 探索 split-brain 风险**：`_resolve_exploration_backend()` 当前优先返回 `_platform_exploration_runtime`（`runtime.py:3220-3226`），`start_platform_exploration()` 仍围绕 Python `PlatformExplorationRuntime` / `_start_external_script_exploration` 推进（`runtime.py:4512-4531`）。本次接入必须明确：默认探索 owner 迁到 Rust `explore_runtime` + `nuwax-exploration`，Python 旧状态机只保留 legacy/manual 或测试 harness，不再作为默认 `ExplorationProvider`。
9. **env-only 启动契约还需删除/禁用 runtime args 配置**：`core/config_registry.py` 与 `core/settings.py` 仍暴露 `NUWAX_GEOMETRY_RUNTIME_ARGS`，但 `GeometryRuntimeSubprocess` 实际只按 env 启动 binary（`geometry_runtime_client.py:203-216`）。若保留该配置，会让实施者继续传 CLI 参数，必须删除或标记 unsupported。
10. **runtime.py/gateway 仍有历史注释、诊断名和 Nav2 资产语义**：若不收敛，会让实施者误以为可继续依赖旧链路（例如 `_start_geometry_runtime_subprocess` 注释仍写 ros-bridge，`runtime.py:1052-1104`；gateway 中仍有 `debug_nav2_goal` / `force_nav2_goal` 等名称）。本次默认路径必须改成 nuwax navigation 语义；旧地图资产名只允许作为离线兼容读取。

## 2. 目标架构

```text
Python platform / gateways / services
  ├─ MapProvider / LocalizationProvider / NavigationProvider / ExplorationProvider
  └─ GeometryRuntimeProvider (gRPC control facade)
        │
        ▼
services/geometry/nuwax_geometry_runtime  [唯一 native runtime]
  ├─ control: Start/Stop/Status/Health/Diagnostics
  ├─ lcm_io: real/fake LCM backend + typed codecs + channel registry
  ├─ mapping_adapter: nuwax-mapping → occupancy/costmap/cloud_map assets
  ├─ nav_runtime: nuwax-nav-stack profile + simple/astar/native adapters → cmd_vel/nav_state
  ├─ explore_runtime: nuwax-exploration controller + wavefront/TARE sources → frontiers/nav goals
  └─ shm_sidecar: pointcloud/map/video large payload refs
        │
        ▼
LCM typed channels / SHM
  /odom#nav_msgs.Odometry
  /tf#geometry_msgs.Transform
  /map/occupancy#nav_msgs.OccupancyGrid
  /nav/goal#geometry_msgs.PoseStamped
  /nav/cancel#nuwax_msgs.CancelNavigation
  /nav/state#nuwax_msgs.NavigationState
  /cmd_vel#geometry_msgs.Twist
  /explore/frontiers#nuwax_msgs.FrontierList
```

**边界规定**：
- gRPC 只用于 Python ↔ Rust 控制面与现有平台兼容，不作为高频数据默认通道。
- LCM typed channel 是 runtime ↔ dimos modules 的默认数据面。
- 大 payload 走 SHM sidecar + LCM metadata，不直接塞 gRPC。
- `nuwax-nav-stack` 的 graph/dry-run 结果用于装配、观测和验证；真正执行由 `nav_runtime` adapter 负责。

## 6. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---:|---|
| real-lcm / fingerprint 未完成导致所有“真实接入”只能 fake | HIGH | Phase 1 作为硬前置；未完成时本仓状态保持 PARTIAL，不宣称接入完成 |
| 把 graph-only `nuwax-nav-stack` 当 runtime 使用 | HIGH | 新增 `nav_runtime` adapter；验收必须看到 cmd_vel/nav_state 真实变化 |

## 9. Premortem（失败预案）

1. **实装 real-lcm 后通道看似有数据但 runtime 无状态更新**
   - 可能原因：typed suffix / fingerprint / schema 名不一致。
   - 预防：Phase 1 golden bytes + runtime 启动时打印 channel registry；LCM frame decode error 计数进入 HealthCheck。

2. **导航目标下发后上层以为 accepted，但机器人不动**
   - 可能原因：`SetNavigationGoal` 仍只写状态、不驱动 planner/cmd_vel；或 cmd_vel sink 未绑定。
   - 预防：验收要求 cmd_vel channel 有 bounded 输出；无 cmd_vel sink 时 `SetNavigationGoal` 必须失败。

3. **探索能产 frontier 但无法闭环到导航**
   - 可能原因：ExplorationController 与 NavigationRuntime 之间只通过 metadata/状态松耦合，未建立 goal handoff。
   - 预防：`explore_runtime` 明确把 FrontierGoal 转 NavigationGoal 并记录 handoff id；集成测试要求 frontier→nav_state transition。
