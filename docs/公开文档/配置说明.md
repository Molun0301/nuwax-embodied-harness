# 配置说明

Nuwax Embodied Harness（NEH，具身运行框架）的安装选择与业务配置分开管理：安装决定装了哪些程序，配置决定这些程序怎样运行。业务配置以“方案”为单位保存，管理页、控制台和 `neh config` 修改的是同一份方案。

## 配置存在哪里

| 内容 | 位置（`安装根` 默认 `~/Nuwax-embodied-harness`） |
| --- | --- |
| 全部配置键、类型、范围、默认值和说明 | 随代码发布的[配置模式文件](../../core/config_schema.toml)；运行中的“设置”页按段列出全部键 |
| 配置方案 | `安装根/config/profiles/方案名.toml`，只保存与默认值不同的键 |
| 当前方案 | `安装根/config/active_profile` |
| 业务实际使用的完整配置 | `安装根/run/config.toml`，每次启动业务时由“默认值 + 当前方案”生成，各程序启动时读取一次 |

不要手工编辑 `run/config.toml`，下次启动会被重新生成。方案文件可以手工查看；修改请用设置页或 `neh config`，它们会先按配置模式检查取值。键名形如 `段.键`，例如 `geometry.pipeline`。

## 修改配置

**网页。** 管理页“配置”与业务控制台“设置 → 平台设置”是同一个入口：选择方案、查看说明、修改、点“保存改动”。保存时只检查一次取值范围，不合法的值直接拒绝。

**命令行。**

```bash
neh config                                              # 查看当前方案的全部设置
neh config --set perception.stream_interval_sec 0.8     # 修改当前方案的一个键
neh config --set logging.level DEBUG --profile 调试     # 修改指定方案
```

`--set` 可以重复写多个键；也可以用 `--file 文件.json` 提交 `{"values": {...}, "profile": "方案名"}`。有安装或更新任务运行时，保存会返回忙，稍后重试。

**保存后何时生效。** 每个键在设置页标明生效方式：

- **即时生效**（热加载）：网关显示参数、点云显示样式、制品保留策略、识别间隔与关键帧阈值、检测置信度、日志级别等，保存后网关立即采用。
- **重启后生效**：其余所有键，包括传感器、标定、建图与导航参数。保存后设置页提示“重启待生效项”，点“立即重启相关进程”或执行 `neh restart --wait`。重启会中断正在运行的任务，请在机器人停止后执行。

几何运行时、导航栈、运动守卫等进程只在启动时读取配置，保存不等于已采用。

**多个方案。** 控制台“另存为新方案…”复制当前方案；“设为运行方案”切换方案，切换会重启业务。当前方案不能删除，先切换到其它方案。

**敏感值。** API 密钥、令牌、设施凭据等键在页面上不回显；保存时留空或保持 `********` 表示不修改原值。

**路径。** 路径类键填相对路径时，解析到 `安装根/data/` 下，例如地图根默认 `runtime_data/maps`，实际为 `安装根/data/maps`。

## 常用配置

完整清单以设置页或[配置模式文件](../../core/config_schema.toml)为准，下表是接入时最常改的键：

| 键 | 默认 | 作用 |
| --- | --- | --- |
| `robot.driver` | `customrobot` | 机器人驱动：`customrobot`、`go2`、`g1`、`raspi_lidar_robot`、`unitree_sim` |
| `geometry.pipeline` | `lio_3d` | 整条建图、探索与导航链：`lio_3d` 三维激光惯性，`slam_2d` 二维激光 |
| `geometry.lio_backend` | `device` | 三维定位前端：`device` 设备自带里程计、`fastlio2`、`pointlio` |
| `geometry.mapping_backend` | `voxel` | 三维建图后端：`voxel` 体素、`raytracing` 射线追踪 |
| `geometry.correction_backend` | `none` | 回环校正：`none`、`library_pgo`、`native_pgo`、`relocalization` |
| `geometry.lio_body_from_sensor` / `geometry.lio_body_from_imu` | 空 | 雷达、惯性到机体的外参（JSON：`translation_m` 与九元 `rotation_row_major`） |
| `geometry.slam2d_config` | 空 | 二维链的传感器、坐标、时钟与标定；选 `slam_2d` 时必填 |
| `geometry.map_catalog_root` | `runtime_data/maps` | 地图根目录 |
| `navigation.pct_terrain_source` | `tomography` | 三维导航地形来源：`tomography` 点云层析，`mls` 多层表面 |
| `robot.length_m` 等外形键、`robot.model_path` | 空 | 机器人外形；留空按机型自带模型计算 |
| `motion_guard.backend` | 空 | 运动执行端：`unitree_sdk2py`（Go2）、`motion_control`（通用），留空不启用运动 |
| `motion_guard.control_factory` | 空 | 通用执行端的工厂，格式 `模块:函数` |
| `gateway.public_base_url` | 空（本机地址） | 调用者下载图像等文件时使用的地址，应从调用者所在机器可达 |
| `perception.yolo_world_model` 等 | 见设置页 | 识别模型、类别与阈值 |
| `memory.text_embedding_model` / `memory.image_embedding_model` | 本地 BGE / CLIP 模型 | 记忆检索使用的向量模型 |
| `semantic_map.NUWAX_SCENE_MAPPING_ENABLED` | `false` | 语义地图总开关（语义地图段的键名保留旧写法） |
| `unitree_sim.base_url` / `unitree_sim.model` | `http://127.0.0.1:18910` / `go2` | 仿真设备地址与型号 |

几点说明：

- **安装会写入设备值。** 选择 Go2 时，安装写入 `motion_guard.backend = unitree_sdk2py` 与出厂标称外参：雷达外参由机型模型的俯仰旋转再叠加宇树 L1 雷达厂家的 −123° 偏航修正得到（数值见[Go2 标定](../../adapters/sensors/go2_calibration.py)），新安装不用手填即可启动定位；有本机实测标定时在设置页覆盖。选择 `unitree_sim` 时，安装读取仿真设备声明的标定与速度上限并写入方案。
- **模块与配置要一致。** 选了 `fastlio2` 却没装该模块，定位前端启动会失败；增删模块用管理页“模块”或 `neh` 的安装计划。
- **业务端口** 在设备管理设置中，只能在首次安装前用 `neh settings --gateway-port 端口` 修改，默认 8766。

## 精细点云缓存与原始扫描暂存

- `geometry.fine_cloud_cache_mib`：`auto`（默认）或 16—4096 的整数（MiB，二进制兆字节）。自动模式从 32 MiB 起按需增长，上限为 `geometry.fine_cloud_cache_auto_max_mib`（32—4096，默认 256）。较大的预算减少反复编码，但占用更多内存；两种模式写出的地图相同。在线建图与回环重建各自使用这份预算。
- 原始扫描暂存供回环重建与地图清理使用：目录 `geometry.raw_scan_directory`（留空为运行数据目录下的 `scan_logs`），总量上限 `geometry.raw_scan_max_mib`（默认 1024 MiB）。与上一帧相比平移达到 `geometry.raw_scan_translation_m`（默认 0.1 米）、转角达到 `geometry.raw_scan_rotation_deg`（默认 3°）或间隔达到 `geometry.raw_scan_interval_s`（默认 1 秒）时记录一帧。**暂存写满时建图会话进入故障**，长时间建图前确认预算足够；保存地图时扫描会拷进地图目录。

以上键都需要重启业务生效。

## 保存后怎样确认

1. 确认编辑的是目标方案（页面顶部显示方案名与机器人）。
2. 保存，核对成功与被拒绝的键及原因。
3. 需要重启的键，按提示重启业务。
4. 重启后在控制台确认数据与功能已经就绪；需要核对实际值时查看 `安装根/run/config.toml`。

更改业务端口或访问地址后，客户端与智能体也要使用新地址。
