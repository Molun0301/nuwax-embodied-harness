# 未知地面导航：运行语义与改动边界

日期：2026-10-14

## 核心规则

缺少地面观测不再等于禁止运动。地面用于高度参考、已知地形变化与路径代价；是否碰撞由实际占用几何、禁行区域和当前近场障碍决定。

未知状态仍是 Unknown。规划所需的临时高度参考只属于当前请求，不写回实测地面、不生成假地面、不清除原点云，也不修改已缓存地图以让路线通过。完整数据已到齐但没有占用的地图，与数据块未到齐或数据损坏分别处理。

## 链路分工

1. PCT 全局规划：在已知地形与请求内未知参考上搜索，保持已知高度层、落差、障碍与禁行范围的几何约束。未知区域带有代价，不作为伪造的已观测平地
2. Scan 局部规划：使用相同原始地图和标定参考接续轨迹；不再依赖起步脚下必须有完整支撑观测的证明
3. 运动检查：验证实际机体扫掠体与占用体的碰撞。没有完整机体包络的兼容路径使用已有半径、高度与标定偏移构成平面圆柱近似，并读取当前近场数据；它不等同于完整三维机体及俯仰/横滚包络
4. 探索与任务往返估算：使用统一的参考路线和真实运动接续；预算耗尽或有限搜索范围不足属于尚未得出结论，不写成“目标不可达”并加入失败黑名单
5. 执行控制：使用后台准备的地图引用，不在控制线程冷构建层析图。已选指令执行前仍按最新近场占用重查；规划与控制的已知地形读取不争用同一机体查询缓存锁

## 地图更新与重规划

- 几何、近场障碍与接收时间分别表达，单纯刷新接收时间不能伪装成新几何或延长旧源有效期
- 同一地图域内，部分数据块暂缺时保留上一份完整数据与可用路线，并沿用原始源时间；损坏数据、切换地图域、取消与清空不套用此保留规则
- 对路线附近有界范围进行兼容性判断。已验证的未知到兼容平地更新可以保留路线版本和运动进度
- 真正新增障碍、已知地形改变或无法证明兼容的更新交给后台重算；局部执行继续按当前实际障碍判断
- 上述兼容优化不是“所有地图更新永远不重规划”，也不会用新时间戳掩盖旧数据

## 搜索资源语义

- 快速零预算请求只检查可直接接续的路线，不以失败取消仍在工作的完整搜索
- 完整搜索受状态数及展开次数约束。预算不足、物化范围不足、人工查询半径截断都有明确的非几何失败结果
- 同一目标与几何下按既定额度推进，达到上限后不因时间戳或微小姿态抖动反复启动同样搜索
- 探索保留待处理候选位置。一个复杂候选的延后、失败或资源耗尽不会丢掉其后尚未检查的候选
- 物理边界和真实封闭障碍仍可构成不可达依据；人为有限查询范围不足不能被当成这种证明

## 删除和保留

删除运行链路中的支撑观测许可、脚下凸包证明、私有清障地图与虚构地面视图。保留实际碰撞、禁行范围、已知地形几何与数据源生命周期语义。

部分历史枚举和公共兼容入口仍保留，以免破坏调用兼容性。`InsufficientClearance` 的运行含义及显示文字改为实际占用碰撞；`MissingSupport` 仍可描述一次事实查询未找到地面，但不能单独阻止未知区域运动。旧朝向搜索公共接口保留用于兼容与诊断，生产任务往返链路已经使用新的共享 PCT 接续入口；不声称所有旧接口都已删除或完全替换。

## 验证边界

详细冻结数据、公共接口与反例验证见 [独立验证报告](diagnostics/unknown-ground-20261014/README.md)。原始采集文件不进入仓库。验证包括真实占用与近期障碍反例、空地图、地图更新连续性、未知起终点与中段、预算及任务结果语义。

这些结果是云端离线验证，不等于实机执行成功，也不证明缺少完整输入的最终会话已经复现。深度相机地面来源记录缺失是单独的数据链路问题，不能用“未知可通行”掩盖；其来源修复在后续独立阶段完成和验证。
