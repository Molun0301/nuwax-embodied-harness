# 三维语义区域的局部资源更新

## 改动范围

`SemanticRegionLayer.update()` 原先把绑定、主题与区域列表序列化为一个变更标识；任意区域修订变化都会清空整个区域图层，重新创建所有面、边线和标签。现在保留原有整体变更入口和选中状态更新规则，按区域 ID 与重复出现次序复用已有记录：

- 仅修订或非显示元数据变化，不重新创建显示资源
- 名称变化，只替换对应标签的纹理和材质
- 颜色变化，更新已有面与边线材质
- 轮廓、孔洞或高度变化，只重建对应区域的几何体，保留其材质与未改变的标签
- 主题变化，只替换受影响的标签资源
- 地图绑定变化，继续完整释放并重建，保持来源切换边界

边界比较保存渲染使用的坐标值，能识别原地修改，不依赖可变输入对象的引用相等，也没有新增摘要、锁或跨请求缓存。保留原有整体 JSON 变更标识；本次不声称把所有输入比较变成增量协议。标签仍保留原有 `display_index` 不单独触发刷新的行为。

复用对象时仍需遵循 Three 的等深度透明排序：区域重排、插入或新增同渲染层级的外部对象时，必要时只重新包装 Object3D，保留几何体、材质和纹理所有权。覆盖与禁行区墙体共享 `renderOrder=3` 的情况。区域选择、重复 ID、拾取顺序、孔洞过滤、轮廓范围、标签避让、隐藏/显示、清空和释放保持原有语义。

独立检查还修正了一处既有所有权问题：Three 的 Sprite 共用模块级四边形几何体，原来的整体遍历释放会把它也释放。现在删除区域、清空和销毁只释放本图层拥有的面/边线几何体及标签材质/纹理，不释放其他标签或外部 Sprite 仍在使用的共享几何体。测试显式加入外部 Sprite，验证局部删除、绑定切换、清空和销毁期间共享几何体的释放次数始终为零；旧模块作为可见内容对照，不把原有共享资源释放缺陷当作应保留的行为。

没有修改点云传输、实时/旧版轮询、连接代次隔离、重连或点云页面资源逻辑。页面入口和模块引用已更新版本参数。

## 有界计数

三个矩形区域，共 18 个由区域记录拥有的几何体、材质、纹理资源。每步只修改指定字段：

| 操作 | 原版释放资源 / 新建标签画布 | 当前释放资源 / 新建标签画布 |
| --- | --- | --- |
| 仅选择变化 | 0 / 0 | 0 / 0 |
| 单区域修订变化 | 18 / 3 | 0 / 0 |
| 单区域名称变化 | 18 / 3 | 2 / 1 |
| 单区域轮廓点变化 | 18 / 3 | 2 / 0 |
| 地图绑定修订变化 | 18 / 3 | 18 / 3 |

基线为 `66176b86a82ffa272a427cd73cfffc121702b100`。完整计数保存在 [semantic-region-reuse-counts.json](performance-evidence/semantic-region-reuse-counts.json)。测试使用实际网页模块和仓库 Three 模块、模拟 Canvas2D、合成区域，不是浏览器或 GPU 测量，也不推算实机帧率、网络或整图吞吐量。

复现当前计数：`node scripts/measure_semantic_region_reuse.mjs`。可传入原版 `semantic-regions3d.js` 的本地路径对比基线。

## 验证

- `node scripts/check_semantic_region_reuse.mjs`：35 次更新，覆盖局部资源更新、原地修改、孔洞、绑定切换、重复 ID、输入排序、外部透明对象排序、选择/拾取、范围、标签避让、隐藏/显示、空列表、清空及资源恰好一次释放
- 同一脚本使用 `--baseline <原版模块路径>`，逐步与原版模块完整重建的可见几何、材质、标签和范围对比通过
- `check_semantic_overlay_reuse.mjs`、`check_scene_graph_overlay_reuse.mjs`、`check_forbidden_overlay_reuse.mjs` 通过
- `check_dense_pointcloud_polling.mjs`：9 项通过；`check_assigned_pointcloud_pairing.mjs`：22 项通过
- 模块与脚本语法检查、差异空白检查通过

本轮实际浏览器验证受环境限制：父任务使用已安装的 Chromium 154、全新的工作区用户配置和简单本地 HTML 进行无头启动，保留正常沙箱。浏览器在加载页面之前以退出码 134 终止，日志为 `process_singleton_posix.cc:297` 的 `socket()` 返回 `EPERM`。正常受审执行中的同类 AF_UNIX 操作也已确认被拒绝，因此未继续重试，也未关闭沙箱或修改安全设置。原始输出保存在工作区 `neh-evidence/cloud-browser-probe/stdout.log` 和 `stderr.log`。实际浏览器/WebGL 像素一致性仍未验证；不声称新增 GPU 上传或实机验证。Python 文件未改动。
