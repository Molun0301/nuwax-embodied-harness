# 贡献指南

Nuwax Embodied Harness（NEH，具身运行框架）欢迎公开贡献。项目自有代码采用 GPL-2.0-or-later（GNU 通用公共许可证第 2 版或更高版本），全文见[项目许可证](../../LICENSE)。

## 适合参与的工作

设备接入、可复现的故障修复、安装兼容性、公开文档和具名场景验证都可以独立贡献。先搜索已有问题，描述具体使用场景、现有行为、预期结果与验证方法。

设备接入请先读[架构与机器人接入](架构与机器人接入.md)，记录传感器、数据格式、坐标与时间、厂商依赖和运动执行边界。在注册表里加一个设备名称不等于完成了该设备的支持。

## 准备修改

普通安装默认跟随 `main`（主分支）。开发修改从维护者约定的目标分支开始，先核对源码与文档对应的提交，再创建自己的功能分支。

- 修改契约（数据结构、能力参数、协议）时同步生产方、消费方、生成的绑定与示例。
- 新增配置键写进[配置模式文件](../../core/config_schema.toml)：类型、范围、唯一默认值、中文说明、读取方与生效方式；读取方不另写默认值。
- 内部旧名称（`nuwax_*` 包名、协议字段、服务名）保留，纯品牌修改不重命名它们。
- 新写的 Python 代码要能在 Python 3.8 下运行（Go2 使用 3.8）。
- 注释、用户提示和公开文档使用中文；公开说明放在 `docs/公开文档/`。不要提交私有配置、现场地图、模型权重、运行日志或构建产物。

## 怎样验证

按修改的实际风险选择检查，不为文字改动编造实机成绩：

```bash
# 代码分层检查
bash scripts/check_layering.sh

# 安装计划检查（不安装软件）
./install.sh --help
./install.sh install --preset basic --robot customrobot --json

# 无机器人的业务闭环（需要已安装项目依赖的解释器）
python scripts/diagnostics/offline_platform_smoke.py
```

离线闭环使用合成数据与模拟的几何运行时，验证真实网关、任务与运动守卫流程，不能代替传感器、模型准确率或实机运动。建图与导航算法的修改可先用[开发工具](开发工具使用指南.md)：建图对比保留同源点云与轨迹，导航测试台支持网页操作与自动执行。

仓库的云端检查在推送到 `main`、`fix/**`、`feature/**`、`feat/**` 分支时运行：源码安装入口与安装生命周期检查（Python 3.8 与 3.12）、分层与 Python 3.8 语法检查、五程序预编译。完整的 Python 与 Rust 测试套件不在云端运行；部分测试和开发资料只在维护者本机，新克隆不一定具备。交付时如实写明本机实际运行了哪些检查。

## 提出合并请求

PR（合并请求）写清触发条件、改动后的行为、测试命令与结果、设备与输入范围，以及仍未验证的部分。涉及配置或升级时写明旧数据怎样处理；涉及算法时提供同输入、同版本的可比较证据。

描述最终实现，不堆放全部过程日志；失败与未运行分别列出。维护者审核后安排合并与设备部署。

## 第三方依赖

记录来源、固定版本、许可、目标架构与下载方式，保留原版权与许可证。新增或删除会进入预编译程序的 Rust crate、改动内嵌上游代码时，需要重新核对预编译许可（见[预编译许可证清单](预编译许可证清单.md)）。模型许可、厂商开发包许可和项目源码许可可能不同，不能用一种许可覆盖全部内容。主要组件见[第三方许可证说明](第三方许可证说明.md)。
