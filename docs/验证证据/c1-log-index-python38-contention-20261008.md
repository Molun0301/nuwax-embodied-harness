# 日志索引SQLite异常在Python3.8下的回退兼容（2026-10-08）

基线 `04bda1cd5444f28e7808386c291d98933e4507ea`。

## 实际缺陷与修复

`LogHistoryReader.query` 在派生索引失败时引用 `sqlite3.SQLITE_BUSY` 和 `SQLITE_LOCKED`。实际CPython3.8.20没有导出这些常量，原生SQLite异常也没有sqlite_errorcode字段。真实数据库占用时，本应回退原日志扫描，却再次抛AttributeError，导致回退失败。

新增一个局部分类函数：有原生错误码时沿用SQLite稳定主结果码5/6（含扩展码掩码）；没有错误码的3.8环境只识别实际数据库／表／schema锁消息及其名称后缀。它只用于既有异常回退，不增加正常查询校验、额外重试或缓存。非临时故障继续保留failed_scope，避免每次查询重复尝试不可用索引；锁释放后继续原有重新建立索引路径。

## 验证

实际CPython3.8.20：新增9项和既有无摘要日志索引33项通过。实际3.12.14补充新增9项通过。

- 原生EXCLUSIVE锁覆盖索引创建和已预热查询，返回值与原扫描结果、游标、脱敏内容及源文件字节一致；锁释放后能恢复索引
- 原生共享缓存产生表锁与schema锁，验证缺字段环境的实际消息；扩展码5/6/261/262/517亦覆盖
- 非临时OperationalError、损坏数据库、unsupported projection及snapshot变化保留原失败／重试边界；近似但不相同的错误文本不误判成临时锁
- 完整历史模块在3.8.20的6个测试方法中产生14个子场景错误，均为缺SQLITE_BUSY；另3个控制方法通过。原日志保留
- 所有回归的内容摘要构造尝试均为0，使用既有测试禁止摘要的fixture。源文件资格采用字节比较及固定Git基线，无新哈希

`check_log_index_sqlite_compat.py` 使用真实临时SQLite数据库；表/schema原生错误在获得后注入构造边界，扩展码使用显式构造异常。没有设备、网络、真实业务数据库或额外包安装。测试中的next_cursor误写在资格执行前修正为既有next_before字段。

未运行精确Python3.8.10、整个HTTP应用或实机。未测性能提速；这是日志故障回退与短暂锁恢复的正确性修复。
